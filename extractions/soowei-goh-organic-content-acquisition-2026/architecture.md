# SooWei Organic Content Acquisition — Architecture

## Architecture verdict

Expand `skills/soowei-consulting-leverage` by eight workflows, bringing the existing skill from four to twelve workflows. Keep `agents/soowei` as the single expert owner. Generate thin command wrappers from the workflow files, but promote only one new entry route: `/soowei-organic-content-system`.

This is a bounded capability expansion, not a new skill, agent, shared primitive, or global default.

## Causal spine

```text
Buyer evidence -> Trust sequence -> Two-pipeline operating plan
              -> Asset packaging -> Content-to-call campaign
              -> [human publishes] -> Performance evidence -> Next-cycle decisions
```

Publishing remains outside the system. A run may prepare publish-ready briefs and assets, but it may not post, schedule, send, or purchase analytics access.

## Composition and context policy

- **Function owner:** SooWei owns buyer-evidence-to-organic-acquisition strategy.
- **Hot context:** `SKILL.md`, `genius.md`, and only the selected workflow plus matching prompt.
- **On demand:** the compact source map, a supplied buyer-evidence file, and one optional last-mile craft skill.
- **Cold:** full transcripts, raw frames, unrelated content experts, connector instructions, and all other migrated command wrappers.
- **Integration rule:** downstream craft experts may transform the execution layer but may not rewrite buyer evidence, proof state, claim limits, or the campaign’s trust-stage diagnosis.
- **Skipped by default:** Lara Acosta, Jasmin Alic, HeyDominik, and Scrapes components. Their names in the table are routing boundaries, not preload instructions.

## Handoff chain

| From | To | Minimum handoff |
|---|---|---|
| Buyer Mirror | Trust architecture | Evidence path, buyer language, proof state, discovery/conviction/booking signals, unknowns |

| Published result | Learning loop | Asset ID, retention moments, responses, buyer events, baseline, time window |
| Learning loop | Next cycle | Keep/cut/test decisions, confidence, evidence gap, next concept input |

No handoff passes full transcripts or an expert stack.

## Proof plan

1. **Structural:** validate the expanded skill, eight born-v2 prompts, generated wrappers, prompt wiring, source links, and registry discovery.
2. **Negative controls:** reject fabricated Buyer Mirror data, unsupported proof, missing publishing permission, reach-only “wins,” and dream-follower ratios treated as laws.
3. **Behavior change:** run the current skill and expanded system on the same fictional high-trust consultancy brief. Compare evidence traceability, trust sequencing, audience narrowing, three-hook packaging, proof discipline, and learning-loop decisions.
4. **Cold start:** a fresh run must find the evidence, choose the earliest missing layer, load one component, produce its contracted artifact, and name the next gate without chat history.
5. **Embodiment:** compare Tier-1 output against two separate, genuinely unseen published pieces. The two build sources cannot be reused as blind evidence. Automated/self-judged success remains B-tier; A-tier requires Farrice’s judgment after that corpus exists.
6. **Regression:** all four existing workflows remain byte-preserved unless a source-grounded pointer must be added; their routability and prompt menu remain intact.

## Promotion boundary

The architecture may be built and verified locally after approval. It may not be globally mirrored, packaged as a plugin, allowed to publish, or described as revenue-proven. Repeated production receipts—not this extraction—would be required before any broader default.
