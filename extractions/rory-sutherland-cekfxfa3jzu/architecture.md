# Rory Sutherland Universal Behavioral Alchemy: Final Architecture

## Checkpoint 2

**Approved by Farrice on 2026-07-30.** This architecture is the production contract for the existing Rory skill.

The density-preserving verdict is:

- **5 new standalone workflows**
- **3 routed aliases into upgraded existing engines**
- **6 targeted workflow upgrades**
- **5 new born-v2 execution prompts**
- **3 existing prompt upgrades**
- **1 timestamped source-ledger extension**
- **0 duplicate Rory skills**

This is smaller than the provisional eight-workflow plan because the overlap audit found three capabilities already had strong canonical owners. Preserving those owners makes the system easier to invoke and less likely to contradict itself.

## Architecture Principle

Route by the **shape of the behavioral obstruction**, not by industry or framework name.

Rory owns the behavioral diagnosis and mechanism. One downstream expert may own the delivery form. A domain specialist can veto a false claim, unsafe move, technical error, or regulatory violation.

Default composition ceiling: **Rory plus one delivery owner**. A third expert is justified only by a separate deliverable or an independent verification need.

### Router Contract

The router selects one primary lens. If a second lens scores closely, it names the runner-up and the evidence that would justify switching. It does not execute both by default.

Every routing output contains:

1. Stated problem versus likely behavioral problem.
2. Exact behavior that must change.
3. Selected canonical workflow or execution prompt.
4. Rejected alternatives and why they were rejected.
5. Delivery owner, fixed constraints, and forbidden drift.
6. Smallest credible test.
7. Evidence class: video, existing corpus, publisher sample, or operational synthesis.

## Composition Ledger

Every stacked run records:

| Field | Required entry |
|---|---|
| Behavioral mechanism | The one Rory lens governing the intervention |
| Behavior to change | Observable target action |
| Source class | Video, existing corpus, publisher sample, or operational synthesis |
| Fixed constraints | Product facts, law, safety, brand, or resource limits |
| Delivery owner | One expert responsible for the final medium |
| Forbidden drift | What Rory’s lens is not allowed to override |
| Test | Hypothesis, variable, metric, kill rule, and scale rule |

Integration evidence is a visible change in the downstream artifact caused by Rory’s diagnosis. Expert names and borrowed terminology are not evidence.
