# Skill System Contract — Layout & Composition Intelligence

## Objective

Future taste-bearing layout work begins with source-grounded composition decisions before styling, prompting, generation, or code. The system must improve first-pass briefs without creating a competing design authority or a universal hard gate.

## Function Owner And Components

- **Craft owner:** `satori-graphics`
- **New use-now surface:** `/satori-composition-brief`
- **Existing components composed:** communication brief, Three-Flow, movement ladder, grid selector, contrast stack, LIFT, transferability checks
- **Execution consumers:** Kittl professional layout, Kittl AI visual asset synthesis, Design-First Build, Design Gauntlet, Fantastic Studio/Posters, GPT Image 2 Director, Canvas Design
- **Human owner:** Farrice decides whether a result is A-tier and whether the companion should later become stricter.

## Context Loading

- **Hot:** `layout-composition-intelligence-contract.md`, Satori workflow 27, the forged prompt.
- **Warm:** existing Satori LIFT, movement, grid, contrast, and Three-Flow references as demanded by the task.
- **Cold:** transcript, video ledger, uncertainty report, and archived frames. Load for provenance disputes, deeper teaching, or system repair.

## Work Chunks

1. Repair source accounting and terminology fidelity inside Satori.
2. Add one composition conductor and one born-v2 prompt.
3. Add a SHADOW inheritance contract with activation and skip conditions.
4. Wire four high-level consumers without changing their native craft ownership.
5. Prove wiring, fidelity, positive behavior change, and negative-control rejection deterministically.

## Agentic Engineering Packet

- **Behavior change:** layout-bearing prompts receive an explicit leverage/path/grid/rhythm/friction/transfer packet before production.
- **Preservation boundary:** no change to brand premises, approved references, generation cost gates, DESIGN.md ownership, or human taste authority.
- **Mutation mode:** local, reversible, workspace-only; no global mirrors or new dependencies.
- **Review loop:** deterministic verifier → realistic cold-start proof → missing-consumer negative control → at most two focused repairs.
- **Stop condition:** all structural checks pass, the negative control fails for the intended reason, and the behavior proof contains source-specific decisions unavailable from a generic “make it look good” brief.
- **No-regression clause:** logo-only, palette-only, exact-pixel, and non-layout image tasks remain valid skip cases; no artifact-wide mandatory schema is created solely to prove activation.

## Dependency Gate

No new runtime dependency. Video retrieval used the already-installed Watch toolchain; the shipped runtime uses Markdown and a standard-library verifier only.

## Human Checkpoint

Technical integration can be VERIFIED. A-tier visual quality remains `UNTESTED` until Farrice reviews real before/after artifacts. Three independent production receipts plus a blind comparison are required before any enforcement promotion.
