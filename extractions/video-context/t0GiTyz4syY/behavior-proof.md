# Behavior Proof: Systems Thinking and Expertise Intelligence Overlay

## Proof Standard

This is a cold-start applied proof for a workflow and agent-system source. Each case records the input, prior failure shape, selected route, source mechanics, output, behavior delta, validation, handoff, and remaining risk. The overlay remains `SHADOW`; these fixtures prove changed decisions, not production outcomes or promotion readiness.

## Case 1: Source Extraction Becomes a Companion Layer

### Input

“Run Extract-Forge and Source-to-Skill-System on Elizabeth Stone's systems-thinking interview. This feels like an intelligence-layer enhancement, not a prompt or skill harvest.”

### Prior Failure Shape

The literal Forge path assumes a new expert skill, eight to fifteen workflows, prompts, and an agent configuration. That would pad an architectural source into a persona and duplicate several existing owners.

### Selected Route

Source-to-Skill-System owns the build. Extract-Forge supplies Deep extraction. Expert Composition governs the integration. No new expert, skill, prompt pack, router, or hot command is created.

### Source Mechanics Used

Zoom identified the wider job as cross-route intelligence rather than one expert package. Craft preserved the authority of existing contract owners. Pave selected one cold primitive plus narrow references. Own kept Source-to-Skill-System as integrator. Learn placed the layer in SHADOW and required behavior proof before promotion.

### Output Produced

The result is the semantic primitive, five owner integrations, one Operator School drill, this proof file, and a deterministic verifier.

### Behavior Delta

The architecture changed from a new isolated capability surface to a connected companion layer with no new invocation burden.

### Validation and Handoff

The source package verifier must pass. The new verifier must detect the primitive, owner references, three proof cases, source boundary, and SHADOW rules. The handoff passes the five decisions and exact source paths, not the full transcript.

### Remaining Risk

This proves design and cold-start behavior only. It does not prove that future production outputs are better or that the overlay deserves enforcement.

## Case 2: Full-Arsenal Content Work Preserves One Craft Owner

### Input

“Use the full arsenal to improve a revenue-critical offer page with positioning, proof, story, voice, design, and compliance expertise.”

### Prior Failure Shape

Six experts could each rewrite the page, producing a stitched-together artifact with duplicated frameworks, inconsistent voice, and no clear authority for the final claim or line.

### Selected Route

The Copywriting function owns the final page. Positioning, proof, story, voice, design, and compliance are considered as bounded contribution slots. Only specialists who change a named decision or line are accepted.

### Source Mechanics Used

Zoom identifies the wider buyer decision and downstream publishable surface. Craft keeps copy integration and voice judgment with one owner while specialists supply narrow changes. Pave reuses the existing High-Taste Writing and Publishable Copy gates rather than inventing a new rubric. Own requires Farrice or the named publisher to approve voice, claims, and release. Learn treats a rejected draft as evidence for a line-level repair before adding a new global rule.

### Output Produced

One coherent page, one Composition Ledger, exact proof boundaries, and one publishing owner.

### Behavior Delta

“Use every expert” no longer means every expert writes. Specialist depth is preserved, adjacent contributions stay bounded, and expert count is not treated as quality proof.

### Validation and Handoff

Expert Composition checks the owner, contribution slots, accepted changes, and rejected overlaps. The handoff contains line-level changes, preserved voice requirements, proof gaps, and publishing risk.

### Remaining Risk

This fixture does not supply a real offer page or buyer outcome. A production receipt and blind comparison are still required.

## Case 3: Repeated Engineering Failure Produces an Upstream Repair, Not Another Checklist

### Input

“Three workflows independently fetch the same source. One failed because its local dependency path drifted. Add a mandatory preflight checklist everywhere so it never happens again.”

### Prior Failure Shape

The local request points toward more process in three consumers while leaving the duplicated upstream acquisition path untouched.

### Selected Route

The system owner inspects the common source-acquisition boundary. The repair targets the shared helper or canonical path, then adds the smallest verifier needed to detect recurrence. Consumer workflows receive a pointer rather than three copied checklists.

### Source Mechanics Used

Zoom reveals that the failure class belongs to shared acquisition, not three local workflows. Craft assigns dependency and source-truth judgment to the engineering owner. Pave creates one canonical acquisition path with a bounded interface. Own names the main-thread integrator who must explain the failure and recovery. Learn requires a blameless root-cause review before any permanent process is approved.

### Output Produced

One upstream repair hypothesis, one canonical source path, one verifier, and narrow consumer pointers.

### Behavior Delta

The maintenance decision changes from three permanent checklists to one root-cause repair with a recurrence check.

### Validation and Handoff

The verifier must reproduce the original failure, pass after the shared repair, and confirm all three consumers use the canonical path. The handoff carries the root cause, affected consumers, recovery command, and rollback rule.

### Remaining Risk

This is an applied architecture fixture, not an implementation of that hypothetical dependency repair. It proves the overlay changes maintenance reasoning.

## Proof Verdict

All three cases produce a material change in architecture, craft ownership, reusable defaults, accountability, or maintenance response. The behavior-changing extraction requirement is satisfied at the cold-start fixture level. Production promotion remains `UNTESTED` and unavailable.
