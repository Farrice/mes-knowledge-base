# Instagram Growth OS — Operator Runbook

## What it does

Give the system a handle plus an evidence packet. It returns the first defensible leak, fixes the account in dependency order, and prepares an eight-week test without pretending views equal revenue.

```text
INSPECT: Offer → Attraction → Profile → Trust → Offer visibility
REPAIR:  Offer → Trust → Profile → Attraction
```

One job per layer:

- **Offer:** make the right buyer want the next step.
- **Trust:** reduce warranted skepticism with voice, judgment, and proof.
- **Profile:** make the right visitor binge relevant evidence.
- **Attraction:** reach the right non-followers.

## First command

```text
/instagram-growth-os Audit @HANDLE. Use the attached Offer Canvas, dated profile screenshots, last-30-day Insights export, representative Reels, proof assets, category/jurisdiction, and primary offer link. Diagnose one breaking point, then draft the Offer → Trust → Profile → Attraction repair plan. Do not edit or publish anything.
```

## Minimum evidence packet

| Evidence | Minimum useful form | If missing |
|---|---|---|
| Offer | buyer, problem, transformation, delivery, price, proof | Offer diagnosis is `UNVERIFIED` |
| Profile | dated screenshots of bio, highlights, pins, grid, link | No visual score |
| Attraction | reach/views and non-follower % for a declared window | No qualified-reach verdict |
| Handoffs | profile visits, follows, DMs, clicks, calls, sales | Missing ratios remain null |
| Revenue | sold and collected, with attribution | Outcome remains `NO_EVENT` |
| Content | representative Reels and performance rows | No trust or outlier diagnosis |
| Compliance | category, jurisdiction, claims, organic/ad/branded status | Restricted work is `HOLD/BLOCKED` |

## Decision rules

1. Compliance risk can hold production, but it does not prove distribution suppression.
2. An unclear offer stops reach work.
3. Large reach plus weak revenue moves the diagnosis upstream; it does not automatically prove one cause.
4. Profile and trust scores need visible evidence.
5. Attraction work begins only after Offer, Trust, and Profile gates pass.
6. The system prepares external assets but does not post, DM, edit profiles, scrape, clone voices, or write to Framer/ManyChat without approval.

## Success state

The build itself succeeds when it produces a reproducible diagnosis, complete repair artifacts, and a controlled test ledger. Commercial success requires attributed live evidence: relevant reach, profile handoffs, qualified conversations, sales, and collected revenue. `$20k+` is a target—not a system promise.
