# Behavior Proof — Say–Do–Need Message Bridge

## Input Tested

A realtor team's weak topic-first concept:

> “Five systems every realtor needs to post consistently.”

Hypothetical evidence packet for the cold-start test:

| Layer | Evidence | Proof state |
|---|---|---|
| SAY | “I need more followers.” | SUPPLIED TEST INPUT, not live research |
| DO | Agents repeatedly choose Reel-hook swipe files and listing-content examples over systems workshops. | SUPPLIED TEST INPUT, not live analytics |
| NEED | A weekly listing-to-trust content system that turns one property event into repeatable proof and follow-up assets. | OPERATOR HYPOTHESIS — UNTESTED |

## Weakness Diagnosed

The original concept leads with the carrot. “Systems” describes delivery architecture, not the audience's chosen entry point. It offers no immediate artifact, no sharer identity, and no evidence boundary.

## Source Mechanics Used

- Say–Do–Need gap.
- Chocolate-covered-carrot wrapper.
- Promise Integrity Lock added by this build.
- Private-truth share identity: the helpful agent who gives another agent something usable.
- Systems-led delivery under the attractive artifact.

## Output Produced

### Selected route: practical value

**Promise:** “7 listing Reel hooks you can post this week.”

**Delivered chocolate:** Seven complete hooks tied to common listing moments: new listing, price adjustment, inspection lesson, neighborhood objection, open-house question, buyer misconception, and seller proof.

**Integrated carrot:** Each hook includes a one-line reuse path—Reel → Story question → follow-up DM → proof-library note—so the agent receives a weekly content system while still getting every promised hook.

**Share identity:** “The agent who always has something useful ready.”

**Natural forwarding sentence:** “Use one of these for your next listing.”

### Promise-to-payload audit

- Surface promise delivered: **PASS** — exactly seven ready-to-use listing hooks are included by contract.
- Deeper need integrated: **PASS** — every hook enters the same repeatable reuse path.
- Bait-and-switch risk: **PASS** — the system does not replace or delay the hook delivery.
- Claim safety: **PASS** — no reach, follower, lead, or sales outcome is promised.

## Behavior Delta

| Before | After |
|---|---|
| Need-first topic | Say/Do-led entry promise |
| Abstract “systems” lesson | Seven concrete promised assets |
| No relationship between hook and delivery | Each asset enters a reusable system |
| No evidence labels | Say, Do, and Need proof states visible |
| Implied usefulness | Specific behavior event defined |

## Validation Run

- Structural transformation: **PASS**.
- Missing-evidence sabotage: **PASS** — verifier returns `NEEDS_EVIDENCE`.
- Broken-promise sabotage: **PASS** — verifier returns `REJECT_BAIT_SWITCH`.
- Market behavior: **NO EVENT**.

## Remaining Risk

The test demonstrates a changed reasoning and output path, not that agents will click, share, implement, book calls, or buy. The Need layer is still an operator hypothesis. A live test must compare qualified behavior and downstream usefulness, not merely views.

## Next Gate

Run the bridge on real realtor audience evidence, publish only with approval, and track at least one distribution event plus one downstream behavior event. Keep the capability at `implemented-unvalidated` until those receipts exist.
