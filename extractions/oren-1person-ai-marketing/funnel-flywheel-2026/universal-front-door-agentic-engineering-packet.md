# Oren Universal Front Door — Agentic Engineering Packet

## Objective

Make every source-grounded Oren package accessible from a cold-start `/oren` request without creating a mega-skill, bulk-loading the corpus, or absorbing specialist-owned work.

## Source truth

- Oren capability packages: the 11 `skills/oren-*` packages named in `agents/oren-taste-development/references/universal-route-map.json`.
- Funnel extension: this extraction package, especially `skill-system-contract.md`, `blind-source-fidelity-review.md`, and `validation-report.md`.
- Runtime owner: `.agent/workflows/oren.md`.
- Machine-readable routing source: `agents/oren-taste-development/references/universal-route-map.json`.

## Work chunks

1. Inventory all Oren skill owners and existing command bridges.
2. Identify the broken access surface: no universal `/oren` workflow and a stale `/oren-one` bridge.
3. Add one canonical conductor, one canonical route map, and thin Claude/Codex bridges.
4. Keep each method in its existing skill package; add no new expert skill and no dependency.
5. Prove the result with cold-start positive, portability, commercial, and negative-control fixtures.

## Context plan

- **Hot:** `.agent/workflows/oren.md`, route-map policy, selected route record.
- **On demand:** selected skill `SKILL.md`, `genius.md`, one workflow, and one execution prompt when applicable.
- **Cold:** all unselected Oren packages, source transcripts, extraction ledgers, and unrelated experts.
- **Hard cap:** one primary Oren package plus at most one bounded support package.

## Dependency gate

- No package installation or new runtime dependency.
- Full VSL copy stays with the VSL/copy owner.
- Paid-media economics and ROAS diagnosis stay with Benoit Vatere.
- Detailed lead-magnet construction stays with Stockton Walbeck.
- The funnel layer may coordinate these owners but may not reproduce their full methods.

## Review loop

Review in this order: bridge presence → route-map integrity → 11 positive routes → two applied funnel cases → three external-owner negative controls → command-menu activation → repo validators. Stop when all deterministic fixtures pass, both `/oren` and `/oren-one` report `hot-bridge`, and no validator finds an unsupported ownership or bulk-load mechanic. Maximum repair scope: the single failing route, boundary, or bridge.

## Structure pass

Keep the runtime surface to one canonical workflow, one route map, and thin compatibility bridges. Check that no Oren method was copied into the conductor, no duplicate expert skill was created, and all route targets exist.

## Human Checkpoint

The user explicitly authorized implementation, commit, guarded merge, and push. The one-writer main-tree interlock remains binding: if main is dirty, park the merge and push the validated feature branch without force.
