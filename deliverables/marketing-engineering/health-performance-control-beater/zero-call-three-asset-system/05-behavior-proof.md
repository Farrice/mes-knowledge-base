# Behavior Proof — DM-Only Baseline to Three-Asset Close

## Input tested

The current Control-Beater buyer-test baseline: one trigger-specific private DM exposing the $500 price, five-static/one-video scope, 72-hour clock and a five-question fit screen. State at inspection: prepared, not sent, no reply, no sale and $0 collected.

## Weakness diagnosed

The DM is a valid smallest buyer test, but it asks one short message to do several awareness jobs at once:

- name the problem;
- establish Farrice's authority;
- explain a new creative-testing model;
- explain the vehicle;
- qualify the buyer;
- expose price and scope.

It therefore has no durable place for the buyer to inspect the belief shift, mechanism, proof boundaries or operating details without asking Farrice live.

## Source mechanics used

- Awareness stages rather than unaware -> most-aware in one jump.
- Model sells the shift.
- Machine sells the vehicle and repeats the shift.
- Invite disqualifies before presenting the decision.
- Progressive filtering at every stage.
- Async fit and payment path with no human save.

## Output produced

1. Public Model: “Six Ads, One Idea.”
2. Unlisted Machine: “How the Control-Beater Works.”
3. Private Invite: exact $500 decision document.
4. Close Path: transitions, fit screen, objections, payment and event states.

## Behavior delta

| Before | After |
|---|---|
| One DM carries belief, vehicle, qualification and offer | Each asset owns one awareness transition |
| Buyer must infer why creative volume fails | Model installs the decision-before-design belief |
| Buyer must ask how the work operates | Machine exposes inputs, hypothesis map, claims, owners and readout |
| Qualification exists only as five questions | Invite leads with wrong-fit conditions and full commercial truth |
| A proof or scope question may pull Farrice into live selling | Async response library preserves the no-call boundary |
| Payment placeholder can be mistaken for readiness | Payment route is explicitly `PENDING`; request is authority-gated |
| Local readiness can feel like demand | Every asset preserves `NO EVENT · $0 COLLECTED` |

**Expected verdicts:** asset build `BUILD`; commercial activation `HOLD`; client delivery `DISCOVER_FIRST`.

**Expected output:** the four files in this directory, with exact Control-Beater terms and no pre-sale call.

## Negative controls

| Fixture | Expected result | Reason |
|---|---|---|
| Vague offer with no price, terms or proof | `HOLD` | Invite cannot expose commercial truth |
| Low-ticket impulse supplement purchase | `REJECT / ROUTE AWAY` | Three-asset considered-purchase path is unnecessary |
| No traffic, referrals or qualified outreach source | `DISCOVER_FIRST` | Assets do not create demand by themselves |
| Unsupported health or performance claim | `HOLD` or `REJECT` | Claim evidence/reviewer gate |
| Buyer has no usable control | `DISCOVER_FIRST` | Cannot position the job as a control test |
| Buyer demands a performance guarantee | `REJECT` | Violates offer truth |
| Procurement insists on a pre-sale call | Continue asynchronously or `DISQUALIFIED` | No-call policy is locked |
| Verbal acceptance, no cleared payment | `SOLD`, not `COLLECTED` | Cash is the start gate |
