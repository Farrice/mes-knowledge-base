## 1. How invocation actually works (read this once)

> **Updated 2026-06-02.** As of this date, **every skill now has its own slash command.** What follows is the corrected, verified model — earlier versions of this section were wrong.

Three things in the system:

| Thing | What it is | How you reach it |
|---|---|---|
| **Skill** | A body of *knowledge* — an expert's methodology, loaded into context so Claude thinks like that expert | `/david-bayer` (NEW), OR name them in plain English, OR auto-suggested by the routing hook |
| **Workflow** | A *procedure* — a sequence of steps (often loads skills inside it) | `/name`, `@name`, "run name", or bare name |
| **Command** (`/name`) | A thin shim pointing at a workflow OR a skill | You type it |

**Two chains now exist:**
- `/parallax` → shim → `.agent/workflows/parallax.md` → loads expert skills inside it (workflow path)
- `/david-bayer` → shim → loads `skills/david-bayer-elite-communication/` SKILL.md + genius.md (skill path, NEW)

### The fix that landed 2026-06-02
Before this date, **241 of 244 skills had no slash command** — `/david-bayer` did nothing, and the only way to reach a skill was to name it or `@`-mention its file. That's now fixed three ways:
1. **Every skill has a `/command`** — short names (`/david-bayer`), full slugs for multi-skill experts (`/luke-iha-vicious-hooks`). Generated by `sync_registries.py`, regenerates automatically when you add a skill.
2. **A routing hook fires on every prompt** — `skill_router_hook.py` (UserPromptSubmit) deterministically surfaces the right skills *before* Claude reasons. You no longer have to remember or name them; describe the job and the matches appear.
3. **`/find-skill <natural language>`** — explicit search, returns ranked matches + slash commands.

### `@` vs `/` — the honest answer
- **`/` now reaches skills AND workflows.** `/david-bayer`, `/april-dunford`, `/parallax` all work.
- **`@` mentions files/resources** — still useful to force an exact file into context (e.g. a specific genius variant), but you no longer *need* it to reach a skill.
- **Plain English still works best for experts** — "use David Bayer's approach" loads the skill via the Skill tool, and the routing hook reinforces it.

### The one nuance worth knowing
A `/command` runs a **process** (workflow) OR loads **knowledge** (skill). For one expert's thinking → `/expert-name` or name them. For a job done end-to-end → a workflow `/command` (`/parallax`, `/autopilot`). When unsure → just describe the job; routing now surfaces the right skill on its own.

## 4. Three things to remember

1. **`/` is your default.** It resolves to skill or workflow automatically — you never have to guess which.
2. **Skill = brain, workflow = procedure, `/command` = doorbell.** A `/command` usually runs a workflow that loads skills inside it.
3. **When unsure which expert fits**, describe the *job* and let routing pick — or open `SKILL_INDEX.md` and grep the Domain column. The cross-references (the "for X use Y" notes) tell you which neighbor is the better fit.

> Maintenance: regenerate `SKILL_INDEX.md` with `python execution/sync_registries.py`. This guide is hand-curated — update categories when new expert clusters are added.
