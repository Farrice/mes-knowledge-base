# /satori-frontend-flow

> Layout thinking compiled for interfaces. AI front-end defaults to evenly-weighted sections and no rhythm — this is the antidote: ONE journey per page, contrast as choice architecture, and the punch → linger → release beat structure "99% of designers don't consider." The Apple product-page pattern, made deployable.

## Quick Deploy

```
Load: skills/satori-graphics/genius.md
Load: skills/satori-graphics/references/layout-flow-hierarchy.md
Load: skills/satori-graphics/references/contrast-stack.md
Execute: skills/satori-graphics/workflows/26-frontend-flow.md
```

## Usage

```
/satori-frontend-flow [page + purpose + sections + aesthetic direction]
```

## When to Use

- Building or briefing ANY web surface: landing page, product page, portfolio, dashboard, artifact page
- An existing page "has everything" but converts poorly — the CTA doesn't win
- Prepping a `frontend-design` / `/product-build` run and you want non-generic structure BEFORE code
- Auditing AI-generated front-end that is symmetrical, evenly spaced, and dead

## Output

A Frontend Flow Brief: the page spine (finisher-first), a section beat map (PUNCH / LINGER / RELEASE — always ending on release into the CTA), behavioral-contrast directives (CTA accent, option steering, double-whammy cards, reserved urgency color, quiet zones), directional wiring + image requirements, DESIGN.md-ready notes, and the 10%-zoom rhythm verdict.
