# /jenny-hoyos-handshake-diandra

Read and execute the workflow at `skills/jenny-hoyos-shorts/workflows/14-jenny-hoyos-handshake-diandra.md` — Hoyos diagnoses a retention-beat map from a LinkedIn post's read-through (cold-open, but/so chains, dip zones, payoff spacing), Diandra converts it into a tagged structural spec (rehook placement, save architecture, payoff position). Output is a structural spec only — never post copy, never a two-author draft.

## Usage
```
/jenny-hoyos-handshake-diandra [LinkedIn post/draft, + engagement data if diagnosing a published post]
```

## When to use
- A LinkedIn post is underperforming and the diagnosis should come from where attention actually drops in the read-through, not a generic "hook is weak" guess
- A long-form post needs its structure engineered for where readers bail (dip diagnosis), not just its opening line polished
- You want retention-graph rigor (dip diagnosis, payoff spacing, loop physics) applied to LinkedIn instead of re-deriving best practices from scratch

## Not This
Diandra = Hooks Only is a standing rule for post AUTHORSHIP — one author per body. This crossing never stitches Hoyos and Diandra into a two-author draft; it produces a structural spec (rehook placement, save architecture, payoff position) that whoever authors the post applies themselves. Full post authorship from scratch → `/diandra-content-engine` or `/farrice-engine`/`writers-room`. Hook-only diagnosis with no retention-graph translation → `/diandra-hook-architect` or `/diandra-rehook-teardown` directly.
