# /dhar-transformational-content-factory

## Purpose

Run the connected Transformational Community Storytelling system from one front door.

This workflow composes existing skills. It does not copy their methods into a mega-skill.

## Function owner

`skills/dhar-mann-transformational-storytelling/`

Dhar owns:

- viewer after-state;
- mission and claim boundaries;
- tension-to-repair covenant;
- safe positive action;
- community feedback loop;
- production-continuity invariant;
- final integration.

Primary workflow family: `skills/dhar-mann-transformational-storytelling/workflows/01-heart-transformation-north-star.md`.

## Inputs

- raw thought, source, or existing draft;
- target audience in a specific situation;
- platform, format, and runtime;
- intended viewer after-state;
- one real lived scene, observation, or proof source;
- creator/brand mission;
- desired safe positive action;
- voice owner;
- audience access;
- available performance evidence;
- for production mode: available assets, known constraints, owners, and unresolved craft needs;
- mode: `strategy`, `production`, or `review`.

If the real scene is missing, mark `[PROVENANCE MISSING]`. Reality Before
Rhetoric is an optional source-recovery practice, not a prerequisite for
strategy, structure, packaging, or a source-labeled outline. Stop only before
invented authorship or an unsupported publishable claim.

## Phase 0: Source, mission, and claim gate

Create a Factory Run Card.

When the earliest diagnosis is `NO SOURCE`, `[PROVENANCE MISSING]`, `ABSTRACT
CONFLICT`, or `UNEARNED SHIFT` caused by absent evidence rather than weak craft:

1. Retrieve workspace sources, receipts, voice evidence, and public evidence
   before requesting input from Farrice.
2. Mark the exact missing scene, bridge, claim, or permission boundary.
3. Offer the optional Reality Before Rhetoric practice only when recovering the
   irretrievable source would materially raise the intended piece.
4. If it is not invoked or the gap remains, continue every supported part as a
   source-labeled brief, strategy, outline, visible placeholder, or smaller
   claim.
5. Block or remove only the fabricated, inflated, private, or unpermissioned
   unit. Hold the full publishable body only when it cannot honestly survive
   that removal.

Do not use source recovery merely because a complete source needs stronger
story craft. Reality Before Rhetoric may help recover truth; Dhar shapes the
transformation.

Stop or narrow the run when:

- provenance is fabricated or unavailable for a personal scene;
- therapy equivalence or substitute-care language appears;
- engagement, retention, impact, or transformation is guaranteed;
- the package exploits pain without an earned repayment;
- the action is unsafe or coercive;
- optimization breaks mission;
- views are treated as proof of transformation.

## Phase 3: Composition switch

### Bayer mode

Choose exactly one:

- `recognition-you` -> `.agent/workflows/bayer-mirror.md`
- `testimony-I` -> `skills/david-bayer-elite-communication/workflows/magnetic-authority-content-system.md`
- `none` -> strategy packet only or another explicit body author

Use `workflows/06-recognized-before-transformed.md` to create the handoff.

### Transformation craft

Choose exactly one:

- `narrative` -> `skills/andrew-stanton-audience-engineering/workflows/stanton-change-engine.md`;
- `educational` -> `skills/kobi-brown-educational-virality/workflows/10-universal-aha-engine.md`;
- `none` -> only when the existing source already earns the shift.

Use `workflows/07-transform-without-preaching.md` to create the handoff.

### Composition limit

One Dhar spine + one Bayer mode + one transformation route + one body author.

Kallaway is cold until a body exists. Kieran Content Ops is downstream and never authors.

## Phase 4: Structure and body

Run `workflows/04-accelerated-youtube-beat-map.md`.

If source and authorship are ready:

- execute one body-author dependency;
- apply the Farrice voice card when applicable;
- preserve the package, recognition, shift, action, and mission.

If not ready:

- produce the production packet;
- name the one missing private fact or source;
- do not create a plausible substitute scene.

## Phase 4.5: Optional production continuity

Activate only when the run mode is `production` and a Viewer Transformation Contract plus approved structure exist.

Choose:

- `workflows/08-story-to-production-continuity.md` when the work needs development intake, capacity fit, production units, department handoffs, or a production-lock verdict;
- `workflows/09-production-capacity-learning-loop.md` when repeated local waits, shared assets, concurrency, reuse, or freshness debt require an evidence-led capacity decision;
- neither when the run is strategy-only or the production need is absent.

Rules:

- efficiency remains subordinate to package, recognition, consequence, shift, action, and mission;
- another studio's crew count, set count, cycle time, and review cadence are never defaults;
- a handoff packet may name but never invent directing, editing, screenplay, casting, software, budget, legal, labor, or safety decisions;
- Kieran Content Ops remains downstream and does not replace either production-continuity workflow.

## Phase 5: Optional post-draft audit

Use Kallaway only to inspect:

- promise match;
- opening hold;
- transition/drop risk;
- belief/attention continuity.

Reject any audit change that:

- adds manipulation;
- changes mission;
- weakens the positive repayment;
- or overrides the selected voice owner.

## Phase 6: Community learning loop

Run `workflows/05-audience-cogreenlight-loop.md`.

Return:

- one decision-changing pre-production instrument;
- smallest complete production;
- discovery, retention, connection, and transformation scoreboards;
- owner, decision date, and next iteration.

Measurement classes remain distinct: Discovery, Retention, Connection, and Transformation.

## Plugin boundary

This is a workspace-local workflow. Three local source-corpus receipts validate components but do not satisfy portability. Do not package or install it globally until:

- three independent real creator runs exist;
- a cold-start test passes;
- the dedicated verifier passes;
- Farrice records a felt verdict;
- and plugin readiness is re-scored.
