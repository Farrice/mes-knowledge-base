# /grace-post-viral

> **When to use**: After any content piece achieves 5x+ your normal reach. The instinct is to celebrate and replicate — this command forces disciplined analysis first.

## Usage
```
/grace-post-viral
```
Or: "run grace-post-viral", "@grace-post-viral", "post-viral analysis"

## What It Does

Three-stage protocol after a viral spike:

### Stage 1: Virality Autopsy (Workflow 14)
— Collect spike data, classify trust stage impact, diagnose come-down tax, assess trust damage

### Stage 2: Trust Damage Repair (conditional)
If the autopsy reveals audience dilution or trust damage (Response C):
- Switch to Grace's trust-rebuilding mode
- Produce 3 Connection/Trust stage content pieces for existing audience
- Reset psychological anchor to pre-viral baseline

**Flood-Zone Integration (a16z Enhancement)**: If trust damage includes an active attack vector (someone misrepresenting, piling on, or decontextualizing):
- Load `skills/andreessen-horowitz-new-media/references/prompts/05-flood-the-zone-crisis-protocol.md`
- Execute the flood-zone crisis protocol: bury the attack under volume of interesting content (exploit the 36-hour viral memory window)
- Deploy pre-built "in the can" content bank (interesting pieces unrelated to controversy)
- Activate ally amplification network for independent supporting content
- 48-hour assessment: has the narrative shifted? If not, escalate to full `/narrative-warfare` response

### Stage 3: City Map Recalibration
- Feed autopsy findings back into City Map (Workflow 01)
- Adjust passenger profiles if audience composition shifted
- Re-validate Grand Central Station alignment

## Steps

1. **Load Context**
   - Read `skills/grace-andrews-media-company/genius.md`
   - Read `skills/grace-andrews-media-company/workflows/14-virality-autopsy.md`
   - Read `skills/grace-andrews-media-company/workflows/01-city-map-architect.md`
   - Read `skills/grace-andrews-media-company/workflows/02-trust-pathway-planner.md`

2. **Collect Viral Spike Data**
   - Ask user for: piece title, platform, normal baseline metrics, viral spike metrics
   - If user doesn't have precise data, estimate with them

3. **Execute Workflow 14** (Virality Autopsy)
   - Run all 6 steps in sequence
   - Classify as Response A (Beneficial), B (Neutral), or C (Damaging)

4. **If Response C — Trust Repair Protocol**
   - Design 3 Connection/Trust stage content pieces targeting EXISTING audience
   - Use Workflow 15 (Emotional Residue Engineer) on all 3
   - Define 7-day + 30-day recovery timeline

5. **City Map Recalibration**
   - Update city map with any shifts in passenger profiles, line performance, or Grand Central alignment
   - If no changes needed, explicitly confirm "city map stable"

6. **Output: Post-Viral Action Brief**
   ```
   # Post-Viral Action Brief: [Piece Title]

   ## Autopsy Summary (Response A/B/C)
   ## Trust Damage Report (if applicable)
   ## Recovery Content Plan (if Response C)
   ## City Map Updates (changes or "stable")
   ## 30-Day Post-Viral Monitoring Plan
   ```

7. **Quality Gate**
   - Verify autopsy is data-driven, not emotional
   - Verify recovery plan (if needed) targets existing audience, not new audience
   - Verify no strategy distortion from come-down tax
