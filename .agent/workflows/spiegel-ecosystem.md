# /spiegel-ecosystem — Ecosystem Build

> Build a moat that can't be copied. Get third parties creating value on your platform so copying a feature is irrelevant.

## When to Use
- You need defensibility beyond features
- After `/spiegel-moat` identifies ecosystem as priority moat layer
- Building a platform, marketplace, or community
- Want to create compounding value without direct involvement in every transaction

## Inputs Required
1. Current product/service/platform description
2. Who currently creates value (just you? contributors? partners?)
3. What value could third parties create if given tools?
4. Existing developer/creator/partner relationships

## Execution Steps

### Step 1: Third-Party Value Audit
Answer the core Spiegel question: "Who else can create value on top of this?"

| Stakeholder Category | Could they create value? | What value? | What do they need from you? |
|---|---|---|---|
| **Developers** | | | |
| **Creators/Content Makers** | | | |
| **Users/Community** | | | |
| **Partners/Businesses** | | | |
| **Resellers/Affiliates** | | | |

If EVERY answer is "only me" → you have a feature, not a platform. Redesign.

### Step 2: Ecosystem Architecture
For each viable stakeholder category:
1. **Value exchange**: What do they get? What do you get?
2. **Tools required**: APIs, templates, marketplaces, dashboards, SDKs
3. **Onboarding**: How do they go from zero to creating value?
4. **Quality control**: How do you prevent ecosystem pollution?
5. **Incentive structure**: Revenue share, exposure, community status, tools access

### Step 3: Chicken-and-Egg Strategy
Every ecosystem faces the cold-start problem. Solve it:
1. **Seed with your own content**: Create the first 50-100 ecosystem contributions yourself
2. **Recruit 10 power creators**: Hand-pick early contributors, give them special access
3. **Subsidize early participation**: Pay, feature, or promote early contributors
4. **Create showcase moments**: Highlight the best ecosystem contributions publicly
5. **Build the tools first**: Make creation so easy that participation is frictionless

### Step 4: Ecosystem Health Metrics
Design measurement for ongoing health:
- **Contribution volume**: How many third parties are creating per week/month?
- **Contribution quality**: What % meets quality standards?
- **Usage**: Are contributions being consumed/used by end users?
- **Creator retention**: Are contributors coming back?
- **Self-sufficiency ratio**: % of value created without your direct involvement

### Step 5: Ecosystem Defense
Once built, protect it:
1. **Switching costs**: What would a contributor lose by leaving? (audience, data, tools)
2. **Network effects**: Does each new contributor make the ecosystem more valuable?
3. **Exclusive capabilities**: What can creators do here that they can't do elsewhere?
4. **Community identity**: Do contributors identify with the ecosystem brand?

## Output Format
```
## ECOSYSTEM BUILD — [Platform/Product]

### Third-Party Value Audit
[Stakeholder map with value exchange for each]

### Ecosystem Architecture
[Tools, onboarding, quality control, incentives per category]

### Cold-Start Strategy
[5-step seeding plan with specific targets]

### Health Metrics Dashboard
[KPIs with targets and measurement frequency]

### Defense Layer
[Switching costs, network effects, exclusives, identity]

### 90-Day Build Sprint
[30/60/90 day milestones]
```

## Quality Gate
- Must identify at least 2 stakeholder categories that can create value
- Cold-start strategy must have specific numbers (not "recruit some creators")
- Health metrics must include self-sufficiency ratio
- Defense layer must address switching costs specifically
