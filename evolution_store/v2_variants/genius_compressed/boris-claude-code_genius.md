## Genius Patterns (Compressed)

### GP1: Manager, Not User (Identity Shift)
Approach every task by asking "What would I delegate?" not "What should I do?" Zero tasks you personally execute that Claude could handle. This reframes the entire human-AI relationship from tool-user to orchestrator-employee.

### GP2: Plan-Before-Execute (Failure Prevention)
For any task >5 steps, demand a plan first and wait for approval before execution. 30 seconds of review saves 30 minutes of rework. First-attempt success rate targets >90%.

### GP3: CLAUDE.md as Living Brain (Context Compounding)
Maintain a CLAUDE.md that grows with every project — learnings, preferences, project references. This becomes your compounding moat; it doubles in value every quarter and makes any new session immediately productive.

### GP4: Multi-Instance Parallel Processing
Run 5-10 Claude instances simultaneously on different workstreams — research, execution, review as separate specialists. Each tab is a specialist employee. Targets 3-5x throughput on complex projects.

### GP5: Self-Verification Loop (Error Elimination)
Never trust single-pass output. Always add "Now verify this output against the original requirements" to workflow. Verification costs less than errors — 80%+ error rate reduction.

### GP6: Device-Ubiquitous Capture (Dead Time Recovery)
Phone starts, computer finishes. Any idle time (commute, waiting) becomes capture/start time on mobile. Desktop completes what mobile initiated. Targets 2x productive hours per day.

### GP7: Context Persistence Protocol
End sessions with "Summarize state for next session continuation." Context handoffs must be explicit — never assume Claude remembers. Zero context loss between sessions.

### GP8: Command Center Architecture
CLAUDE.md serves as command center referencing all active projects, contexts, and preferences. Any new Claude session becomes immediately productive through this central reference point.

### GP9: Exponential Integration Rhythm
Monthly capability audit: "What new can I do that I couldn't before?" Systematically evaluate and integrate new AI capabilities so capability compounds month-over-month.

### GP10: Teaching Through Prompts
Convert successful workflows into reusable prompts after any workflow gets >3 uses. Prompt library grows from actual usage, not theoretical templates.

### GP11: Intentional Friction Reduction
Continuously audit: "What step could I eliminate between intention and result?" Time-to-execution shrinks continuously by removing unnecessary intermediary steps.

### GP12: Strategic Pause Points
Define explicit checkpoints for high-stakes decisions. Know when to pause for human judgment vs. let AI run. Optimal balance of speed and control.

### GP13: The "Layer Under the Layer" Heuristic
Focus on post-training and mechanistic interpretability rather than prompt engineering alone. To build at any level, master the layer immediately beneath it (e.g., understand tool-use distribution to predict agent behavior).

### GP14: Latent Demand Mining
Ignore stated feature requests; hunt for how users "abuse" existing tools. Audit logs for unintended workflows, then build minimal scaffolding to support that exact abuse. Pre-validated demand yields extremely high adoption.

### GP15: The Underfunding Catalyst
Intentionally starve projects of human headcount to force automation. Apply a "1-person constraint" to a 5-person project to activate intrinsic motivation for agentic automation over brittle human-dependent processes.

### GP16: The Bitter Lesson for Product
Refuse to build complex, brittle orchestrators that the next base model will render obsolete. Bet on general capabilities of the next model (6 months out) rather than over-engineering today. Zero tech debt from discarded scaffolding.

## Signature Moves

1. **The "Plan Mode First" Stance** — For any non-trivial task, immediately demand a detailed plan with steps, dependencies, and expected outcomes before any execution begins.
2. **Multi-Quad Parallel Launch** — Upon plan approval, open 3-5 separate Claude instances each assigned specialized, independent sub-tasks (diagnose, implement, test, review).
3. **The "Underfunded Project" Test** — Evaluate new projects by asking "Can I assign this to a single human with no additional headcount, forcing an AI-native solution?"
4. **Latent Demand Audit** — Regularly review user feedback, support tickets, and usage telemetry looking for creative misuse of existing tools as breakthrough innovation signals.
5. **The "Next Model" Scaffolding Check** — Before building any complex orchestration, mentally fast-forward 6 months: "Will the next base model render this obsolete?" If likely yes, defer or minimize.
