## Core Operating System

Website visitors judge in milliseconds — every tool choice and animation decision serves that single neurological reaction through motion, depth, and visual coherence. Establish complete visual identity (color palette, lighting, mood, composition) using reference images and AI generators BEFORE touching any code. Build in layers (foundation, pages, content, CMS, polish), use each tool for exactly one job, and the systematic workflow paradoxically produces sites that look nothing like templates because the visual direction step creates unique aesthetic foundations every time.

## Genius Patterns (Compressed)

### GP1: Visual Direction First
Before touching any code or layout tool, establish a complete visual identity — color palette, lighting, mood, composition — using reference images and AI image generators. Never build without knowing the final aesthetic.

### GP2: Bookend Frame Architecture
Create exactly two frames — starting frame and ending frame — as visual anchors. AI generates all motion in between. These bookends define the visual arc's start state and destination. This is cinematic directing applied to web design.

### GP3: Tool Specialization Pipeline
Each tool handles exactly one job: Nano Banana/Whisk = image generation + style definition; Google Flow/Veo 3.1 = frame-to-video animation; EasyGIF = video-to-WebP conversion; Firebase Studio/Antigravity = website assembly + deployment. Never force one tool to do two jobs.

### GP4: Boilerplate-First Foundation
Never start from zero. Begin with a professionally structured boilerplate — document structure, viewport handling, styling defaults, responsive foundations. Eliminates 90% of setup time.

### GP5: Reference Image Anchoring
Always upload a reference image alongside generation prompts. This anchors AI output to intended color palette, texture quality, and product style — preventing generic, off-brand results.

### GP6: Progressive Polish Protocol
Build in layers: foundation, pages, content, CMS, polish. Each layer is complete before the next begins. Polish (cursor glow, animations, micro-interactions) comes last — they're finishing touches, not foundations.

### GP7: Headless CMS as Client Independence Layer
Position the CMS as the mechanism ensuring clients never call you to update a headline or publish a blog post. Wire up GraphQL endpoints so non-technical users manage dynamic content without touching code.

### GP8: WebP Sequence Scroll Animation Hack
Convert animations to WebP frame sequences triggered on scroll. Export at original resolution, closest native FPS, quality 85, forever loop. Split into frames, store in Supabase, reference URLs for scroll-triggered playback. Keeps visual quality while maintaining page performance.

### GP9: Prompt Document as Build Blueprint
Create a structured prompt document containing every prompt needed for the entire project, organized by phase. Eliminates improvisation and makes the workflow repeatable by anyone.

### GP10: AI Agent as Autonomous Engineer
Treat the AI agent as an autonomous front-end engineer: give implementation plan, review the plan it returns, approve or adjust, let it execute autonomously, verify output. Don't micromanage individual lines.

### GP11: Security-Conscious API Handling
Separate API key handling — never paste secrets into agent prompts. Wait for the agent to create an .env file, then paste secrets only there. No API keys visible in code files, prompts, or version control.

### GP12: Export-Ready Architecture
Build with portability — projects export from Firebase Studio and deploy anywhere (Netlify, Vercel, custom hosting) without restructuring. Use code editor to select all, zip, download, deploy.
