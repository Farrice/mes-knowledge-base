# The Mailroom — What We Built 2026-08-27/28 and How to Use It

> Live councils: expert personas as named teammates who DM each other, argue, concede, and
> converge while Farrice watches — plus the register correction that came out of using it twice
> on his real offer decisions. Companions: `councils/MAILROOM-GUIDE.md` (Farrice's short guide),
> `directives/agent-mailroom.md` (protocol canon), `.agent/workflows/roundtable-live.md`
> (conductor runbook), session record `knowledge/council-sessions/2026-08-27-offer-path-decision.md`.

## ⚡ If you only read 10 lines

- Invoke with one sentence: **"run a live roundtable on ___"** (optionally naming seats).
- Entry gate: conductor first writes its best ONE-PARAGRAPH answer from real reports — confident = ship it, no council.
- Ground seats in `python3 execution/revenue_tracker.py report` + live offer docs, numbers verbatim — never memory paraphrase (scar: "zero cash" vs the real $4,650).
- Cast: `python3 execution/persona_team.py "<question>" --mode tight` (4 seats default, 6 max, Sonnet bodies).
- Live councils are conductor-run **Agent-tool teams** — never `.workflow.js` (workflow agents can't SendMessage).
- Farrice reads TWO things only: the debate in seats' own words + **Do this / Don't do / We're wrong if**; cost = one closing line.
- Brief seats: plain first-person, ≤180 words, no framework names — their words go to him verbatim.
- Close: `python3 execution/persona_team.py close-session --members "<slugs>" --question "<q>" --verdict "<line>" --session "<digest>"`.
- Watcher: `python3 execution/council_pulse.py --full` (wired into the session digest; silent when clean).
- Measured: ~500k-1M tokens per question, ~10 min, $0 cash — deliberate use only, 3-run review at 2 of 3.

## Command table

| Command | Produces | Reach for it when |
|---|---|---|
| "run a live roundtable on X" (chat) | entry-gate paragraph, then (maybe) a live council | real fork, taste-bearing, disagreement worth paying for |

## The mental model

1. **The harness was already the runtime.** Grok Bot's six mechanics (identity, DMs, priority
   tiers, meetings, sandboxes, permissions) map onto agent teams + SendMessage + worktrees +
   permission modes. The entire build was wiring: a bridge (`persona_team.py`), a protocol
   (`agent-mailroom.md`), a runbook. Nothing new runs as a daemon; nothing fires on its own.
2. **The protocol is an anti-chatter device, not a parallelism device.** Pass tokens, bounded
   rounds, and priority tiers exist to END exchanges. A dry meeting closes in one round.
3. **The reader contract outranks the machinery.** What made Farrice call run 1 "a waste of a
   read" wasn't the council — it was reporting process instead of argument. The register that
   landed ("exactly what I wanted"): visible work + the debate verbatim + a one-page decision.
   That register is now his default for ALL substantive outputs (memory:
   `default-output-register-debate-then-memo`).

## Capability: persona-team bridge (`execution/persona_team.py`)

**What it is.** Materializes a `council_cast.py` roster into dispatch briefs for named teammates:
genius.md excerpt (≤6k chars) + the persona's own `agents/<slug>/memory/context.md` (≤2k) + the
Mailroom protocol block + peer roster. `close-session` appends a dated position/verdict entry to
each seated persona's memory — identity accumulates across councils (Hormozi's file now carries
both 2026-08-27 positions). Refuses to invent agent dirs for unknown slugs.
**When to reach for it.** Any live council; also usable alone to generate a single persona brief
with memory loaded.
**When NOT to.** Frozen councils (the .workflow.js engine loads genius files itself, cheaper).
**Worked example.** Session 2 cast Hormozi/Haynes/Flynn/Cole for the stack triage; weak keyword
casts (a contemplative writer seated for a cash decision) get re-seated by hand — cast quality
still needs conductor judgment.
**Honest edges.** Keyword relevance casting is crude; memory files are capped excerpts, not
retrieval; no trust-weighting of seats yet (calibration rows exist, weighting doesn't).

## Capability: live roundtable protocol (`.agent/workflows/roundtable-live.md` + directive)

**What it is.** Conductor spawns seats as named background agents; openings land independently;
meeting rounds run via SendMessage with `[NORMAL]/[PRIORITY]/[URGENT]` tiers and PASS as a legal
move; max 3 rounds; conductor converges and closes. Three binding contracts added after Farrice's
feedback: entry gate (one-paragraph answer first), grounding contract (real reports verbatim),
reader contract (debate + Do/Don't/Wrong-if only).
**When to reach for it.** Genuine can't-call forks: portfolio triage, offer kills, direction
picks with real stakes. Expect 1-2/week ceiling, realistically 1-2/month.
**When NOT to.** Anything the conductor can answer confidently solo (most things); ideation
breadth (frozen mode); pure taste calls (offer a `/jam` instead — two takes, his gut).
**Worked example.** Session 2 (stack triage) produced two genuine reversals: Haynes conceded his
"flip the Stripe link" was functionally park; Cole conceded killing the $500 funnel was wrong
(price problem, not funnel problem) after Flynn's split. Session 1's question, by contrast, had
an obvious answer — it would have failed the entry gate and is the standing example of misuse.
**Honest edges.** Seats are one base model in four voices — direction converged fast both runs;
value concentrated in mechanics and sequencing, not overturned verdicts. Whether that's worth
~4x frozen cost is exactly the open 3-run review (2 done). Watching it is real UX value — score
it separately from decision value.

## Capability: council pulse (`execution/council_pulse.py`)

**What it is.** Deterministic watcher (no LLM): flags calibration rows pending >14 days and
standing councils with template-empty `decisions.md`. Wired as a `session_brief.py` child —
silent when clean, one line when loops are open.
**When to reach for it.** Automatic; `--full` during /cos or weekly closeout.
**Honest edges.** Currently reports 3 July rows + 1 new Mailroom prediction (≥1 substantive
teardown reply within 14 days of send) — it can only nag; closing rows still requires Farrice's
reported outcomes.

## Composition (options, not wiring)

| Stack with | When it earns its cost |
|---|---|
| `/jam` | the fork is taste, not tradeoffs — two takes beat four debaters |
| `/offer-redteam` | verdict needs adversarial kill-testing after the council converges |
| `revenue_tracker.py` / market-pulse | ALWAYS before any offer council — grounding contract |
| `/panel-sync` + `.tmp/assemble` panels | reconvening a bespoke forged panel instead of roster personas |

## Honest edges, whole system

- Two councils spent ~1M tokens to conclude, twice, that the constraint is Farrice's send loop,
  not strategy. The machinery cannot fix the last mile it is rightly forbidden to touch.
- Persona memory compounding is one session old — its value is unproven until runs 3-5.
- Trust calibration (promised in `councils/README.md`) still has no weighting implementation.
- The register contracts live in prompts and directives, not enforcement — drift shows up as
  walls of text; Farrice's "say so and I'll tighten it" is the repair loop.
