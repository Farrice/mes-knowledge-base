# Solution Card — Bounded Freeze Override via Receipt Excavation

**Date:** 2026-07-07 · **Domain:** strategy / decision architecture · **Session:** Alignment Architect launch

## The problem
A binding strategic freeze (Path Decision Incumbency Rule) collided with a persistent founder pull toward a "new" offer (Alignment Architect). The default reads were both wrong: blocking it treats the pull as pure sabotage-pattern; building it fresh treats it as a greenfield idea and repeats the documented redirect loop.

## The crack
**Excavate receipts before ruling.** Episodic memory + Notion mining surfaced what neither the original council nor the current PMF brief had: the "hypothetical" offer had already been SOLD ($3,000, Coach Cooz) — and the failure was classifiable as **delivery-model failure** (unbounded guarantee, architect-does-everything, no client-reps gates), not concept or sales failure. That classification changes everything: a delivery-model failure is fixable with mechanics; a concept failure is not.

## The method (reusable)
1. **Excavate before arbitrating**: episodic search + Notion search + workspace grep for the contested idea. Look specifically for money that moved.
2. **Classify the prior failure**: concept / sales / delivery-model / execution. Only the last two justify a rebuild.
3. **Override as bounded test, on record**: written override doc, the new evidence named, the pattern-risk named against future-self.
4. **Falsifiability is the safety rail**: pre-committed win/kill conditions with an execution qualifier (kill only counts if ≥80% of reps happened), AND — the wargame's critical catch — **a tracked metric for the incumbent path** (Path A touches ≥3/week). *A congruence claim with no metric that could falsify it is a hope, not a fact* — that exact gap is how "one lane, two rungs" becomes the next redirect wearing a scoreboard.
5. **Rebuild kills the named failure modes structurally**, not rhetorically: bounded guarantee, hour ceilings on every rung, client-does-reps gates with a no-chase pause clause.

## Why it worked
The override stopped being freeze-vs-founder and became evidence-vs-evidence: a real receipt beat a real pattern, but only inside a container the pattern can't dissolve.

## Reuse triggers
Any time a user pushes against a standing strategic binding; any "dead idea" revival request; any offer described as unproven — check for buried receipts first.
