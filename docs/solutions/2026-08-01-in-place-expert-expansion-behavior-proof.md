## Problem

A focused source introduced a connected operating method that was only partly represented across an existing expert and adjacent production specialists. Creating another skill would split authority, while adding a prompt and command alone would prove only that the package existed.

## Root Cause

Source extraction often confuses technique count with capability shape. The missing leverage was an orchestration layer: one owner had to turn evidence into a locked hypothesis packet, and a frozen case had to show that the packet changed the resulting decision and test design.

## Approach That Worked

1. Preserve the primary source, label claim classes, search the existing roster, and write a Skill System Contract before mutation. Choose an in-place workflow when the expert already owns the strategy and adjacent specialists already own production.
2. Build one source-led workflow and one born-v2 prompt, generate only the thin family wrapper, then prove natural-language routing and run a detached before/after fixture with provenance, decision, handoff, and remaining-risk gates.

## Dead Ends

- A generic static-ad mega-skill would have duplicated Dara, Fraser, and Omar.
- A Parker-specific implementation would have made an unverified vendor demonstration part of the durable method.
- `generate_slash_commands.py --help` is not a read-only help path; it regenerates the catalog. In this run the output was deterministic and produced no diff, but scoped wrapper tooling is the safer route.
- A stale `validate_workflow_contracts.py` reference no longer resolves. `skill_auditor.py check --skill <slug>` is the current workflow-contract and menu-parity gate.

## Verification

- `skill_auditor.py` passed all 7 checks, including all 7 workflow contracts and menu parity.
- `renaissance_audit.py` passed 3,742 v2 prompts with 0 failures.
- The prompt index exposed the new Alex prompt and increased to 7,310 entries.
- Natural-language routing ranked `/alex-copper-static-acquisition-system` first for its intended static-acquisition queries.
- The frozen Morrow Sleep case passed all 10 behavior gates and kept live market performance explicitly unproven.

## Weaker-Model Trap

A weaker model will either create a duplicate skill because the source contains several techniques, or blend Alex, Dara, Fraser, and Omar into expert soup. It may also call the build deployed after registry and routing checks without showing a changed decision on a realistic input. Require one function owner, bounded handoffs, and a behavior proof artifact.
