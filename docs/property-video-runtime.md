# Cinematic property films: shared local installation

Use `property-video-ai` or `jen-cinematic-property-film` in Codex or Claude Code with a listing URL. Both commands load the same locally installed source packs, latest approved specimen and production tools. `real-estate-marketing-fal` remains a compatibility entry; it does not grant API spending.

The repository is public. Only the installer and thin entry points are committed. Paid source packs, prompts, private records and media live under the gitignored `.private/property-video/` home. The installer preserves the original task folders and verifies each copied file. It does not download, generate, publish or send data.

Run `python3 execution/property_video_runtime.py status` to locate the current workflow, approved standard and inherited budget record. Run `python3 execution/property_video_runtime.py verify` to verify the preserved files, source catalog, approved baseline and renderer installations. A clean verification is integrity and installation proof; it does not certify a new generated shot or prove live Claude browser execution.

Initial installation takes explicit source-root arguments: `python3 execution/property_video_runtime.py install --rosita-root <source-worktree> --armida-root <source-worktree>`. It refuses to overwrite an existing installation or changed destination. Source originals are copied, never moved. No credentials are copied. Global skill links should point to this repository's `.agents/skills/` entry points, not a temporary worktree.

New projects use their own source facts and spending approvals. Preserve current taste decisions, review motion and geometry before batching, and keep the private runtime out of public Git history. Use the asset index in the private home for human retrieval.

After copying, `python3 execution/property_video_runtime.py relocate-replays` creates independent replay states in the private runtime. It first verifies the original completed state and all relocated video bytes, preserves every trim and setting, and updates only path-dependent fingerprints. Original reviewed states remain unchanged. `runtime/REPLAY-RECEIPT.json` records the zero-generation replay checks.
