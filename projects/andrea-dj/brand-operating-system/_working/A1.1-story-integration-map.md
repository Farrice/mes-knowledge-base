## Scoring system

- **0 — Story-independent operational.** Doc is procedural / template / operational. Story relevance not expected (e.g., DOCX-format spec, change-log template, run-of-show timing).
- **1 — Fine as-is.** Story is implicitly compatible. No edit needed. Doc inherits the integration via reference to upgraded foundation files.
- **2 — Micro-touch.** One sentence, one example, or one inline reference to story material strengthens the doc without rewriting it.
- **3 — Section rewrite needed.** A defined section of the doc directly carries founder-voice / origin material and must be regenerated to reflect story integration.

## Stage 2.5 G3 cohesion-audit instructions

After the 13 v1.1 rewrites + touches ship, run a cohesion audit on every score-0 and score-1 doc. The audit question is simple: **with story-context loaded (A1 §9 + Brand Bible v1.1 §5 in the reviewer's working memory), does this doc still breathe Andrea's vibe — or does it now read as flat, generic, or stylistically disconnected from the upgraded foundation?**

Any score-1 doc that drifts under the audit gets reclassified to score-2 and patched with a one-line or one-paragraph touch that re-grounds it. Any score-0 doc that drifts likely indicates the reviewer mis-classified it as operational when it actually carries voice load — escalate to score-2 or score-3 as appropriate.

The audit is bounded: a doc passes if it would not embarrass Andrea in a hypothetical "show me how every layer of my BOS reflects who I am" reading. The audit is not a request for stylistic perfection; it is a check for *coherence-with-the-upgraded-foundation*. Operational docs (run-of-show, change-log format, ticket spec) are exempt from the vibe test because their job is mechanical.

The G3 audit output ships as `_working/G3-story-cohesion-audit.md` and updates this map (A1.1) with any reclassifications. After G3 ships, BOS v1.1 is canonically complete.
