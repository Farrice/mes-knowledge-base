# Systems Thinking and Expertise Intelligence Overlay

Status: `SHADOW`. This is a companion intelligence primitive, not a command, router, expert, score, schema, or blocking gate.

## Purpose

Use this overlay to help existing Antigravity owners reason one level beyond a local task while preserving the specialist judgment, source truth, human accountability, and execution speed needed to finish the work well.

The source is Elizabeth Stone's interview on Lenny's Podcast at
`https://www.youtube.com/watch?v=t0GiTyz4syY`. The verified source package is
`extractions/video-context/t0GiTyz4syY/`. Its timestamped extraction map lives
in `analysis.md`, and the mastery harvest lives in `deep-extraction.md`. The
evidence is transcript-backed spoken material; visual frames and OCR are
unavailable.

## Activation

Apply the overlay quietly when at least one condition is true:

1. A local decision affects three or more downstream consumers, components, or workflows.
2. Several experts or functions can contribute, but scarce craft judgment still needs a clear owner.
3. Multiple teams, agents, or workflows repeatedly solve the same foundation.
4. AI-generated work has meaningful quality, safety, source-truth, or recovery consequences.
5. A failure creates pressure to add permanent process before the cause and learning are understood.

Skip it for tiny, mechanical, obvious, or already well-paved work. Never ask extra questions merely to prove the overlay ran.

## The Five Decisions

### Zoom

Step out exactly one level from the local task. Name the wider outcome, the assumption that matters at that level, the downstream consumer, and any reusable building block. Return to execution as soon as the wider view changes or confirms the local decision.

Failure signal: generic “think bigger” language, strategy theater, or continued abstraction after the decision is clear.

### Craft

Name the scarce specialist judgment that still owns “what good looks like.” Adjacent contributors and agents may execute across role boundaries, but certification, exception handling, and consequential tradeoffs stay with the fitting craft owner.

Failure signal: either role protectionism that blocks useful contribution or shallow generalism that treats all judgment as interchangeable.

### Pave

When the same foundation recurs, encode a strong default that carries source truth, access rules, quality markers, guardrails, reusable components, and allowed variation. Aim to solve the shared portion once while leaving a bounded last mile for context.

Failure signal: every local team rebuilds the base, or the common path tries to control 100 percent of cases and becomes a cage.

### Own

Assign one human or operator as the outcome owner. That owner must be able to defend the problem choice, review boundary, quality judgment, and recovery path even when an agent performed the work.

Failure signal: “the model did it,” unclear review authority, or an output nobody can explain, diagnose, or repair.

### Learn

After a failure, run a blameless reflection on assumptions, decisions, source truth, handoffs, and changed behavior before adding permanent process. Add a durable gate only for a demonstrated recurring need or a hard truth, proof, privacy, safety, or permission veto.

Failure signal: a new checklist appears after every scar while the upstream cause remains unchanged.

## Owner Integrations

1. **Operating Alignment owns Zoom.** It identifies the one-level-wider outcome before final routing.
2. **Expert Composition owns Craft.** It protects specialist judgment while allowing bounded adjacent contribution.
3. **Skill System owns Pave.** It encodes the reusable default, downstream consumers, and allowed variation.
4. **Agentic Engineering owns Own.** It assigns the outcome owner plus explain, diagnose, and recovery duties.
5. **Goal-Loop Maintenance owns Learn.** It requires retro-before-rule and prevents process accretion.
6. **Operator School teaches the combined move.** It drills one-click zoom, craft ownership, and return to execution.

No integration transfers authority away from its existing contract. This primitive supplies shared reasoning language and source grounding only.

## Context Policy

Keep this primitive cold and load it on demand. Existing owners may retain a compact pointer and their native decision. Do not preload the transcript or Deep extraction. Handoffs pass the changed decision, exact source path, owner, and open risk rather than the full upstream context.

## SHADOW Rules

The overlay may recommend or explain. It may not:

1. block safe work;
2. add mandatory questions or fields to clear tasks;
3. create a universal readiness score;
4. override factual, proof, privacy, safety, cost, destructive-action, or permission vetoes;
5. hot-promote itself into a command, router, skill, agent, hook, or global mirror;
6. claim deployment success from file presence or verifier output alone.

## Behavior Proof and Promotion

The current proof artifact is `extractions/video-context/t0GiTyz4syY/behavior-proof.md`. The overlay remains SHADOW after this build.

Promotion requires three independent production receipts across different task types, a blind comparison where the overlay result is preferred or materially clearer, zero new blocks on frozen safe controls, no added question burden for clear tasks, preserved creative range and specialist depth, and explicit Farrice approval.

Keep it cold or remove it if it produces generic abstraction, duplicates current owners, adds ceremony without changing a decision, or makes clear tasks slower and less decisive.

## Quality Test

A strong use changes at least one of these: route, architecture, craft ownership, reusable default, review boundary, recovery plan, or maintenance decision. If none changes, the overlay should remain silent.
