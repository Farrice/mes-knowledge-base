# Category-Building Deployment Contract

## Purpose

Use this primitive when a brand, offer, product, creator, or internal system needs to change the category people use to judge it.

The goal is not a clever label. The goal is a new frame of reference that changes expectations, proof standards, pricing logic, language, content, and behavior.

## When To Use

- A brand is trapped in a default category and being judged by the wrong criteria.
- A service or offer sounds like a better version of a crowded thing.
- A founder, creator, or expert has an unfair intersection but no repeatable category language.
- A content system needs world-building, belief architecture, and adoption signals.
- A product or workflow needs to become easier to explain because the old category creates wrong expectations.
- Internal harness design needs a new capability lane without adding a competing command or mega-skill.

## When Not To Use

- The user only needs a tagline, headline, or naming brainstorm.
- The category is a normal service renamed with fancier language.
- The buyer cannot tell what problem changes.
- There is no proof, ritual, repeated behavior, or adoption signal.
- The move is only trend-chasing, shock value, or aesthetic contrast.

## Anti-Gimmick Gate

Reject or repair the category if any of these are true:

- The phrase sounds impressive but does not change buyer understanding.
- The category depends on novelty instead of truth.
- The proof does not exist yet.
- The audience would need a long explanation before caring.
- The new category is just the old category with a premium adjective.
- The category cannot generate repeated content, proof, and rituals for at least 90 days.

## Deployment Standard

A category is deployed only when all four layers exist:

1. **Language:** people can repeat the category in plain words.
2. **Proof:** the brand demonstrates the category through visible behavior.
3. **Ritual:** the proof repeats often enough to become associated with the brand.
4. **Adoption:** audience or buyers begin using the language, asking for the ritual, or comparing alternatives through the new criteria.

## Quality Gate

Pass only if the output:

- names the current category and hidden rules
- changes the criteria of judgment
- has proof behind the unfair intersection
- gives buyer-readable language
- includes proof rituals and adoption signals
- creates a 30-day deployment sequence
- includes behavior proof before calling the category operational
