# Alex Suzuki Revenue OS — User's Guide

How to drive the OS properly: the mental model, the command map, best-leverage use cases, do-NOT-use cases, and the guardrails. Built from three Alex Suzuki videos; all his revenue figures are creator claims — the OS uses his *mechanics*, never his promises.

---

## 1. The mental model (read this first)
Everything in the OS is one machine:

`specific result post → comment/like trigger → DM or auto-DM (free asset) → trust → checkout (low-ticket) or application+call (high-ticket) → reply sprint → proof loop`

The edge is **a high-fit buyer taking a small public action**, not big reach. Three things must always be true (the OS enforces them):
1. The post names a specific buyer + a specific result/asset (repels the wrong reader).
2. Proof is real (owned facts are fine; never invented).
3. The CTA is an **opt-in** "like/comment → I'll send X" (this is what makes the DM legal and the automation possible).

At scale, two layers get added: **cold-start** (sell a partner's real proof or an affiliate product when you have none) and **automation/portfolio** (generate → schedule → opt-in auto-DM across many accounts).

## 3. Decision tree — which command to start with
- Have a product, want to sell on X now → `/suzuki-revenue-os`
- Just want the post (and variants) → `/suzuki-post-lab` (or `/suzuki-tweet-to-sale` for one)
- No product / no proof / starting from zero → `/suzuki`
- Need to decide build vs partner vs affiliate → `/suzuki-product-source`
- Have a working funnel, want more volume → `/suzuki-automate`, then `/suzuki-scale`
- Want it on another platform → `/suzuki-platform-engine`
- It's getting attention but not selling → `/suzuki-launch-debugger`
- Want the entire system in one pass → `/suzuki`

## 4. Best-leverage use cases (where this is the right, high-ROI tool)
1. **Selling a high-margin digital product** ($50–$10K: ebook, course, template, community, cohort, productized service) to a buyer who's on X and has capital.
2. **"Teach people how to [outcome]" info products** — the OS's native sweet spot.
3. **You have expertise but no audience/proof yet** — `/suzuki` routes you to the partner or affiliate path instead of stalling.
4. **You want the strongest possible sales post + a bank of variants** to test — `/suzuki-post-lab`.
5. **A funnel already works and you want to multiply it** — `/suzuki-automate` (autopilot) + `/suzuki-scale` (more accounts/niches).
6. **Taking a proven X offer onto Instagram/LinkedIn/etc.** — `/suzuki-platform-engine`.
7. **Diagnosing a dead funnel** — `/suzuki-launch-debugger` (it treats wrong-audience attention as failure).
8. **A focused launch window or cohort open** — `/suzuki-flash-launch`.

**Maximum leverage when:** the buyer can take a public micro-action (like/comment), you'll do the first-window reply sprint, your margins are high, and your proof is real (or you'll borrow a partner's real proof).

## 5. Do-NOT-use cases (wrong tool, or it will fail / create risk)
1. **Physical products / e-commerce** with inventory, shipping, fulfillment → wrong tool. Use the **Meg Heckman Buyer-Trigger OS** (`/merch-os`) for merch, or a real ecom stack.
2. **Local / brick-and-mortar / service businesses** with no packaged digital offer.
3. **Building the actual product/course content** → this OS *sells*; it doesn't write your curriculum. (`/suzuki-product-source` scopes a spec, not the finished book.)
4. **Brand identity, visual design, naming** → use `/brand-operating-system` or DESIGN.md tools.
5. **Slow newsletter/authority nurture as the primary play** → this is direct-response selling. For a newsletter flywheel use the Nicolas Cole / newsletter skills (Substack/email are supported here only as funnel *surfaces*).
6. **You won't show up for the reply sprint / early management** → the funnel assumes active first-window work.
7. **You have no real proof AND won't partner, affiliate, or build** → the OS refuses to fabricate proof. It is not a "fake it" machine.
8. **Pure reach / brand-awareness with no offer** → it optimizes conversion to a sale, not vanity metrics.
9. **Regulated claims** (financial advice, health, guaranteed income) → the compliance gate blocks guaranteed-income language; get professional/legal review before selling these.
10. **Cold mass-DM, fake engagement, impersonating a partner, fabricated scarcity** → hard-blocked by the compliance gate. If that's the intent, the OS will refuse.

## 6. Guardrails (what the OS enforces — so you stay safe)
- **Creator claims labeled** — Suzuki's $1.8M/$97K/etc. are never presented as your expected results.
- **Opt-in auto-DM only** — DMs fire because someone liked/commented to ask. No cold mass-DM (ban risk + the OS won't do it).
- **Disclosure** — partnerships and affiliate links must be disclosed (FTC); borrowed proof must be the partner's *real* proof.
- **Human claim-edit gate** — AI-generated posts are reviewed for claims/disclosures before they're scheduled.
- **Multi-account = distinct** — no duplicated copy/identity, no fake engagement (platform ToS).
- **Honest scarcity** — flash launches use real caps/deadlines/bonuses, never fake countdowns.
Every risk-bearing run ends with a **compliance ledger** (claims / disclosures / platform-risk / verdict: SHIP / SHIP-WITH-DISCLOSURE / REVISE). Reference: `references/compliance-gate.md`.
