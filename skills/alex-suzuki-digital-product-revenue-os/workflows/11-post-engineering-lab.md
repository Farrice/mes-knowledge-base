# Post-Engineering Lab

## Use When
The user wants the deepest post-construction pass: a hook bank, anatomy-mapped final post, reusable swipe templates, a scroll-stop test, or AI-generation at volume. This is the "how he writes the posts" engine.

## Load First
- `../genius.md`
- `../references/post-anatomy.md`
- `../references/post-mechanics.md`
- `../references/compliance-gate.md`

## Pre-Flight Gate
Confirm buyer, product, price, proof posture, free asset, and platform. If proof is thin, switch to owned facts (page/module count, sample, turnaround). If the user only wants questions answered (no purchase motion), route to `/suzuki-launch-debugger` first.

## Steps
1. **Lock inputs**: buyer, product, price, proof, free asset, platform.
2. **Proof posture**: pick the strongest *safe* proof cue; owned facts when revenue proof is unverified.
3. **Hook bank**: generate 15 first lines across the post-anatomy types (result/number, asset/owned-proof, problem/contrarian, curiosity/mechanism, proof/case, offer-led).
4. **Score + pick 3**: run the scroll-stop / buyer-quality test; keep the 3 that stop the right buyer and repel the wrong one.
5. **Build the anatomy** for the top hook: header → body (context + what's inside + proof cue) → deliverable bullets → two-lane CTA → reply-sprint plan.
6. **Swipe templates**: produce 5 reusable skeletons customized to this offer (build reveal, problem→asset, case study, free-first, offer-direct).
7. **Volume option**: if scale is needed, output the AI-generation prompt pack to batch 20-50 variants — flag the mandatory human claim-edit gate before scheduling (`/suzuki-automate`).
8. **Compliance pass**: claim ledger + any earnings/affiliate/partner disclosure.

## Content Type Adaptations
| Offer | Adjust |
|---|---|
| Ebook | Lead with page count + sample; bullets = chapters/outcomes |
| Course | Lead with module count + transformation; bullets = lessons |
| Community | Lead with access + people + wins; CTA → free channel then application |
| Service / DFY | Lead with outcome + turnaround; CTA → fit check |
| Affiliate | Lead with buyer outcome; add FTC disclosure |
| Partner post | Use the partner's real proof; add partnership disclosure |

## Output Format
```markdown
## Inputs Locked
## Hook Bank (15, by type)
## Scored Top 3
## Final Post (anatomy-mapped: header / body / bullets / two-lane CTA / reply sprint)
## 5 Swipe Templates (customized)
## AI-Gen Prompt Pack (+ human-edit gate note)   [if volume]
## Claim Ledger + Disclosures
```

## Quality Gate
- The three invariants present (qualified hook, proof body, opt-in multi-freebie CTA).
- Ready buyers have a purchase lane separate from the value lane.
- No invented proof or guaranteed-income language.
- Every output line could spawn 50 honest variants (scale test).
- Fail and run `/suzuki-launch-debugger` if the draft is a question-map with no purchase motion.
