# Audience Quality Router

## Use When
The user has views or engagement but weak sales, or needs to aim a post at buyers instead of spectators.

## Load First
- `../genius.md`
- `../references/post-mechanics.md`

## Audience Types
| Type | Signal | Action |
|---|---|---|
| Buyers | Ask price, fit, implementation, timeline | Send proof and checkout/application |
| Peers | Praise craft or strategy but avoid purchase talk | Engage lightly, do not optimize around them |
| Spectators | React to drama, numbers, or curiosity | Tighten buyer filter |
| Freebie collectors | Comment for every asset but never act | Add fit criteria and buyer-specific proof |

## Steps
1. Identify current audience attracted by the hook.
2. Rewrite the hook to name buyer, pain, and product context.
3. Add fit criteria to the free asset or CTA.
4. Define reply routing by comment type.
5. Choose the posting window and early reply sprint.

## Output Format
```markdown
## Audience Diagnosis
[Who the current post attracts]

## Buyer Filter Rewrite
[New hook and fit language]

## Comment Routing
| Comment Type | Reply | Next Step |
|---|---|---|

## Timing Plan
[Posting window and first 10-minute sprint]

## Watch Metrics
[Buyer comments, DMs, checkout clicks, applications]
```

## Quality Gate
- Audience Diagnosis names the actual attracted type from the Audience Types table (buyer, peer, spectator, or freebie collector) — not a vague "mixed" or "general" audience.
- Buyer Filter Rewrite changes what the hook names (buyer, pain, or product context), not just the CTA wording — a rewrite that only swaps the CTA fails this gate.
- Comment Routing gives a distinct reply and next step per comment type; a shared boilerplate reply across rows fails this gate (see Pattern 3, `genius.md`: audience quality is a reflection of the copy).
- Timing Plan names both the posting window and the first 10-minute reply sprint, not one without the other.
- Watch Metrics tracks buyer-behavior signals (DMs, checkout clicks, applications) as the primary read, with impressions/views noted only as context — never as the success metric.
