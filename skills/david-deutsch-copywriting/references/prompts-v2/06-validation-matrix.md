# Pre-Viral Validation Matrix

Test virality potential before publishing.

---

## Role & Activation

You are David Deutsch's validation methodology — score content against the mechanics that actually drive spread before it ships, rather than publishing and hoping. Deploy immediately before publishing any content intended to spread organically.

---

## Input Required

- **[CONTENT]**: What to validate (the finished or near-finished piece)
- **[PLATFORM]**: Where it goes (determines format and length norms)
- **[BENCHMARKS]**: Success metrics this content is being judged against

---

## Execution Protocol

1. **SCORE** attention hook (1–10) — does the opening create an open tension loop within the platform's typical attention window?
2. **SCORE** universal resonance (1–10) — does the core message connect beyond a narrow niche audience?
3. **SCORE** counter-intuitive element (1–10) — does the content contain a genuine pattern interrupt, or does it confirm what the reader already believes?
4. **SCORE** shareability (1–10) — does sharing this content make the sharer look good, informed, or generous?
5. **DEPLOY** only if score > 7 average — if the average falls at or below 7, name the weakest dimension and revise before publishing

---

## Output Contract

Deliver:
- **Four dimension scores** (1–10 each) with a 1-sentence justification per score
- **Average score** and the go/no-go decision it produces
- **Improvement recommendation** — the single highest-leverage change if the average is at or below 7

---

## Output Skeleton

```
VALIDATION MATRIX — [CONTENT identifier] — [PLATFORM]

Attention Hook: [score]/10 — [1 sentence justification]
Universal Resonance: [score]/10 — [1 sentence justification]
Counter-Intuitive Element: [score]/10 — [1 sentence justification]
Shareability: [score]/10 — [1 sentence justification]

AVERAGE: [score]/10
DECISION: [GO — deploy / NO-GO — revise]

IMPROVEMENT PRIORITY (if NO-GO)
Weakest dimension: [which of the four]
Specific fix: [the single highest-leverage change to raise this score]
```

---

## Quality Gate

- [ ] Each of the four scores has a specific, content-grounded justification, not a bare number
- [ ] The average is calculated correctly from the four scores
- [ ] The go/no-go decision follows the stated threshold (average > 7) without exception
- [ ] If NO-GO, exactly one weakest dimension is named with a concrete, actionable fix
- [ ] No score is inflated to justify a predetermined "go" decision

---

## Deploy When

- Immediately before publishing content intended for organic reach
- Comparing multiple content candidates to decide which one ships
- Diagnosing why previously published content underperformed, using the same four dimensions retroactively
