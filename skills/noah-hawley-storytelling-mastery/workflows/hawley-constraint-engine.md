# Constraint Engine

A budget limit makes one storyteller shrug and shoot an episode where everyone just talks in a room. The same limit makes Hawley ask what the room makes *possible* — and the answer becomes the show's signature. This workflow runs that fork: it names the constraint, exposes the lazy default hiding inside it, and pressure-tests until the limit produces a move you'd never have made with abundance.

## Input Required
- **The constraint** — the actual limit (e.g. "$0 ad budget," "one location," "90-second runtime," "one founder, no team," "single product photo").
- **The story / deliverable** it constrains (season, essay, campaign, ad, post).
- **The theme or question** the work is answering — so the invented move serves meaning, not just cleverness.
- **The mid-piece risk**, if any — where the energy might sag (a season's late middle, an essay's third act, a campaign's week three).
- **What abundance would have looked like** — the version with unlimited budget/time/scope, so you can measure what the limit forces.

## Workflow

### Step 1: Name the constraint and the lazy default
Write the constraint as a flat fact. Then write the response it produces *by default* — the move you'd reach for if you absorbed the limit without thinking. The default almost always sounds reasonable; that's why it's dangerous. "We can only afford one location, so I guess everyone just talks in a room for an episode" is the canonical example. Catch it.

| Field | Fill in |
|-------|---------|
| The constraint (flat fact) | |
| The lazy default it produces | |
| Why the default is reasonable-sounding | |
| What the default quietly surrenders | |

The last row matters most. The default doesn't feel like a loss — it feels like being responsible. Name the thing it gives up (urgency, surprise, the theme's bite) so you can refuse to give it up.

### Step 2: Refuse it — ask what the limit makes possible
Stop treating the constraint as a fact to absorb. Treat it as a problem to invert. The question is never "how do I survive this limit" — it's *what does this limit make possible that abundance wouldn't?* Horror gets the biggest emotion for the least money **because** it's low-budget and single-location — the limit is the engine, not the apology.

Answer these out loud:
- If money/scope were unlimited, what *easy* move would I make — and why would that move be worse?
- What does the limit force me to *withhold*, and could that withholding detonate (dry-then-score)?
- What does scarcity make the audience *imagine* that abundance would have shown them flatly?
- What is the one thing this limit hands me for free that a bigger budget never would?

If you can't name something the limit *gives*, you haven't refused the default yet. Go back to Step 1 and find a harder default to break.

### Step 3: Invent the move
Convert the answer into a concrete structural or formal move. Two reliable shapes:

- **Make the constraint urgent.** If you only get one location, make that location a pressure cooker — a reason the characters *can't leave* turns the limit into the source of tension. The room stops being a compromise and becomes the trap.
- **Move when the energy stalls.** When a season hits its late middle, the structural answer is structural — Fargo S1 ep8 leaps a year forward; S2 ep7 puts Ed and Peggy on the run. A timeline jump or a location move escapes the lull *because* the form was about to sag, not in spite of it.

| The limit | The inventive move it forces | What it makes urgent / what it escapes |
|-----------|------------------------------|----------------------------------------|
| | | |
| | | |

Generate at least two candidate moves. Pick the one whose *only* reason to exist is the constraint — that's the signature.

### Step 4: Check that the limit became a signature, not a patch
A patch hides the constraint and hopes nobody notices. A signature wears it — the limit becomes the thing people remember. Run the move against the question from Step 2's first bullet: would you make this move *even if the constraint vanished?* If yes, it's a patch dressed up as invention; the limit isn't doing the work. If the move only makes sense *because* of the limit, you've turned the limit into a feature.

Then check it serves the theme. A clever constraint-move that betrays the question is the white-hat-at-noon twist in disguise — cut it however inventive. The biscuit scene works because the season's constraint (decency vs. cynicism) *forced* the refusal of the violent payoff, and the refusal answered the question. The move and the meaning are the same move.

## Content Type Adaptations
| Format | Adaptation |
|--------|-----------|
| Screenplay / TV | Treat budget, location count, and runtime as story engines. Single-location → urgency that traps; late-middle sag → timeline jump or location move; tight episode runtime → verb-driven concentration (Fargo S5's 44-min cap as a feature). |
| Long-form essay / Substack | Word ceiling, no original reporting, or one anecdote → the limit forces compression and a single deep image instead of a survey. The third-act sag (HK-5) gets a structural move: a section break that relocates the argument, not another paragraph of payoff. |
| Short-form (LinkedIn / X) | Character cap or 90-second runtime is the engine — the limit forces the withhold. One product shot, one line, one frame: make the scarcity carry the imagination the way Paranormal Activity carried fear on $15K. |
| Brand / campaign | $0 budget, one channel, one asset → invent the move that *needs* scarcity (the constraint becomes the brand's posture, not its excuse). Refuse "we'll do less of the expensive thing"; ask what the limit makes the audience feel that a big spend would flatten. |
| Product / founder-solo | One person, no team, no inventory → the limit becomes the offer. Constraint-as-positioning: what does "made by one person in a week" make possible (intimacy, speed, a story) that a studio output erases? |

## Output Format
```
CONSTRAINT ENGINE — [deliverable]

THE QUESTION / THEME
  [the question the work is answering — so the move serves meaning]

THE CONSTRAINT (flat fact)
  [the actual limit]

THE LAZY DEFAULT (refused)
  [the reasonable-sounding move the limit normally produces]
  What it quietly surrenders: [urgency / surprise / theme's bite / imagination]

WHAT THE LIMIT MAKES POSSIBLE
  - [thing abundance would have flattened or shown too plainly]
  - [the free gift scarcity hands you]
  - [what the audience now has to imagine]

THE INVENTIVE MOVE(S)
  1. [move] — exists ONLY because of the constraint; makes [X] urgent / escapes [Y]
  2. [move] — [why this one is the signature, not the patch]

SIGNATURE CHECK
  Would I make this move if the constraint vanished?  [NO = signature / YES = patch, rebuild]
  Does it serve the theme?  [how the move and the meaning are the same move]
```

## Quality Gate
> **🛡️ Anti-Pattern Check**: review output against `genius.md § Anti-Patterns` and the § Expert-Specific Quality Rubric. Flag and fix any violation before delivering.
- **Default named, not skipped.** Step 1 surfaced the reasonable-sounding lazy response in plain language. If you jumped straight to the clever move, you skipped the refusal and the move is unearned.
- **The move requires the constraint.** The signature check returned NO — the move collapses if the limit vanishes. If it survives unlimited budget, it's a patch; rebuild.
- **Scarcity does the work, not explanation.** The move triggers imagination or urgency (Pattern 7 / Pattern 14), it doesn't apologize for the limit or over-fill to compensate.
- **Theme intact.** The inventive move answers the question rather than betraying it for cleverness — no white-hat-at-noon twist (Anti-Pattern: the satisfying turn that betrays the theme).
- **Machinery invisible.** The output names the constraint and the move; it does not lecture about "constraint-as-innovation" or label patterns by number on the page.

## Common Pitfalls
- **Absorbing the constraint instead of inverting it.** You wrote the limit, then accepted the first survivable response. Recovery: return to Step 2 and force the question "what does this make *possible*?" until you can name something the limit *gives*.
- **Cleverness that betrays the theme.** The move is inventive but it answers a different question than the work is asking. Recovery: re-run Step 4's theme check — if the move and the meaning aren't the same move, cut it.
- **The dressed-up patch.** The move would exist anyway with more money; the constraint is decoration. Recovery: run the signature check honestly — if "would I do this with unlimited budget?" is YES, it's a patch.
- **Inventing a move with no sag to fix.** A timeline jump or location move that solves nothing because the energy was fine. Recovery: only deploy the structural escape where the form actually sags (HK-5 late-middle / third-act); otherwise leave it and let the constraint's urgency carry.
