# Coherence Cut

By season two of a recurring show you wake up with a cast you have to feed. So a romance gets bolted on, a C-story limps along, and the audience asks what this thread is and why they should care. Hawley refuses the obligation: the best thing for the story is to tell a great story, and a returning character who doesn't fit this one gets paused, repositioned, or broomed. This pass does that to your draft — element by element, with the story as the only master in the room.

## Pre-Flight
Read these files before executing:
1. `skills/noah-hawley-storytelling-mastery/genius.md`
2. `skills/noah-hawley-storytelling-mastery/references/genius-patterns.md`

> **🔒 Pre-Flight Gate**: Before executing, run the **Decision Framework** in `genius.md § Decision Framework` — confirm you can answer the question (the theme this work is answering now), the ending (where it lands), and the assumption being taken for granted. You cannot test what serves "the story" until you can name the story.

## Input Required
- The work or plan being cut (script/season, essay, content series, campaign, product roadmap, deck).
- The **question this version is answering** — one sentence, stated as a question (from the Pre-Flight Gate).
- The **ending / destination** — where it lands.
- Any elements you suspect are bloat but feel obligated to keep (and *who* you'd be disappointing by cutting each).
- The constraint behind the bloat, if known: a beloved character, a paid asset, a sequel hook, a stakeholder who "needs to appear."

---

## Workflow

### Step 1: Inventory every element
List every discrete thing the work spends attention on. Not scenes by number — *load-bearing units*: each character, subplot, section, recurring bit, callback, feature, stakeholder cameo, franchise hook. One row per element. Be ruthless about granularity; service creep hides inside things that "obviously belong."

For each, capture what it is and — the diagnostic that matters — *why it's here*. Write the real reason, not the flattering one.

| Element | Type | Why it's actually here (honest) | Whose absence would I be "wasting"? |
|--------|------|--------------------------------|--------------------------------------|
| | character / subplot / section / callback / feature | | (actor, asset, stakeholder, sequel, "we already built it") |

### Step 2: Test each against *this* story
Run one question per element: **does this serve the question this version is answering, or am I servicing it because it exists?** The tell of a failure is the C-story nobody cares about — the thread that's present so an actor isn't idle, so a paid asset gets used, so a callback rewards the loyal, so a feature you already built isn't wasted.

Score each element. Anything below "serves the question" is a candidate for the broom.

| Element | Serves the question? (the theme, the ending) | Or servicing it because it exists? | Verdict candidate |
|--------|----------------------------------------------|-------------------------------------|-------------------|
| | (how, specifically) | (the constraint it's feeding) | serve / fail |

A "great twist," a beloved returning face, an expensive set — none of it earns a pass. Reality rarely ends with white-hat-versus-black-hat in the town square at noon; clever and beloved are not the same as load-bearing.

### Step 3: Decide broom / pause / reposition
Every failing element gets a verdict. There are three exits, not one — the cut isn't always deletion.

- **Broom** — remove it. It services something other than this story and has no future home. Gone.
- **Pause** — pull it now; it belongs to a *later* story, not this one. Hold it for a future edition/season/release where it serves.
- **Reposition** — the element has real weight but is in the wrong place doing the wrong job. Move it so it serves the question instead of the asset.

| Element | Verdict | Rationale (what it was servicing → what changes) | If pause/reposition: where it goes |
|--------|---------|--------------------------------------------------|--------------------------------------|
| | broom / pause / reposition | | |

### Step 4: Verify it isn't a prison of your own creation
Read the surviving spine back. Two checks. First: is the **story the master** — does every remaining element now serve the question, with nothing left in to feed a cast, asset, or franchise? Second: did you over-broom — cut something that genuinely carried the theme because it *looked* like service? Servicing the whole cast is a prison; so is amputating the spine to prove you're disciplined.

State the result as a single coherence sentence: *"With these cuts, the work now answers [the question] and lands at [the ending] without servicing anything that doesn't earn it."* If you can't say that cleanly, a verdict is wrong — revisit it.

## Content Type Adaptations
| Format | Adaptation |
|--------|-----------|
| Screenplay / TV / season | Inventory characters, subplots, returning faces, callbacks. The classic broom: the second-season romance bolted on because two actors are under contract. Pause arcs for a later season; reposition a character into the spine instead of a side-thread. |
| Long-form essay / Substack | Inventory sections, anecdotes, tangents, callbacks to prior editions. Broom the digression that's there to show range. Reposition a buried passage that's actually carrying the thesis. The "completist" instinct is the franchise instinct. |
| Short-form (LinkedIn / X) | Usually one or two elements over the load limit. Broom the extra hook, the second CTA, the credential aside that services *you* not the reader. One question, one landing. |
| Brand / campaign | Inventory channels, assets, sub-messages, partner shout-outs, reused creative. Broom the asset included because it was paid for; broom the message servicing a stakeholder's pet feature. The campaign serves the buyer's question, not the org chart. |
| Product / roadmap | Inventory features, integrations, legacy surfaces. Broom the feature kept only because it's already built. Pause the one that belongs to a later release. Reposition the buried capability that's actually the spine of the value story. |

```

THE STORY (the master):
  Question this version answers: [one sentence, as a question]
  Ending / destination:          [where it lands]

ELEMENT LEDGER
  Element | Type | Verdict | Serves the question OR servicing what? | Rationale | Pause→where / Reposition→where
  --------|------|---------|----------------------------------------|-----------|--------------------------------
  [...one row per element from the inventory...]

BROOMED ([n]):
  - [element] — was servicing [constraint]; removed because [reason]
REPOSITIONED ([n]):
  - [element] — moved from [old job] to [new job serving the question]
PAUSED ([n]):
  - [element] — held for [later story/edition] where it serves

  - [element] — earns its place: serves the question by [how]

COHERENCE SENTENCE:
  "With these cuts, the work now answers [question] and lands at [ending]

OVER-BROOM CHECK: [anything cut that actually carried the theme? if so, restored — note it]
```

## Quality Gate
> **🛡️ Anti-Pattern Check**: review output against `genius.md § Anti-Patterns` and the § Expert-Specific Quality Rubric (especially **Coherence over Service**). Flag and fix any violation before delivering.
- Every "keep" verdict names *how* the element serves the question — not "it's important" or "the audience loves it." Loved ≠ load-bearing.
- No element survives on the rationale "we already built it / paid for it / they'd be wasted otherwise." That sentence is the definition of service creep.
- At least one honest broom or reposition exists. A pass that cuts nothing was a defense of the status quo, not a cut.
- The "why it's actually here" column tells the real reason, not the flattering one. If every row reads as essential, the inventory wasn't honest.
- The over-broom check ran: nothing that genuinely carries the theme was cut just to look disciplined.

## Common Pitfalls
- **Renaming service as theme.** The bloated subplot gets a thematic justification invented after the fact to save it. Recovery: ask whether the theme would survive the element's deletion. If yes, the element was servicing, not serving — broom it.
- **Treating broom as the only verdict.** Real weight in the wrong place gets deleted when it should move. Recovery: before brooming, ask "is this in the wrong job?" (reposition) or "wrong story?" (pause) — deletion is the last exit, not the first.
- **Sparing the expensive or beloved.** The paid asset, the fan-favorite, the clever twist get a pass on sentiment or sunk cost. Recovery: cost and affection don't appear in the test; only "serves the question" does. Run the same test on the darling.
- **Over-brooming to perform discipline.** Cutting a load-bearing element because it superficially resembles service. Recovery: the over-broom check in Step 4 — restore anything whose removal weakens the question the work answers.
