# April Dunford to Jeremy Haynes Handshake: Positioning to Cold-Offer Composition

Sequential stack. Dunford's finished positioning canvas is the input; Haynes' offer-composition engine reads it and builds a temperature-staged stack. Upstream to downstream, not a merge.

## Stacking Partners
- **April Dunford** (host, upstream). Supplies the finished positioning canvas: Competitive Alternatives, Differentiated/Unique Attributes, Value Themes, Target Segment, Market Category.
- **Jeremy Haynes** (downstream). Re-composes that canvas into an offer staged by audience temperature (in-market / needs-convinced / mass-market, mapped here to hot inbound / warm engaged / cold outbound). Driven by the objection-mining loop and the core-vs-edition split.

## When to Use
- Positioning is done. The 5 components exist, even embedded in prose inside a master offer doc, not necessarily a labeled worksheet.
- The same pitch (same headline, same price, same opening line) is firing at cold strangers, warm commenters, and hot inbound leads alike.
- Cold LinkedIn outbound is flat or freezing prospects while warm/inbound converts fine. That's an audience-state problem wearing an "offer isn't working" costume.
- Before scaling outbound volume: recompose the stack per temperature first. Adding DMs to a misaligned pitch just freezes more strangers, faster.

## Pre-Flight Gate
| Question | If NO -> |
|---|---|
| Does finished Dunford positioning exist (5 components, even if embedded prose)? | Run `product-positioning-blueprint` or `dunford-positioning-diagnostic` first |
| Is the ICP's umbrella narrative (problems/circumstances/desired outcomes) field-grounded? | Run `jh-umbrella-narrative` first. Never pull it from assumption. |
| Is audience temperature currently undifferentiated (one pitch, all readers)? | If already staged and just drifting colder, use `jh-temp-migrate` instead. This handshake is for the first staging, not re-migration. |

## The Handoff Contract (Positioning Component to Offer Element)

| Dunford Component | Haynes Offer Element | Mechanism |
|---|---|---|
| Competitive Alternatives | Objection-mining seed list | What the buyer already tried and got burned by is the alternatives map. Feed it into the pie chart before running new mining from scratch. |
| Differentiated / Unique Attributes | Mechanism claims (core stack components) | Each unique attribute traces 1:1 to a stack component. Haynes' "not random" test applies to positioning-derived components exactly like field-derived ones. |
| Value Themes | Pilot promise, the bridge between the two cliffs | Value themes are the desired-outcome cliff. Competitive alternatives' failure modes supply the problem cliff. The offer is the bridge, and cold readers only care about it once both cliffs are named. |
| Target Segment | ICP umbrella narrative frame | Segment definition supplies who, but still needs Haynes' problems/circumstances/desired-outcomes decomposition. A segment alone is a demographic, not a narrative. |
| Market Category | Category frame for cold legibility | Determines what a cold stranger assumes on sight. Must be reinforced or corrected in the opening line of the cold-tier offer, or the 30-second cold-read test fails. |

## Fused Sequence

1. **Extract the Canvas.** Pull Dunford's 5 components from the finished positioning artifact, plain language, no worksheet fields.
2. **Classify Temperature Tiers.** Map the go-to-market's real audience states onto Haynes' 3. Cold outbound: unaware-to-needs-convinced strangers, zero prior exposure. Warm engaged: needs-convinced-with-context, has seen 1+ content pillar or replied/commented. Hot inbound: in-market, reached out unprompted with a dated occasion in hand.
3. **Derive Narrative Per Tier.** Run problems/circumstances/desired-outcomes through the same positioning canvas for each tier, but let Competitive Alternatives supply harsher problem-cliff language the colder the tier. A stranger has more status-quo comfort to dislodge than a hot inbound lead who is already past that stage.
4. **Compose Tier-Specific Stacks.** Cold gets a low-friction bridge component only, never the priced core offer. Warm gets the core offer plus one or two objection-answering components surfaced from the alternatives list. Hot gets the full stack, editions on the table, pricing anchored.
5. **Objection-Mine Per Tier.** Run the pie chart separately per temperature. A cold-tier objection ("who is this, why are you in my inbox") is categorically different from a hot-tier objection ("is the price worth it"). Never average them into one FAQ.
6. **Migration Path.** Name the single content or interaction event that re-classifies a lead from cold to warm to hot, so the pipeline isn't guessing at temperature by feel.

## What This Replaces
Pitching the finished positioning statement as one universal sales asset. That "set it once, fire it at every reader" move is an anti-pattern both experts reject on their own terms. Dunford treats positioning as context-setting, not a messaging template stamped on every audience. Haynes treats warm-validated offers as non-transferable evidence for cold traffic, and the reverse mismatch (a cold offer built for hot readers) freezes cold leads harder than no offer at all.

## Output Contract
- Positioning extract: the 5 components in plain language, sourced from the finished canvas.
- Three temperature-tier narrative maps (problems / circumstances / desired outcomes per tier).
- Three tier-specific offer stacks (component list, core-vs-edition split, the specific ask at each tier).
- Objection pie chart per tier.
- Migration triggers (cold to warm to hot).

## Quality Gate
- [ ] Every stack component traces to BOTH a Dunford component and a Haynes narrative element. Double traceability, not "not random" applied once.
- [ ] Cold tier never leads with the priced core offer.
- [ ] Positioning fidelity: no tier's pitch claims more than the Value Themes actually support.
- [ ] 30-second cold-read test passes specifically for the cold-tier bridge component.
- [ ] Migration triggers are named events, not vibes.
