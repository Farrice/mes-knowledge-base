# Client Rolodex → Framework Engine

Omar sat with the camera and made the fear small. "If you're breathing, you should never run out of content." Then he handed over the move that ends the panic for good: "I want you to open up AI and I want you to start listing out every single client you had... what situation they were in, what they did, and then what happened. So I want you to create a rolodex of client success." The point was never to brag about results. It was to find the recurring thread hiding across all of them, because "you have a framework in there." Most experts never look — they go scavenging for someone else's content angle while their own uncopyable IP sits in their client list, undrawn and unnamed.

This workflow runs that excavation and finishes the job: it surfaces the thread, mines the alphabet for more, then NAMES and DRAWS the one framework worth shipping. Out the other end you get a coined, visual model plus the rolodex table that produced it — content "no one can copy" because it's content "only you can make."

Read these files before executing:

> 🔒 Pre-Flight Gate: This engine needs RAW MATERIAL, not aspiration. The creator must have actually served people — clients, students, free-help cases, even their past self. If there is zero lived practice to mine, stop: there is no moat yet, only theory. Theory produces frameworks anyone could draw. Send them to do the work first, or mine their OWN transformation as the single "client."

## Input Required
- The creator's expertise domain in one phrase ("short-form video editing," "first-time homebuyer financing")
- A client list — names/initials OK, 5–20 cases (more = stronger thread). If memory is thin, reconstruct from invoices, DMs, calendar, testimonials
- For each case (best available): the SITUATION they came in with, what they DID, what HAPPENED
- The intended deployment surface (which platform/container the framework will headline) — sets the draw style

## Workflow

### Step 1: Build the Client Rolodex (the excavation)
Open a doc or AI and list every client. One row each — Omar's exact three columns plus the odds-line that makes the thread visible:

| Client | Situation (what they came in with) | What they did (the intervention YOU ran) | What happened (the result) | "You defied the odds because ___" |
|---|---|---|---|---|
| (initials) | | | | |

Discipline: fill the WHAT-THEY-DID column with the move YOU made them run, not generic effort. The last column is the unlock — for each case, complete "you defied the odds because ___." That sentence forces the latent mechanism to the surface. Produces: a populated rolodex of 5–20 rows.

### Step 2: Find the Recurring Thread
Read down the "what they did" and "defied the odds" columns. The thread is the move you ran with EVERYONE, even when the situations looked unrelated. Name it as a raw sentence first, ugly is fine: "I always made them ___ before ___." If two or three threads compete, pick the one that appears in the most rows AND that you could defend as the actual cause of the result. Produces: one stated thread (the framework-in-the-rough).

### Step 3: Mine the Alphabet (Myron Golden's drill — expand the supply)
The single-thread risk is a one-trick brand. Run Myron Golden's $110K gem (UNCONFIRMED, Omar's account): "for every letter of the alphabet, create frameworks and formulas for your expertise." Draft three per letter where you can — three A's, three B's, three C's — as candidate framework seeds, sub-steps, or principle-names inside your domain. This is generative, not perfectionist; most get discarded. It does two jobs: stress-tests whether the Step 2 thread is the strongest one available, and stockpiles named pieces for future content. Produces: a raw alphabet bank (aim 15–40 candidate fragments).

### Step 4: Extract the Framework from the Thread
Take the winning thread and structure it into 3–7 discrete steps or components — the journey a person actually travels from their starting situation to the result. Each step must be doable, not theoretical. Apply the genius.md Principle-not-Theory test now: does it hold for MORE than one person? If it only fits one client's quirk, it's a story, not a framework — return to Step 2. Produces: the bare 3–7-part structure.

### Step 5: NAME It (so people feel smart)
A name is an obsession signal: coining a term communicates "you've thought about this more than the person you're teaching" (Pattern 7). Run all four levers, pick the one that survives the one-hearing test:
- **Alliteration** — same starting letter ("Crispy Content Checklist")
- **Matching suffixes** — rhythm across the steps (-tion, -ment, -ity)
- **Acronym** — if the steps spell something sticky (Omar's editing model "ALVS" — Audio, Lighting, Video, Shot)
- **AI-assist** — "give me a P word that means consistent" → swap a flat step-name for a charged one

Test: can someone hear it once and repeat it tomorrow? If not, it's a label, not a name. Produces: one framework name + named steps.

### Step 6: DRAW It (give the brain its picture)
"Our brains are always looking for a picture." A drawn framework signals "I've thought about this before you have" (Pattern 7). Pick the shape that matches the structure — never default to numbered circles out of habit:

| Shape | Use when the framework is... |
|---|---|
| Before → After (sad face → arrow → happy face) | A transformation with a clear start/end state |
| Numbered steps (boxes/circles) | A linear sequence run in order |
| Pyramid / triangle | A foundation-up hierarchy or priority stack |
| Loop / cycle | A repeating engine (flywheel, retention) |
| Ladder / staircase | An ascension or skill-progression |
| 2×2 quadrant | A positioning or sort along two axes |

Produces: a described (or sketched) visual of the named framework.

### Step 7: Validate & Deploy
Run the gate, then place it. The framework must teach in <5 min, cover the full journey (situation → result), and read as principle (multi-person) not theory. Then deploy as a teach, not a brag — one element per short post, the full model in the paid container, the name in the bio ("Creator of the ___"). Calibrate disclosure by context (Pattern 8): give the WHAT of the framework generously in free/transient formats; the HOW-to-run-each-step lives in the paid room. Produces: validation checklist + a 3-surface deployment plan.

## Quality Gate
> 🛡️ Anti-Pattern Check: review against `genius.md § Expert-Specific Quality Rubric` before delivering — target Obsession Signaling 9+, Receptive-Soil Realism, WHAT-not-HOW Discipline.
- The framework was MINED from real lived cases (rolodex populated), not invented from desired positioning — that's the moat (Pattern 11).
- ONE framework shipped, not five. Omar runs multiple frameworks across a brand, but this engine produces and validates one at a time — no buffet.
- The name passes the one-hearing test and reads as obsession, not jargon (Pattern 7).
- The draw fits the structure (transformation → before/after; sequence → steps; engine → loop) — not numbered circles by reflex.
- Principle-not-Theory holds: the framework applies to more than one person.
- Deployment calibrates disclosure by context — WHAT free, HOW in the paid container (Pattern 8). No gatekeeping anxiety.
- Any self-reported numbers (the $110K to Myron Golden, Omar's revenue) carry the UNCONFIRMED label.

## Common Pitfalls
- **Empty rolodex, invented framework.** A creator with no client history drafts a slick model from aspiration — anyone could draw it, zero moat. Recovery: gate first; mine their OWN transformation as the single client, or send them to do the work.
- **Threads that are stories, not principles.** The "thread" only fits one memorable client. Recovery: re-run Step 2 across the full column; keep only the move that recurs AND plausibly caused the result.
- **Naming before extracting.** Falling in love with a clever acronym, then bending the steps to fit it. Recovery: lock the 3–7 real steps (Step 4) BEFORE naming (Step 5); the name serves the structure, never the reverse.
- **Shipping the whole framework on a transient feed.** Dumping all five steps into one reel — the fire hose. Recovery: one element per short-form post; reserve the full walk for the committed container.
- **Framework hoarding.** Running the alphabet drill and trying to launch ten frameworks at once. Recovery: the bank is a reserve; deploy one, prove it, then return for the next.
