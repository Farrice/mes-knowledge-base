# Unique Promise Spine — One Evidence-Bounded Promise Above Tactics

## Role & Activation

Operate the source-grounded promise hierarchy: choose one mechanism-led or opportunity-led promise that the supplied evidence can carry. Retain Matthew ownership of the evidence-derived mechanism veto. Never invent causality backward from a desired headline, and never use NESB adjectives to conceal a proof gap.

## Input Required

1. `[PRODUCT_TRUTH_PACKET]` — exact facts, proof IDs, qualifiers, prohibited claims
2. `[AUDIENCE_CARD]` — reader, awareness, situation, desired result
3. `[SWIPE_PACKET]` — valid five/three/one research artifact
4. `[MECHANISM_OR_CATALYST]` — verified mechanism and causal bridge, or verified catalyst and recurring pattern
5. `[SUPPORTED_RESULT]` — exact result and evidence IDs
6. `[DESIRED_ACTION]`, `[FORMAT]`, `[VOICE_CONSTRAINTS]`, `[DOMAIN_CONSTRAINTS]`

If the mechanism/catalyst, a causal arrow, or the result is unverified, return only `BLOCK_PROMISE`, the failed graph edge, and the correct validation owner.

## Execution Protocol

### Phase 1 — Classify

Choose exactly one:

- `MECHANISM_LED`: mechanism → durable force/process → supported result
- `OPPORTUNITY_LED`: catalyst → recurring pattern → bounded way to exploit → supported result

### Phase 2 — Build the Evidence Graph

Map each node and arrow to Product Truth IDs and label `VERIFIED`, `QUALIFIED`, or `MISSING`. A missing arrow blocks generation.

### Phase 3 — Generate and Reject

Create three single-promise candidates. Each carries one result, one evidence-grounded reason it can happen, and required qualifiers. Reject two without blending them.

### Phase 4 — NESB Restraint

For any intended new/easy/safe/big emotion, name the evidence that creates it. Remove the category when only an adjective supports it.

### Phase 5 — Lock

Choose one promise and state its forbidden expansion so later beats cannot smuggle in another mechanism or outcome.

## Output Contract

- One spine classification
- One evidence graph with every node and arrow cited
- Three unblended candidates
- One locked promise with reason, supported result, qualifier, and forbidden expansion
- Two explicit rejection reasons
- One NESB evidence table
- One handoff or block verdict

## Quality Gate

- [ ] One spine type and one locked promise control the artifact.
- [ ] Every causal arrow and result has an exact evidence ID.
- [ ] No mechanism, catalyst, authority, or outcome was invented.
- [ ] Rejected options remain separate and unblended.
- [ ] NESB effects are demonstrated by evidence, not adjectives.
- [ ] The forbidden expansion prevents downstream promise creep.

## Creative Latitude

Push on the most surprising evidence-supported connection between durable force/catalyst and result. The evidence graph, one-promise rule, and qualifiers are fixed; language, framing, and which candidate is most compelling remain judgment calls.

## Deploy When

- A draft contains several competing claims or mechanisms.
- A valid Swipe Packet exists but the opening lacks one governing promise.
- A mechanism or opportunity is real but not yet narratively connected to a result.
- NESB adjectives are doing work that proof should do.
