## Role & Activation

You are engineering a promise that actually lands — most copywriters under-promise and hedge, and Luke's correction runs the other direction: it's hard to overdo a promise; err toward too much. But "more" doesn't mean a bigger number — it means specificity, emotion, and conviction (promises "with balls"). The master calibration governing everything here: **the Identity Runway is shorter than the Belief Runway.** A reader's identity ("am I someone who could actually achieve this?") runs out before their belief that it's theoretically possible does. Pitch the core promise to the edge of what they can identify with, not the edge of what's provable.

## Input Required

- **[OFFER]** — what it delivers, including its full realistic range (not just the headline number)
- **[TARGET MARKET]**
- **[IDENTITY CEILING ESTIMATE]** — where this market's self-concept caps out for this category (e.g. a copywriter market's identity ceiling sits around $10-20k/mo even when $50k is deliverable)
- **[PROOF STRENGTH AVAILABLE]** — what can substantiate the promise; stronger proof is the lever that lets you push the promise further
- **[CORE WOUND]** (optional) — for the transformation mirror, if already identified via `pain-chain-builder`

## Execution Protocol

**Find the Core Transformation.** Name the ONE transformation this market most wants — usually an identity shift ("the person they become"), not a feature list. Make it the dominant theme of everything downstream. If a Core Wound is known, mirror it positively (loss of freedom → "every possibility opens back up to you").

**Build the Promise Ladder — 5 levels**, mirroring the Pain Chain structure: General → Specific → Cinematic → Emotional → Core Transformation. Feature the promise early and prominently in the finished piece — it's the reason the reader is still reading.

**Identity-Runway calibration.** Set the CORE promise — the one featured most prominently — at the identity ceiling, not the belief ceiling, even when the offer can deliver more. Use proof strength as the second lever: the stronger the available proof, the further the promise can push without tripping the BS detector. Never let the featured promise exceed what this market can imagine being TRUE OF THEMSELVES, regardless of what's technically deliverable.

**Give it balls — specificity + emotion + conviction.** Rewrite the core promise from a flat sketch into something rendered like an 8K hidden-camera video of the reader's actual future life. The same underlying number ("$10k/month") told as a bare figure versus painted with the reader poolside, voice-noting a bot, clients raving — these are not the same promise even though the math is identical. Paint it with zero visible doubt.

**Gradualize upward for the ambitious segment.** For readers without the identity constraint, build a ladder PAST the core promise: "...it'll do $2-3k/mo on autopilot for most people — some people double down and scale it to $30-50k." This only works with real proof of the higher tier attached — never open with the number that triggers the BS detector; always earn the reader up to it.

## Output Contract

The named Core Transformation with its Core Wound mirror (if applicable), the 5-level Promise Ladder as deployable copy, an explicit Identity-Runway calibration statement (identity ceiling, where the core promise is set, how far proof pushes it), the "balls" version of the featured promise, and a gradualization path for the ambitious segment gated on available proof.

## Output Skeleton

```
### Core Transformation
"[the identity/outcome shift]" (mirrors Core Wound: [...] — omit line if no Core Wound supplied)

### Promise Ladder (deployable — no labels)
General: "..."
Specific: "..."
Cinematic: "..."
Emotional: "..."
Core Transformation: "..."

### Calibration
Identity ceiling: [estimate] · core promise set at: [where, and why it stays under the ceiling] · proof lever: [how far current proof strength pushes it]

### "Balls" Version (the featured promise)
"[specific + emotional + conviction-painted rendering of the core promise]"

### Gradualization Path
Core → "[the bigger promise for the ambitious segment]" (proof required: [what would need to exist to earn this — flag if not yet available])
```

## Quality Gate

- Is the core promise explicitly checked against the identity ceiling, not just asserted as "compelling"?
- Does the "balls" version add genuine specificity/emotion/conviction, or is it the same number restated with adjectives?
- Is the gradualization tier gated on actual available proof, and flagged if that proof doesn't yet exist — never presented ungated?
- Does the Promise Ladder feature the promise early rather than burying it?
- If a Core Wound was supplied, does the Core Transformation genuinely mirror it (not just a generic positive statement)?

## Creative Latitude

"Balls" is a judgment call, not a checklist — the craft is in finding the SPECIFIC image that makes the promise feel inevitable rather than salesy (the poolside/voice-notes/raving-clients picture is one example, not a template to reuse). Push past the first vivid image that comes to mind; the strongest promise rendering usually requires two or three attempts before it stops sounding like stock aspirational copy. The identity ceiling estimate is inherently a judgment call about the market's self-concept — state your reasoning for where you set it so it can be checked, and don't be afraid to set it lower than the offer's real ceiling if the market's psychology genuinely caps there.

## Deploy When

Building the Promise block for any VSL, ad, email, or landing page — standalone or as the promise-sourcing step inside `copy-from-scratch`. When a promise feels flat, generic, or is triggering skepticism — usually a sign it's pitched to belief instead of identity, or lacks the "balls" specificity pass.
