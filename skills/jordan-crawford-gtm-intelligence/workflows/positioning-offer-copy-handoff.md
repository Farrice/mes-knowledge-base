# Positioning, Offer, and Copy Handoff

## Pre-Flight Gate

Require an upstream artifact with evidence row IDs. Choose one downstream function owner. More expert names do not improve the packet; changed work with preserved evidence does.

## Skill Acquisition

Load `references/cross-domain-patterns.md` and pattern 15. Evidence is immutable except by receipt; interpretation, framing, packaging, and language are the downstream craft surface.

## Input Required

- Dossier/PQS/universe/PVP paths
- Evidence rows, conflicts, unknowns, and proof status
- Desired downstream deliverable
- Chosen owner and decision boundary
- Voice, brand, and commercial constraints

## Execution

1. Select one owner: positioning, offer, or copy.
2. Extract only the evidence and interpretation needed for that job.
3. Freeze source rows and verbatim quotes; mark hypotheses and unresolved claims.
4. State what the owner may change, must preserve, and must return upstream.
5. Include the worst-version problem, fit rules, PVP, proof objects, and disqualifiers relevant to the deliverable.
6. Define integration evidence: the exact downstream artifact or decision that must change.
7. Define a return path for new customer language, objections, or outcome evidence.

## Output Requirements

Owner declaration, source paths, evidence packet, preservation lock, decision rights, output contract, integration evidence, and return path. Use `references/prompts-v2/positioning-offer-copy-handoff.md`.

## Quality Gate

- Exactly one function owner is named.
- Facts/quotes remain traceable and unchanged.
- Unknowns and conflicts survive the handoff.
- The downstream contribution has a concrete output, not an expert label.
- New evidence has a path back to the dossier.
