# Congruence Supply Chain

Use this when public content, newsletter, and paid offer feel like separate businesses or attention is not moving toward a commercial decision.

## Input Required

- Named buyer and problem
- Existing public content or library units
- Owned email/newsletter state
- Current paid offer, if any
- Proof, permissions, and observed drop-off

## Protocol

1. Write one problem-spine sentence: `[buyer] struggles with [costly problem] because [mechanism], and wants [outcome]`.
2. Map three depths of the same spine:
   - public proof or useful insight,
   - owned recurring explanation or asset,
   - paid implementation, information, advice, or done-for-you result.
3. Compare promise, vocabulary, mechanism, proof, and next action across all stages.
4. Remove category changes and redundant editorial calendars.
5. Choose the smallest missing bridge. Do not force a newsletter if direct buyer contact is the faster valid path.
6. Send format decisions to `nicolas-cole-library-first-writing`, newsletter architecture to `nicolas-cole-newsletter-flywheel`, and offer design to the fitting product/service owner.

## Output Contract

Produce the problem spine, a three-stage congruence map, mismatch diagnosis, one repaired path, required assets, permission gates, and the exact next handoff.

## Quality Gate

- Same buyer and problem across all stages
- Each stage adds depth or access rather than switching topics
- Owned audience is a means, not a vanity metric
- Paid offer contains a concrete result or deliverable
- No publication or outreach without approval
- No performance claim without receipts
