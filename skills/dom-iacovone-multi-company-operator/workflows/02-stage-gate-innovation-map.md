# Workflow 02: Stage-Gate Innovation Map

Use this before launching a product, SKU, offer, feature, or command surface.

## Inputs

- Product or offer idea.
- Target customer and channel.
- Margin or economic target.
- Differentiation claim.
- Buyer, partner, or customer request if relevant.

## Gates

1. Strategic sense: why should this exist now?
2. Category improvement: what does it do better than the existing option?
3. Margin creation: can the economics support growth?
4. Channel fit: does the intended channel have the right buyer and execution logic?
5. Brand/objective fit: does it strengthen or dilute the core?

## Decision

Return one of:

- Go.
- Revise.
- Park.
- Kill.

Include the evidence, the weakest gate, and the next proof needed.

## Output Schema

- Decision: exactly one of Go / Revise / Park / Kill.
- Evidence: what supports the decision, per gate, in one line each.
- Weakest gate: the single gate (1-5) that is least supported, named explicitly.
- Next proof needed: the specific, checkable data point that would move the weakest gate.
- Buyer/partner/customer request status: how the request was weighed against gate 5 (brand/objective fit), if one was present.

## Quality Gate

- Is the decision exactly one of Go / Revise / Park / Kill — never a hedge like "maybe" or "let's see"?
- Is the weakest gate named explicitly by number and name, not implied?
- If a buyer, partner, or customer request drove the idea, is it treated as input evidence rather than an automatic override of gate 5?
- Is "next proof needed" a specific, checkable data point, not "more research" or "more data"?
- Does the output avoid launching on novelty or competitor pressure alone, without a stated margin or differentiation basis?
