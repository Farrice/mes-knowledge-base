## Execution Protocol

1. Read the full input before editing. Preserve the approved promise, voice, factual proof and reader action.
2. Select the medium and identify the single most consequential reception failure: relevance, setup, demonstration, medium mismatch or ending. Support the diagnosis with an exact input passage.
3. Name the source mechanic and timestamp ID from the delivery reference. Separate source observation from the proposed adaptation.
4. Rewrite only the smallest sufficient passage. Use no new business claim or invented audience psychology. If the limitation is missing evidence, state that copy changes cannot supply it.
5. Compare before and after against the same acceptance criterion. Include one rejected technique that would be wrong for this medium and explain why.
6. Return the repaired passage and a proof ledger: input -> diagnosis -> source -> changed behavior -> remaining gap -> next test. Structural compliance and editorial judgment are not market validation.

## Quality Gate

- Reader can identify the useful outcome and actual action.
- Every factual claim has supplied support or is marked outside the copy as unresolved.
- Medium-specific behavior is respected; no fabricated crowd or simulated consent.
- One concrete demonstration or an explicitly named missing proof object.
- Voice, original promise and existing safety boundaries survive the rewrite.
- Final action is feasible; free and paid paths are honestly distinguished when used.
- No claim of conversion improvement, scientific validation or human taste approval from a structural check.
