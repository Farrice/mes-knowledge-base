## Execution Protocol

1. Lock the real audience context, time available, offer terms, supported proof, current objections and desired voluntary action. When evidence is missing do not infer fear from silence.
2. Open with relevance and a transparent teaching/offer frame (D01/D12). Select a small, supported promise. Do not invent pricing, guarantees, scarcity or credentials.
3. Build one teaching module around setup -> visible demonstration -> useful application (D04/D09). Reuse the existing point architecture for longer teaching; do not impose a four-point grid on a short close.
4. Design evidence-seeking interaction (D02/D15). Include explicit branches for a specific question, confusion, no response, refusal and time running short. A no ends that invitation; do not exhaust objections or reinterpret refusal as consent.
5. Reconnect offer components to earlier demonstrated needs (D07). Use D06 to clarify what varies by situation. Include a genuine self-directed alternative.
6. Supply one disruption-recovery line (D14) and a complete main ending (D17). Optional encore gets its own time bound and ending. Never invent spontaneous applause or a callback to an event that did not happen.
7. Produce the actual lines and cue-card outline. Callbacks, humor and profanity are optional and must fit the user's register. End with a clear choice and next step.
