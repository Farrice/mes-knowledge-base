# Workflow 02: Ship It Protocol

> **Prerequisite**: Load [genius.md](../genius.md) before running this workflow.
> **Uses**: Patterns 6, 7, 8, 9, 11 + Tacit Knowledge 3, 6

## When to Use
- You have something that's 80%+ done but keep polishing
- You're debating whether something is "ready"
- You've been "almost done" for more than a week
- You feel like you need "one more pass" before releasing

## Produces
1. Spec Definition (what "done" actually means)
2. Quality Classification (meets-spec vs luxury vs perfectionism)
3. Perfectionism Diagnosis (hiding or genuine quality pursuit?)
4. Shipping Decision (go/no-go with specific rationale)
5. Post-Ship Protocol (what to do after releasing)

---

> **🔒 Pre-Flight Gate**: Before executing, run the **Decision Framework** in `genius.md` § Decision Framework. Confirm all diagnostic questions are answered.


## Phase 1: Define the Spec

### Step 1: Name What You're Shipping
State it plainly:
- What is the deliverable? (article, product, email, course, feature, launch)
- Who is it for? (Pattern 7 — by name if possible)
- What is it for? (What specific change does it create for that person?)

### Step 2: Write the Spec
The spec is the standard the work needs to meet. NOT "the best it could possibly be." The spec is the line between "this serves the audience" and "this doesn't."

Define:
```
SPEC DEFINITION
═══════════════
Deliverable: [What you're shipping]
Must contain: [Non-negotiable elements — list 3-7]
Must NOT contain: [Things that would actively harm quality]
Audience expectation: [What does the recipient need this to DO for them?]
Time-boxed at: [Maximum additional hours before forced ship]
```

**Critical Reframe**: The spec is not a ceiling — it's a floor. Meet the floor. Ship.

### Step 3: Classify Current State
Where is the work right now against the spec?

| Element | Spec Requirement | Current State | Status |
|---------|-----------------|---------------|--------|
| [Element 1] | [What's required] | [Where it is] | ✅ Met / 🔧 Close / ❌ Missing |
| [Element 2] | | | |
| [Element 3] | | | |

## Phase 2: Diagnose the Stall

### Step 4: Quality Type Classification (Pattern 8)
Three types of quality exist. Only one matters for shipping:

| Quality Type | Description | Example | Decision |
|-------------|-------------|---------|----------|
| **Meets-Spec** | Attainable standard that serves the audience | "The article makes the core point clearly" | ✅ Ship when met |
| **Luxury** | Nice-to-have above spec, doesn't change function | "What if I added custom illustrations?" | ⚠️ Only after shipping V1 |
| **Zero-Defect Pursuit** | Perfectionism masked as quality | "I need it to be absolutely perfect" | 🛑 This is hiding |

What type of quality are you currently pursuing? Be honest.

### Step 5: Perfectionism Diagnosis
Answer each question honestly:

1. If you shipped it right now, would it genuinely harm the audience? (Not embarrass you — HARM THEM)
2. Is the "one more pass" driven by serving the reader or by protecting your ego?
3. If your name weren't on it, would you still insist on the changes you're contemplating?
4. Have you already made changes that your audience would never notice?
5. Complete this sentence: "If I ship it now, I'm afraid that ________"

**Scoring**:
- If #1 = No → You're hiding. Ship it.
- If #2 = Protecting ego → You're hiding. Ship it.
- If #3 = No → You're hiding. Ship it.
- If #4 = Yes → You're past spec. Ship it.
- If #5 = anything other than "the audience will be harmed" → You're hiding. Ship it.

### Step 6: The "Merely" Gate
Seth Godin's phrase is "merely ship it." The word "merely" is doing heavy lifting. It means:
- The shipping is not the heroic act
- The making was the heroic act
- Shipping is the minimum courtesy to the work you already did
- NOT shipping is disrespectful to your own labor

Can you MERELY ship it? Not dramatically. Not with fanfare. Just... put it out there?

## Phase 3: Make the Decision

### Step 7: Shipping Decision Matrix

| Condition | Decision |
|-----------|----------|
| Spec met + perfectionism diagnosed | **SHIP NOW** |
| Spec nearly met (1-2 elements at 🔧) | **2-hour time-box to close gaps, then SHIP** |
| Spec not met (multiple ❌) | **Complete spec elements only, ignore luxury, then SHIP** |
| Genuine quality gap that would harm audience | **Fix the specific gap (name it), then SHIP** |

### Step 8: Consistency Check (Pattern 9)
Before shipping, ask: "If I were playing the role of the best version of me — the one who does this professionally — would this version ship it?"

The best version of you ships consistently. Not perfectly. Consistently.

---

## Phase 4: Post-Ship Protocol

### Step 9: Plant the Seed (Tacit Knowledge 3)
It's out. Now:
- **Don't hover**. Don't check metrics for 24 hours.
- **Tell 3 people**. "Here, I made this." That's it. No preamble, no caveats, no "it's not perfect but..."
- **Start the next thing**. The best antidote to post-ship anxiety is pre-ship momentum on the next project.

### Step 10: Become What You Did (Pattern 13)
You just shipped. That makes you a shipper. Write down:
"I shipped [thing] on [date]. I am now someone who ships."

Identity follows action. You didn't wait to "become" a creator. You created, and now you are one.
