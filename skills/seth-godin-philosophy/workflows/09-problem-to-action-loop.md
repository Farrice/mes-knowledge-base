# Workflow 09: Problem-to-Action Loop

> **Prerequisite**: Load [genius.md](../genius.md) before running this workflow.
> **Uses**: Patterns 3, 4, 7, 13, 27, 30-35 plus Tacit Knowledge 2 and 8
> **Source**: BigDeal × Seth Godin interview, 2026-08-12; timestamped evidence in `extractions/video-context/o8yD6nt71Cs/`

## When to Use

- The user says “I’m stuck,” but the block mixes fear, old commitments, metrics, identity, and tradeoffs.
- Several symptoms keep returning after isolated fixes.
- The operator knows the advice but is not converting it into a decision or experiment.
- A project needs a useful feedback loop and repeatable cadence after the first move.

Do not use this for a clean quit-versus-persist decision; route that to `seth-godin-marketing-mind/workflows/09-quit-or-dip.md`. Do not use it for positioning once the problem is already clear; route that to `03-strategic-clarity-engine.md`.

## Input Required

- **[STUCK_STATEMENT]**: The problem in the operator's exact words. Preserve the “but,” status language, and metric anxiety; they are evidence.
- **[STAKES]**: What changes if the problem persists for 30 days.
- **[CONSTRAINTS]**: Fixed conditions, chosen commitments, and assumed constraints.
- **[ATTEMPTED_FIXES]**: What has already been tried and what returned.
- **[FEARED_DOWNSIDE]**: Financial, social, time, identity, and relationship risks as the operator currently feels them.
- **[PEOPLE_AFFECTED]**: Who cares, who controls the yes, and who is merely watching.
- **[CURRENT_MEASURES]**: Numbers, reactions, or signals currently used to judge progress.

## Execution Protocol

### Phase 1: Classify Before Solving

1. Preserve `[STUCK_STATEMENT]` verbatim.
2. Break it into discrete obstacles. Classify each as:
   - **Problem**: a solution exists, including one the operator dislikes.
   - **Situation**: unchangeable in the relevant horizon.
   - **Chosen constraint**: changeable but deliberately protected because it buys a wanted life.
3. Problems receive action. Situations receive acceptance. Chosen constraints receive a named cost and benefit. Never mix the three.

### Phase 2: Find the Root Post

4. Ask: what single assumption, incentive, old commitment, status demand, or identity requirement organizes at least two symptoms?
5. Run the entanglement truth test: state it in plain language without euphemism. If it sounds absurd, defensive, or inherited when spoken plainly, keep it visible.
6. Identify the primary protective posture:
   - **Deniability**: no ownership if the work remains generic or hidden.
   - **Helplessness**: no action if the system is treated as fate.
   - **Contempt**: no care if the audience or work is dismissed.
   - **Fear**: no exposure if the consequence remains vague.

### Phase 3: Expose the Tradeoff

7. Replace the load-bearing “but” with “and.” Hold both truths.
8. Name the cost attached to the chosen path. Do not promise the operator both incompatible prizes.
9. Write the purpose exchange: “For the next `[PERIOD]`, I am trading `[TIME/RISK]` to create `[CHANGE]` for `[PEOPLE]`.”

### Phase 4: Calibrate Actual Risk

10. Put on the pessimist hat first. For each feared downside, record:
    - maximum financial loss
    - maximum time loss
    - who would know if it failed
    - whether the loss is reversible
    - what would put the operator out of the game
11. Redesign until the test stays inside the non-fatal boundary.
12. Put on the optimist hat second. State what becomes possible if the test works and what will be learned if it does not.

### Phase 5: Design the Smallest Useful Experiment

13. Choose the smallest generous act that can still change a named decision. “Easy but informationally empty” fails.
14. Name the smallest viable audience and the people who are not relevant to this test.
15. Make failure appropriately quiet: expose the test only as widely as the signal requires.
16. Set a date, owner, downside cap, decision it informs, and stop rule.

### Phase 6: Audit the Feedback Loop

17. For every current measure ask:
    - Who made this easy to see?
    - Who benefits when it rises?
    - What real behavior is it supposed to represent?
18. Keep only qualified feedback: observed behavior from the intended audience, a decision-maker response, a purchase/deposit, completion, or another signal tied directly to the change sought.
19. Structurally exclude spectator feedback that cannot change the named decision.

### Phase 7: Turn the Move Into Craft

20. If the test reveals a useful behavior, convert it into one four-week decision-once habit:
    - cadence
    - minimum spec
    - review date
    - maximum permitted misses
21. Define the stop/quit rule before the expected hard part arrives. This is not a forever vow.
22. State the identity earned only after the repeated action begins.

### Phase 8: Route the Next Owner

23. If the memo reveals a clean quit-versus-dip question, hand off to `/gmind-quit-or-dip` with the classification and sunk-cost facts.
24. If it reveals an audience/positioning problem, hand off to `/strategic-clarity` with the SVA and change statement.
25. If it reveals a broken premise or fuzzy category, hand off to `/godin-lens` with the verbatim question and root post.
26. Otherwise, the experiment is the next action. Do not add another framework.

## Output Contract

Produce one **Problem-to-Action Memo** containing:

1. verbatim stuck statement
2. problem/situation/chosen-constraint table
3. root post and primary protective posture
4. truth statement and “and” tradeoff
5. actual-risk ledger
6. smallest useful experiment with downside cap, decision, measure, and stop rule
7. feedback-sponsor audit and qualified signal
8. four-week decision-once habit, if warranted
9. one next owner or explicit “run the experiment” verdict

Execution prompt: `references/prompts-v2/problem-to-action-memo.md`. Honor its Output Contract.

## Quality Gate

- [ ] Every obstacle is classified exactly once; no situation receives an action plan and no problem is disguised as fate.
- [ ] The root post changes at least two visible symptoms; otherwise it is another symptom.
- [ ] Felt risk is converted into explicit downside caps and reversibility, not dismissed with encouragement.
- [ ] The experiment is small enough to survive and strong enough to change a named decision.
- [ ] The chosen signal belongs to the intended audience or decision-maker; vanity and spectator metrics are excluded.
- [ ] The habit has a four-week term, minimum spec, review date, and stop rule; no permanent vow is smuggled in.
- [ ] The memo ends with one executable move or one exact handoff, never a menu of frameworks.
