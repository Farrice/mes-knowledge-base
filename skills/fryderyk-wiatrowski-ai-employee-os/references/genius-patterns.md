# Genius Patterns

## 1. Employee, Not Tool

Treat the system as a hire with a job, non-job, manager, surface, access policy, and trust path. A tool can be invoked casually. An employee needs onboarding, permissions, feedback, and a scope of responsibility.

## 2. Native Surface First

Put the employee where the work already happens. In Antigravity, that can mean the Codex conversation, local workspace, command bridge, recurring loop, or client artifact system. External Slack-like deployment is optional and later.

## 3. Context Is A Safety Boundary

Company context creates leverage only if personal, project, team, client, and executive contexts are partitioned. Memory is not a pile; it is a governed map.

## 4. Shared Integrations Need Ownership

One connected integration can save a team from duplicate setup, but only when owner, scope, allowed actions, personal/team status, audit trail, and revocation are explicit.

## 5. Ambient Events Are Inputs

Threads, DMs, edits, deletes, reactions, file changes, and recurring schedules all change task meaning. Treat them as structured events before they enter model context.

## 6. Proactivity Earns Its Way Up

Helpful proactivity expands adoption. Premature proactivity creates security panic. Start with suggestions and small cohorts before workspace-wide activation.

## 7. Personality Is Reliability

Users notice model changes through trust, humor, restraint, tone, and comfort. Regression checks must include personality and relationship quality, not just task correctness.

## 8. Latency Is Surface-Dependent

A ten-minute task feels slow in a web app and fast in a teammate channel. Set progress signals and expectations according to the surface.
