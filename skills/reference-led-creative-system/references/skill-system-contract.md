## Objective

Provide one repeatable front door that turns reference research into visible visual choices, a selected reference lock, production assets, and regression-safe reuse without replacing the user's existing brand system.

## Components

| Component | Function | Ownership boundary |
|---|---|---|
| Installed `refero-design` | Research and taste methodology | Sole reference-research and synthesis authority |
| Refero MCP styles/screens/flows | External evidence | Read-only research; no copied brand system |
| `reference-led-creative-system` | Sequence and handoffs | Orchestrates; does not invent a second taste methodology |
| Existing brand/design system | Identity and reusable tokens/components | Outranks borrowed reference styling |
| `direction_pack.py` | Local preview capture, contact sheet, receipt | Proves visibility only; does not judge taste |
| `/generate` | Optional new imagery or mockup production | Only when the reference lock requires bitmap media; cost/craft gates remain |
| `/repeatability-spine` | Golden example, preservation lock, regression recovery | Prevents drift and one-off magic |
| Farrice or named reviewer | Final taste promotion | Human checkpoint; verifier scores do not replace taste |

## Composition rule

Refero Design is the sole function owner for visual research and synthesis. The existing brand system owns identity constraints. This system owns sequence and proof of visibility. `/generate` may fill a media slot but may not reinterpret the lock. Repeatability Spine protects the good example. Every contribution must name the decision it changes; component names alone are not proof.

## Step order

1. Brief and identity boundary.
2. Existing-route and source check.
3. Refero style research; screens/flows only as needed.
4. Three-direction synthesis and distinctness test.
5. Manifest, local preview capture, contact sheet, and receipt.
6. Recommendation and human checkpoint.
7. Reference lock and decision ledger.
8. One or two production surfaces.
9. Rendered visual QA and drift correction.
10. Preservation receipt, replay prompt, and bounded extension.

## Inputs

- what is being designed and on which surface;
- audience, business/user goal, objection, and desired feeling;
- existing brand/product/design-system source paths;
- must-keep and forbidden territory;
- research depth and needed Refero layers;
- whether the desired result is directions, a chosen lock, production assets, or an audit;
- paid-tool, publishing, and external-action boundaries.
