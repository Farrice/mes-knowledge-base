# Context Engineering OS — User's Guide

The complete operating manual for `skills/chase-hughes-context-engineering/`. Built 2026-05-30 from Chase Hughes's Modern Wisdom interview. This is the "how do I actually use this" doc — leverage, limits, and the exact commands.

---

## 1. What it is, in one breath

A system that runs **before you write anything**. It does not produce copy. It produces the **context** that copy gets written into, so the action you want becomes the reader's own obvious next step instead of something you have to push them toward.

The whole thing rests on one inversion:

> **Stop engineering the outcome. Engineer the conditions upstream of it, and the outcome becomes automatic and self-chosen.**

Behavior is downstream of permission → permission of context/category → context of perception. So you never push "buy / subscribe / book." You shift perception, reclassify the category, grant permission — and the behavior falls out for free.

The planning question, for every project, is one of these two:
- *"What is upstream of the thing I want?"*
- *"What context makes the behavior I want automatic?"*

---

## 2. The core mechanic (PCP)

Every workflow is a variation on this cascade:

| Layer | The move | Example (a $5K coaching offer) |
|---|---|---|
| **Perception** | Shift what they believe is happening / possible | "My plateau is a *system* problem, not a willpower problem" |
| **Context / Category** | One loaded word that reclassifies the situation | "audit" (not "coaching") |
| **Permission** | The category makes the action obviously allowed | "Commissioning an audit is what serious operators do" |

The category word is the highest-leverage lever you have. One word ("audit" vs "coaching", "being helped" vs "being sold to") rewrites permission faster than any argument. When you're stuck, you're almost always missing the category word.

## 4. How it fits everything else (the handoff)

`/ce-design` does **not** replace `/parallax`, `/ghostwrite`, Luke Iha copy, or Lara Acosta. It feeds them.

```
you have an outcome you want
        ↓
/ce-design  →  Context-Design Spec  →  /parallax | /ghostwrite | Luke Iha | Lara | Caleb 4C
        ↓                                         ↑
the spec (category word, perception shift,   they write the actual asset
touchpoint order, deferred ask)              INTO the designed context
```

Two modes:
- **Standalone** — run `/ce-design`, get the spec, stop. You wanted the design, not the asset.
- **Inside the Chain (Step 3.5)** — after routing, it produces the spec, then the production expert writes into it; verification and finalize run normally on the finished asset.

Precedence rule: "design a campaign where buying feels automatic" routes to `/ce-design` **first**, which hands off to the production workflow. Multi-deliverable missions defer to `/supercomputer` (which can call `/ce-build`).

## 5. The ethics gate (the guardrail you can trust)

`/ce-design`, `/ce-build`, and `/ce-honesty` run a deterministic gate (`execution/context_ethics_gate.py`) before any spec ships. It is not a vibe — it's code, it logs every verdict, and it can't be skipped by forgetting. It returns:

- **PASS** — clean; proceed.
- **REVIEW** — a structural flag (e.g. running the honesty protocol on someone who can't freely exit); the design must clear it.
- **BLOCK** — manufactured urgency/scarcity/fear with no defensive read (manufacturing chaos to sell the cure). Halt and rewrite.

The bright line it enforces: **reducing someone's chaos and supplying genuine clarity = help. Manufacturing chaos to sell the cure = blocked.** Every offensive mechanic in the skill ships with its detection tell and resistance move, so the same system that designs influence also teaches you to spot it.

## 7. What it CAN do

- **Write finished, publishable copy across 7 verticals** (`/ce-write`) — social, content, media, storytelling, marketing, copywriting, ghostwriting — by fusing the psychology with the craft expert for that vertical. Not a brief: the actual post, email, article, or page.
- **Turn a weak offer into a compelling one** (`/ce-offer`) — recategorize, name the mechanism, stack the value and proof, reframe the price/risk. Makes a badly-built offer land; flags a hollow one honestly.
- Design the conditions where a good action feels self-chosen (offers, funnels, launches, onboarding, content systems, leadership asks).
- Find the single category word that reframes resistance into permission.
- Sequence a recipient-build so the ask lands last, after belief/identity/permission are installed.
- Build genuine followability and confidence at the cause level (not body-language tricks).
- Surface a real objection or hidden truth ethically, with a hard consent boundary.
- Read a person/transcript/video for stress and change as likelihood (feeds your audience research and sales prep).
- Decode manipulation being run on you (or audit your own draft for it), in a usable brief format.
- Turn your own stuck patterns into memoir-grade content.
- Hand a clean, executable brief to any production expert so they write *into* a designed context.

## 8. What it CANNOT do (read this part)

- **It WILL only deploy manipulation for a buyer-harming offer — that's the one hard no.** `/ce-offer` makes a badly-*built* offer compelling (wrong category, buried value, no mechanism, weak proof — all fixable). It will not make a buyer-*harming* offer sell; it flags it honestly and stops. That single line is the guardrail that lets you wield the finished-copy version safely. Everything else about offers is fair game.
- **It is not a lie detector and `/ce-read` gives likelihood, never verdict.** "There's no behavior for deception — zero." Trained deceivers and psychopaths can't be reliably read. Use it for *direction*, not proof.
- **Knowing the mechanics does not immunize you.** Hughes's own point: defense is *structural* (limit exposure, pause at choke points), not "being aware." `/ce-defend` names the move; it doesn't make you bulletproof.
- **It needs you to know the end-state and the target.** Vague input → vague spec. If you can't name the one behavior you want and who's performing it, run `/ce-pcp` or do ICP work first.
- **`/ce-honesty` refuses power-asymmetry situations.** Running it on an employee, subordinate, or partner mid-conflict (anyone who can't freely leave) is coercive regardless of intent; the gate flags it.
- **It is not a substitute for proof or ground truth.** It's the delivery architecture, not the evidence. Pair it with real proof (your proof-ladder skills), not in place of it.
- **Don't judge it by the finalize score.** Behavioral influence has no ground-truth benchmark in the system, so `chain_runner` caps it at 7.25 regardless of build quality. Judge outputs by whether the spec passes the ethics gate and whether the action actually became automatic — not the composite number.

## 9. Quick-start

1. Pick the one outcome that pays fastest (probably the Authority Flywheel call).
2. Run `/ce-design` with end-state + target + channel.
3. Read the spec — especially the category word and the deferred-ask placement.
4. Hand Section 8 (the handoff) to your production workflow.
5. The gate already ran; if it flagged anything, fix it before you write.

When you only need one move, skip the front door: `/ce-pcp` for the category word, `/ce-followability` for delivery, `/ce-defend` to decode something, `/ce-source-code` for content fuel.
