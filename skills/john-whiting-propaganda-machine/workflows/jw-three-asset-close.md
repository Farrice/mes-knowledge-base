# Three-Asset Close — Model, Machine, Invite

This is the compact considered-purchase path inside the Propaganda Machine. Tom Youngs supplies the three-asset compression; John Whiting remains the function owner for truthful belief installation, self-selection, objection handling and closing without a human save.

`PUBLIC CONTENT -> MODEL -> MACHINE -> INVITE -> FIT SCREEN -> PAYMENT -> DELIVERY`

No setter. No closer. No pre-sale call. A synchronous conversation may happen only after cleared payment and must be operational, not a second sales gate.

## Input contract — Offer Truth Packet

| Section | Required truth |
|---|---|
| Buyer | Exact considered-purchase buyer, current context and decision owner |
| Painful job | The consequential job they need done now, preferably in buyer language |
| Failed game | Current approach and the observable reason it fails |
| New belief | One defensible belief that changes how the buyer sees the solution |
| Vehicle | How the operator's method works and why each step exists |
| Offer | Exact scope, price, terms, timing, exclusions and make-right |
| Proof | Real proof available, proof gaps and prohibited claims |
| Objections | Sourced objections or explicitly marked hypotheses |
| Fit | Right-fit behaviors, wrong-fit behaviors and disqualifiers |
| Required inputs | What must exist before payment, work start or delivery clock |
| Claim constraints | Legal, policy, health, financial or other approval boundaries |
| Capacity | Delivery owner, reviewer, launch owner and results owner |
| Payment | Real payment route state and cleared-payment definition |
| Acquisition | Public content, referral, outbound or other source of qualified attention |
| Awareness | Current entry stage and evidence for that classification |

## Readiness verdict

Return the verdict before drafting:

- `BUILD` — considered-purchase offer is specific, true, provable and has a qualified attention source.
- `DISCOVER_FIRST` — buyer/job fit exists, but traffic, control, baseline, buyer language, proof or outcome definition needs bounded discovery.
- `HOLD` — a required truth, reviewer, permission, payment route or claim source exists but is missing or pending.
- `REJECT` — low-ticket impulse purchase, fabricated proof, unsafe claim, false scarcity, wrong-fit buyer, guaranteed outcome, or a buying process that mandates pre-sale calls.

Never convert a missing field into generic copy. Name the missing input and the smallest allowed next action.

## Step 1 — The Model: sell the shift

**Awareness job:** problem-aware -> solution-aware.

Run `jw-big-domino`. Surface the current belief generously, show the observable cost of the failed game, contrast it with the new model, and let the buyer reach the new belief. Do not explain modules, price, deliverable counts, onboarding or the operator's offer.

Default public-video range: 20-30 minutes. Runtime is a heuristic, not a gate. The pass condition is that the buyer can explain why the old game fails and what better game should replace it.

**Handoff:** one-sentence installed belief, evidence used, unresolved proof gap, and the sentence that introduces the private Machine.

Execution prompt: `references/prompts-v2/model-belief-shift-video.md`

## Step 2 — The Machine: sell the vehicle

**Awareness job:** solution-aware -> product-aware.

Begin by restating the Model's shift. Then open the inspection room: show the operating sequence, why each component exists, required buyer inputs, proof objects, limitations, review/approval owners and how the buyer will judge completion. This is calm inspection, not an offer-stack ambush.

Default unlisted-video range: 30-60 minutes. The pass condition is that the buyer can explain how the vehicle works, what it requires from them, what it can prove and what it cannot promise.

**Handoff:** vehicle summary, proof boundary, fit signals, open risk, and the sentence that offers the private Invite.

Execution prompt: `references/prompts-v2/machine-inspection-video.md`

## Step 3 — The Invite: invite the right person

**Awareness job:** product-aware -> most-aware/decision-ready.

Run `jw-self-selection-filter`. Lead with explicit disqualifiers. Then state the qualified buyer, painful job, exact deliverables, price, terms, timing, required inputs, proof limits, make-right, next step and what happens after cleared payment. Page, document or equivalent private surface is acceptable; completeness and decision clarity are not optional.

The CTA is an async fit screen or direct payment path when fit is already established. Never use a calendar link or “book a call” escape hatch.

**Handoff:** readiness verdict, qualified next action, missing input if any, and payment-authority boundary.

Execution prompt: `references/prompts-v2/invite-decision-document.md`

## Step 4 — The Close Path: remove the human save

Wire the exact transitions and asynchronous responses:

1. public content -> Model;
2. Model -> unlisted Machine;
3. Machine -> private Invite;
4. Invite -> fit screen;
5. fit confirmation -> exact scope/terms;
6. authorization -> payment request;
7. cleared payment -> delivery intake.

Include concise responses for proof requests, price/scope objections, no usable baseline, wrong fit, procurement requesting a call, payment not cleared and buyer silence. Silence is `NO EVENT`, not permission to chase or rewrite the offer.

Execution prompt: `references/prompts-v2/zero-call-close-path.md`

## Entry-stage adaptation

- Cold/problem-aware traffic enters through the full Model.
- A referral or product-aware buyer may receive a shorter Model recap, but the belief-shift check cannot be skipped.
- Low-ticket impulse products route away from this workflow.
- No qualified attention source returns `DISCOVER_FIRST`; the assets do not create demand by themselves.

## Output contract

Deliver one **Three-Asset Close System** containing:

1. Offer Truth Packet and readiness verdict.
2. Model blueprint/script and handoff.
3. Machine blueprint/script and handoff.
4. Invite decision document and handoff.
5. Close Path with transition copy, fit screen, objection responses, payment boundary and event ledger.
6. Ethics Gate and domain-specific claim review.
7. Human checkpoint card for the Model belief, Machine mechanism and Invite exclusions.

## Quality gate

Fail and repair once if any condition is false:

- The Model changes a defensible belief without pitching offer features.
- The Machine re-anchors that exact belief before explaining the vehicle.
- The Invite names wrong fits, exact price/terms, proof limits and an async next step.
- No branch contains a pre-sale call, calendar link, setter, closer, invented scarcity or outcome guarantee.
- Every factual/proof claim has a source or explicit proof-gap label.
- A missing critical input produces `HOLD`, `DISCOVER_FIRST` or `REJECT`.
- Public content or another qualified attention source is acknowledged as a prerequisite.
- The Ethics Gate passes true claims, real proof, buyer interest and reversible respect.

Local completion proves `RUNNABLE` or `TRANSFERRED`, not demand or conversion. Market state remains `NO EVENT` until a buyer acts.
