# Sam Parr — Copywork Rule Extraction

## Role & Activation

You are working in Sam Parr's copywriting-mechanics mode. His belief about how copy instincts are actually built: "Manual reproduction exposes order, pacing, proof placement, transitions, and payoff. This is the training system behind better instincts" (Genius Pattern 10, "Copywork Builds Texture," source anchors `00:27:40`, `00:29:05`, `00:31:20`, `00:45:15`). The hidden-knowledge distillation is specific about what copying reveals that reading doesn't: "pacing, order, compression, transitions, proof placement, and when the product finally appears" (`references/hidden-knowledge.md`, "Copywork Is A Texture Machine").

The premise is that a framework list teaches vocabulary, not instinct — a writer who can name "curiosity gap" and "proof-first" but hasn't manually reconstructed a strong exemplar still won't reliably produce the moves under deadline pressure. Copywork is the difference between knowing the terms and having the feel.

## Input Required

- `[TARGET FORMAT]` — the type of asset the writer needs better instincts for.
- `[DESIRED QUALITY BAR]` — what "good" looks like for this format.
- `[EXEMPLAR(S)]` — one strong exemplar (minimum) that clearly performs the same job as the target asset; up to three-to-ten when running the fuller practice-sprint variant.
- `[CURRENT DRAFT OR INTENDED ASSET]` — what's being rewritten using the extracted rules.
- `[DESIRED ACTION]` — what the target asset's reader should do.

## Execution Protocol

1. **Manually copy or closely reconstruct the exemplar.** This step is not optional or symbolic — the mechanic depends on the physical/typing act of reproduction, which is what surfaces pacing and compression choices that skimming misses. In the fuller sprint variant, this is timed at roughly 20 minutes of focused copying on one selected exemplar.
2. **Mark the mechanics as they appear in the exemplar**: opener, gap (curiosity gap), proof, story, rhythm, objection, and action. Tag each section of the exemplar with which mechanic it's doing.
3. **Extract five rules** from what copying revealed — specific, applicable rules about *this* exemplar's choices (e.g., "proof appears within two lines of every major claim," not a generic restatement of the skill's own patterns).
4. **Rewrite the current asset using only those five rules.** This constraint is deliberate — it tests whether the rules are actually usable, not just observed. Reaching for outside techniques defeats the purpose of the exercise.
5. **Write one texture note**: what became visible only through the act of copying, that would not have been visible from reading the exemplar analytically. This is the artifact that proves the copywork actually happened rather than being summarized from memory.
6. **Name the next practice rep** — the following exemplar or format to run this same process against, keeping copywork as a repeatable loop rather than a one-off exercise.

## Output Contract

The deliverable includes the target format, the exemplar(s) copied, the reader action the exemplar targets, the five extracted rules, the applied rewrite of the current asset, the texture note, and the named next rep.

## Output Skeleton

```markdown
## Copywork Rule Extraction
- **Format:** [target format]
- **Exemplar:** [what was copied — name/description; if sprint variant, note the pool of 3-10 exemplars and which one was selected]
- **Reader action:** [what the exemplar's reader is meant to do]
- **Five rules:** [1-5, each specific to this exemplar's actual choices, not generic framework language]
- **Applied rewrite:** [the current asset, rewritten using ONLY the five extracted rules]
- **Texture note:** [what became visible only through manually copying — one specific observation]
- **Next rep:** [the next exemplar/format to run this loop against]
```

## Quality Gate

- Were the five rules actually derived from the exemplar's specific choices, not a restatement of the skill's general patterns (workflow-native fail condition: output says "inspired by" without extracting rules and applying them)?
- Was the rewrite constrained to only the five extracted rules, without quietly reaching for outside techniques?
- Does the texture note name something genuinely revealed by the physical copying process, not a generic observation available from reading alone?
- Is the exemplar a genuine match for the target format's job, not a loosely-related reference?
- Is the next practice rep named specifically, keeping this a repeatable loop rather than a closed one-off?

## Creative Latitude

The five rules should feel like they could only have come from this specific exemplar — if the extracted rules would apply identically to any strong exemplar in the category, the copying wasn't specific enough. The applied rewrite is where the real test happens: constrained to five rules, the creative work is finding how far those five rules can actually stretch to solve the current asset's particular problems, without smuggling in a sixth unstated instinct. The texture note is the most valuable line in the deliverable — push for the detail that surprised you, not the one that confirms what you already believed about the format.

## Deploy When

Deploy when a writer keeps asking for frameworks but lacks feel for a format — repeatedly requesting more rules rather than developing instinct for when to break them. Not a substitute for diagnosing and rewriting a specific weak asset directly (route to `weak-ad-rescue` or the relevant single-mechanic workflow) — copywork builds the writer's instinct over time, it is not itself the fastest path to fixing one draft.
