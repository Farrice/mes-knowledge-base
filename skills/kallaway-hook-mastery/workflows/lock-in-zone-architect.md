# Lock-In Zone Architect

> **🔒 Pre-Flight Gate**: genius.md Decision Framework. Non-negotiable input: what PROOF artifact exists (study, case study, third-party reference, screenshot)? A strong claim with no trust anchor is the fake-guru pattern — if no proof exists, say so and stop; do not fabricate or hedge around it.

## Skill Acquisition
`genius.md` Patterns 9–10 + the lock-in quotes block in `references/source-quotes.md`.

## Input Required
- **[THE HOOK]**: final hook set (spoken + text at minimum)
- **[THE CLAIM]**: the promise the hook makes
- **[PROOF ARTIFACT]**: the concrete evidence (and its form — screenshot, number, name)
- **[MESSENGER CONTEXT]**: who's on camera / whose voice; audience-relatability facts
- **[PACKAGING REALITY]**: production context (set, lighting, audio) — for the levers checklist

## Execution

1. **Confirm the claim (sentence 1).** Restate/advance the hook's exact subject + outcome so the viewer knows they weren't bait-and-switched. Same nouns, no pivot.
2. **Anchor trust (sentences 2–3).** Deploy [PROOF ARTIFACT] concretely: name the number, show the screenshot, cite the third party. Proof is the most important lever by far.
3. **Tune the other three levers** (checklist, not script): presentation (best believable version of the messenger), packaging (polish signals care; care = trust — one upgrade note if [PACKAGING REALITY] is weak), relatability (does the messenger match the character the audience expects? one wardrobe/framing/vocab note if not).
4. **Bridge (final sentence).** Hand momentum to the body: what's coming, in the viewer's outcome language. No throat-clearing, no "before we start."
5. **Read-back test.** Hook + lock-in read aloud together: does the pair survive a skeptic asking "is this another fake guru?" If any sentence is claim-without-evidence, rework.

## Content Type Adaptations
| Format | Adaptation |
|---|---|
| Short-form video | 2–4 sentences, proof visual cut in at the anchor line |
| Long-form YouTube | This is the intro's job: confirm title/thumbnail click, then anchor |
| LinkedIn post | Sentences 2–4 after the first-line hook; proof = named number/receipt |
| Ad | Anchor is mandatory and earliest; stack `hook-trust-stack` |
| Email | After subject+opening line; proof before the first CTA |
| Sales page | The lead's job; anchor above the fold |

## Output Requirements
Deliver: (1) scripted lock-in zone (2–4 sentences, proof insertion marked), (2) four-lever checklist with pass/upgrade notes, (3) read-back verdict. State length held. Feedback Triad.

Execution prompt: references/prompts-v2/khm_lock_in_zone.md

## Quality Gate
Claim confirmed with the same nouns (no topic drift). Proof concrete and real (factual-grounding rules apply — VERIFIED/LIKELY/UNCONFIRMED labels on any external fact). No lever left unexamined. Anti-pattern: strong hook + trust-free lock-in.
