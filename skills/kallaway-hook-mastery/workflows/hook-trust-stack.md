# Hook Trust Stack

> **🔒 Pre-Flight Gate**: genius.md Decision Framework + proof inventory. This workflow is for conversion-critical assets. If no real proof exists yet, the honest output is a proof-generation plan, not a faked trust stack.

## Skill Acquisition
`genius.md` Patterns 9–10 + `skills/luke-iha-vicious-hooks` and `luke-iha-proof-ladder` context (Tier per Context Engine; hot-context rules apply). One author per body: Kallaway architecture, Luke's proof mechanics as structure — final prose in one voice.

## Input Required
- **[ASSET]**: ad / VSL / sales post / landing hero / webinar open
- **[CLAIM]** and **[OFFER]**
- **[PROOF INVENTORY]**: every receipt available (numbers, screenshots, case studies, third-party refs, testimonials)
- **[AWARENESS LEVEL]**: cold / warm / hot traffic

## Execution

1. **Hook per Interrupt Theory** (via `interrupt-hook-engine` logic): subject + stakes at [AWARENESS LEVEL] — cold traffic needs the pain/outcome named harder; hot traffic can lead with the mechanism.
2. **Ladder the proof.** Sort [PROOF INVENTORY] strongest-first for THIS audience (third-party > screenshot > self-report; specific > round numbers). Place proof #1 as the lock-in trust anchor (sentence 2–3), proof #2–3 deeper as objection collateral.
3. **Four-lever pass**: messenger presentation, packaging polish, relatability match to the buyer's expected character, proof density. One upgrade note per weak lever.
4. **No-bait guarantee**: the lock-in confirms the exact hook claim; the body delivers it. Bait-and-switch kills trust at the moment wallets open.
5. **Compliance/factual pass**: every proof labeled VERIFIED/LIKELY/UNCONFIRMED; UNCONFIRMED proof never ships in a paid asset (factual veto applies).

## Content Type Adaptations
| Asset | Adaptation |
|---|---|
| Static ad | Hook = headline+creative; proof = one on-image receipt + body block |
| VSL | Hook ≤8 words spoken; anchor at 5–10s; ladder through the lead |
| Sales post (LinkedIn) | Line 1 hook; receipt in lines 2–4; CTA after second proof |
| Webinar open | Hook + anchor + credibility beat inside first 60s |
| Offer doc / proposal | Page-1 hook line; receipts section = the ladder |

## Output Requirements
Deliver: (1) hook set, (2) proof ladder with placement map, (3) scripted lock-in, (4) four-lever notes, (5) factual labels. State length held. Feedback Triad.

Execution prompt: references/prompts-v2/khm_lock_in_zone.md (conversion lane)

## Quality Gate
No unverified proof in paid assets (hard). Claim–delivery match audited. Anti-pattern: strong claim, thin anchor — the fake-guru shape this workflow exists to prevent.
