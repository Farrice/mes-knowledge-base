# ALEX COOPER - CUSTOM GPT ARCHITECTURE BLUEPRINT CROWN JEWEL PROMPT

## Activation



## Input Required

- [USE CASE]: What recurring task, decision, or analysis this GPT will handle
- [CONTEXT DOCUMENTS]: What information should be embedded (brand info, research, examples, etc.)
- [USER TYPE]: Who will be using this GPT (you, team members, clients)
- [OUTPUT EXPECTATIONS]: What kind of outputs should it produce
- [FREQUENCY]: How often this GPT will be used
- [EXISTING EXAMPLES]: Any examples of good outputs for this use case (optional)

## Execution Protocol

1. **Purpose Definition**: Clearly articulate the single primary purpose of this GPT. What decision does it help make? What task does it execute? What analysis does it perform?

2. **Context Architecture**: Identify all context that should be embedded—brand information, historical data, examples of good outputs, frameworks, preferences, constraints.

3. **Instruction Engineering**: Design the system instructions that will guide the GPT's behavior—persona, tone, output format, decision frameworks, quality standards.

4. **Input Specification**: Define what inputs the user will provide and how they should be structured for optimal outputs.

5. **Output Formatting**: Specify exactly what the output should look like—structure, length, components, formatting.

6. **Edge Case Handling**: Anticipate edge cases and build in handling—what if context is missing? What if request is outside scope?

7. **Iteration Protocol**: Design how the GPT should handle follow-up requests and refinements.

## Output Contract

**Deliverable**: Structured framework/system responding to input requirements
**Format**: Strategic guide with sections and actionable components
**Length**: 3,000–5,000 words
**Core components**:
- System overview or architecture
- Step-by-step execution protocol
- Implementation templates or worksheets
- Quick-reference guide or checklist

## Quality Gate

Verify all v2 outputs against these checkpoints:

1. **Methodology Integrity**: All execution steps from original are preserved; no thin gaps where examples were stripped.
2. **No Fabricated Specifics**: Zero invented statistics, case studies, client names, or results presented as real.
3. **Input-Output Traceability**: Every input required maps to output components; logic is transparent.
4. **Actionability**: User can reasonably execute or adapt steps without domain expertise beyond the original intent.
5. **Tone Alignment**: Maintains expert confidence and activation stance without padding or unverifiable claims.
