# /spiegel-distribution — Distribution Audit

> Solve distribution BEFORE building. The #1 startup failure mode is a great product nobody knows about.

## When to Use
- You have a product, service, or offer idea and haven't validated distribution
- Something is built but isn't growing and you can't figure out why
- Before deploying any other Spiegel workflow
- Evaluating a new market, platform, or product category

## Inputs Required
1. Product/service/offer description (what it does, who it's for)
2. Current distribution channels (if any)
3. Competitive landscape (who else serves this audience?)
4. Available resources (budget, existing audience, partnerships)
5. Timeline (when does this need to reach people?)

## Execution Steps

### Step 1: Distribution Channel Scan
Answer each question with specific evidence, not hopes:

| Question | Answer | Score (1-10) |
|---|---|---|
| What distribution channel already exists for this category? | | |
| Is there a platform shift creating a temporal window? (new form factors, AI capabilities, new stores) | | |
| Can you subsidize distribution? (TikTok model — spend to bootstrap both sides) | | |
| Can you leverage existing distribution? (Threads model — ride existing platform) | | |
| What structural advantage can you engineer? (Snapchat model — network density) | | |

### Step 2: Temporal Window Assessment
Diagnose whether you're in, approaching, or past the distribution window:
- **Open Window**: New platform, new form factor, early adoption curve → MOVE NOW
- **Closing Window**: Growth decelerating, incumbents arriving → MOVE FAST
- **Closed Window**: Saturated, dominated by incumbents → FIND ANOTHER WINDOW
- **No Window**: No platform shift, no structural tailwind → ENGINEER YOUR OWN

### Step 3: Distribution Advantage Statement
Write ONE sentence: "My distribution advantage is [X] because [structural reason]."

If you cannot write this sentence, you do not have a distribution strategy. Go back to Step 1.

### Step 4: Channel Prioritization Matrix
Rank available channels by:
1. **Addressability** — Can you reach your specific audience through this channel?
2. **Cost** — What's the per-user acquisition cost?
3. **Speed** — How fast can you activate this channel?
4. **Defensibility** — Can competitors replicate this channel access?
5. **Scalability** — Does this channel grow with you or hit a ceiling?

### Step 5: Distribution-First Build Spec
Redesign the product/service/offer around distribution:
- What features must exist to take advantage of the distribution channel?
- What features can be cut because they don't serve distribution?
- What's the minimum viable product that the distribution channel needs?

## Output Format
```
## DISTRIBUTION AUDIT — [Product/Offer Name]

### Distribution Score: X/50

### Temporal Window Status: [Open/Closing/Closed/None]
[Evidence and timeline]

### Distribution Advantage Statement
"My distribution advantage is ___ because ___."

### Channel Priority (Ranked)
1. [Channel] — Addressability: X | Cost: X | Speed: X | Defensibility: X | Scale: X
2. [Channel] — ...

### Distribution-First Build Recommendations
[What to build, cut, or redesign for distribution]

### Recommended Next Workflow
[/spiegel-moat if distribution is solved, /spiegel-empathy if building new]
```

## Quality Gate
- Distribution Advantage Statement must be ONE sentence with a structural reason
- Temporal window status must cite specific evidence, not vibes
- Channel ranking must use all 5 criteria with scores
- Must recommend specific next workflow in the Spiegel chain
