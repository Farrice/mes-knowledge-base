# /spiegel-dual-org — Dual-Org Sprint

> Design and implement the Loonshots dual-org: fast-brain innovation + slow-brain operations with managed interface.

## When to Use
- Need both innovation AND operational reliability
- Innovation is dying under operational process weight
- Operations is breaking under innovation chaos
- Scaling past founding stage and need organizational structure

## Inputs Required
1. Current org structure (size, hierarchy, roles)
2. Innovation pain points (what's broken)
3. Operations pain points (what's unreliable)
4. Leader's current time allocation (innovation vs. operations)

## Execution Steps

### Step 1: Current State Diagnosis
Score each brain:

**Fast Brain Health** (Innovation)
- Flatness (0 = perfectly flat): ___/10
- Idea volume per week: ___
- Ego attachment level: ___/10 (lower = better)
- Fresh eyes (when did someone last rotate in?): ___

**Slow Brain Health** (Operations)
- Process documentation: ___/10
- Delivery reliability: ___/10
- Scale readiness: ___/10
- Clear accountability: ___/10

### Step 2: Team Splitting
Design the two teams:
- **Fast Brain**: Max 9-12 people. No titles. Weekly output reviews. Day-one presentation rule.
- **Slow Brain**: Clear hierarchy. Documented processes. Reliability metrics. Scalable.

Who goes where? Map current team members by natural orientation.

### Step 3: Interface Design
The leader's PRIMARY job — managing the dialogue:
1. **Innovation → Operations handoff**: When is an idea "ready"? What criteria?
2. **Operations → Innovation feedback**: How do real-world constraints inform ideation?
3. **Mutual respect protocol**: Innovation doesn't mock process. Operations doesn't mock experiments.
4. **Conflict resolution**: When the two brains disagree, how is it resolved?

### Step 4: Solopreneur Adaptation
For solo operators, split your WEEK:
- **Innovation Days** (2/week): No client work. Only ideation, experimentation, building.
- **Operations Days** (3/week): Delivery, admin, process, client management.
- **Interface Moment** (Friday): Review what innovation produced, decide what enters operations.

### Step 5: Tension Management Playbook
When tension becomes destructive:
1. Identify whether the conflict is structural (design issue) or personal (ego issue)
2. Structural → redesign the handoff criteria
3. Personal → address directly, citing mutual respect protocol
4. Escalation → leader absorbs the tension, doesn't redistribute it

## Output Format
```
## DUAL-ORG SPRINT — [Organization]
### Fast Brain Design: [structure, team, cadence]
### Slow Brain Design: [structure, process, metrics]
### Interface Protocol: [handoff, feedback, respect, conflict]
### Solo Adaptation: [weekly schedule]
### Tension Playbook: [structural vs personal resolution]
### 30-Day Implementation Plan
```

## Quality Gate
- Must design BOTH structures, not just the exciting one
- Interface protocol must be explicit (not "they'll figure it out")
- Must include solo/small-team adaptation
- Tension playbook must distinguish structural from personal conflict
