# Breadth-to-Leverage System

## Purpose

Preserve a multi-interest operator’s breadth while forcing one narrow execution arena. This is a diagnostic and behavior-change workflow, not a personality quiz. Archetypes are working hypotheses that must change the prescription or be omitted.

Execution prompt: `references/prompts-v2/breadth-to-leverage-decision-brief.md` — honor its Output Contract.

## Inputs

- Interest and project inventory.
- Last 90 days of starts, switches, completions, and abandoned opportunities.
- Current buyer, problem, offer, or destination arena.
- Visible outputs and external proof, kept separate.
- Constraints, anti-goals, and permission boundaries.

If the behavioral history is missing, stop at `EVIDENCE INCOMPLETE` and request only the missing evidence. Do not infer an archetype from adjectives such as “curious,” “creative,” or “multipassionate.”

## Phase 1 — Evidence Before Identity

Build an evidence table with four columns: behavior, date/context, consequence, proof state. Separate:

- learning or research;
- frameworks or system artifacts;
- visible shipped outputs;
- external use or response;
- sales and collected payment.

Never treat one category as proof of another.

## Phase 2 — Competing Archetype Hypotheses

Evaluate all six mechanisms:

| Archetype | Behavioral signal | Prescription |
|---|---|---|
| Explorer | Samples widely and overestimates the depth created by fast learning | Multi-year panoramic question |
| Master of Synthesis | Repeatedly combines fields toward a useful destination | Destination arena + hub skill + interests as R&D |
| Free Agent | Exits near commitment, exposure, breakthrough, or success | Problem large enough to contain interests + commitment audit |
| Talent Stacker | Builds an unusual combination but lacks a directing vision | Meaningful vision + bounded interest seasons |
| Pattern Hunter | Builds models and connections, then moves on before deployment | Work broadly, execute narrowly + visible output in one arena |
| Polymath | Has inspectable mastery and contribution across several domains | Sequential depth; one domain threshold at a time |

Output:

- primary hypothesis with two behavioral receipts;
- secondary hypothesis with one receipt;
- strongest rejected hypothesis and disconfirming evidence;
- confidence: `HIGH`, `MEDIUM`, or `LOW`.

Withhold `Polymath` unless at least two domains have contribution evidence. Never use archetypes as fixed identities.

## Phase 3 — The Focus Lock

Choose exactly one:

1. **Destination arena** — one buyer class and one consequential problem.
2. **Hub skill** — the capability that appears in every output.
3. **Lead interest** — the current 30-day season.
4. **Supporting R&D** — no more than two interests that materially improve the output.
5. **Maintenance** — capabilities kept warm with a strict time ceiling.
6. **Parked** — every other interest, with a revisit date.

Apply the removal test: if removing an interest does not weaken the promised result, it is decoration and cannot occupy a production slot.

## Phase 4 — Visible Deployment

Define one output that can be inspected by someone outside the operator’s internal system. It must name:

- format;
- recipient or proof surface;
- due date;
- hub skill exercised;
- external behavior that would count as a signal.

For a Pattern Hunter, no new framework or agent may begin until the current framework changes a decision or produces the visible output.

## Phase 5 — Thirty-Day Experiment

Track weekly:

- outputs shipped;
- sent or published only when authorized;
- replies;
- calls;
- sold;
- collected;
- switches avoided;
- parked interests reactivated early.

At day 30 choose `KEEP`, `REVISE`, or `KILL`. A beautiful internal system is not commercial evidence.

## Phase 6 — Optional Strategic-Interest Handoff

Only when `FOCUS LOCKED` and a proof artifact exists, apply the supporting Joanna sequence:

1. create a perceptible gap;
2. make the gap matter to the buyer;
3. preserve one substantive open loop;
4. keep real layers and tensions rather than over-polishing;
5. name the idea or behavior the work rejects.

Route identity filtering to `references/prompts-v2/advanced_prompt_18_identity_polarization_engine.md`. This phase amplifies a chosen direction; it cannot choose the direction.

## Output

Produce the Breadth-to-Leverage Decision Brief. End with one next action inside 24 hours and an explicit proof state.

## Quality Gate

- [ ] Classification cites behavior, not self-description.
- [ ] Primary, secondary, and rejected hypotheses are present.
- [ ] One arena, one hub skill, and one lead interest are locked.
- [ ] Internal artifacts, external signals, and commercial proof remain separate.
- [ ] The plan preserves breadth as R&D while narrowing execution.
- [ ] No external action is taken without explicit permission.
