# Workflow 16: Bar-Raising Audit

> **Genius Patterns**: GP-8 (Bar-Raising Reflex) + GP-5 (Anti-Romanticism / Data Kill Switch) + HK-6 (Testing Obsession ≠ Perfectionism)
> **Purpose**: Grace's DOAC team constantly asked "how do we make this better than anything else out there?" — not "is this good enough?" This workflow is the pre-publish quality gate that enforces that standard without becoming perfectionism that delays shipping.

## Pre-Flight Check

Before starting:
- [ ] You have a content piece that is at minimum 80% complete
- [ ] genius.md has been read this session
- [ ] This is NOT for first drafts — this is for content ready to publish

**Critical distinction**: This workflow prevents publishing mediocre content. It does NOT prevent shipping fast iterations. If the piece is an experiment (tagged in Workflow 03), apply lighter criteria — speed matters more than polish for experiments.

---

## Step 1: The Bar Check (GP-8 — Signature Move)

For the content piece, answer these three questions:

### Question 1: "Is there a better version of this already published?"

Research before answering. Search for:
- Top-performing content on the same topic (same platform)
- Content from competitors in your niche on this topic
- Viral/evergreen pieces that "own" this topic

```
COMPETITIVE SCAN
Topic: [your topic]
Top 3 Existing Pieces:
  1. [Title + creator + what makes it strong]
  2. [Title + creator + what makes it strong]
  3. [Title + creator + what makes it strong]
```

### Question 2: "What does mine do differently or better?"

If you can't answer with specific, concrete differences → the piece isn't ready.

```
DIFFERENTIATION CLAIM
My piece is categorically different/better because:
  1. [Specific angle, data, experience, framework, or insight no one else has]
  2. [Structural/format innovation]
  3. [Depth/detail level others don't reach]
```

**Quality gate**: If you can't fill at least ONE differentiation claim convincingly → iterate before publishing.

### Question 3: "Would I bookmark this if someone else published it?"

The honest self-referral test. Not "is this good for something I made?" but "is this genuinely worth consuming?"

- [ ] Yes → Proceed to Step 2
- [ ] No → Return to draft, apply Emotional Residue Engineer (Workflow 15)

## Step 2: Anti-Romanticism Audit (GP-5)

Is there anything in this piece you're keeping for emotional reasons rather than performance reasons?

Run the **Data Kill Switch** (Grace's Signature Move) on the piece:

```
ROMANTICISM DETECTOR
For each section/element of the piece, answer:

Section 1: [describe]
  - Why is it here? [explanation]
  - Is the justification DATA or FEELING?
  - If FEELING: What would you need to see in the data to justify keeping it?

Section 2: [describe]
  - Why is it here? [explanation]
  - Is the justification DATA or FEELING?
  - If FEELING: What would you need to see in the data to justify keeping it?

[Continue for each major section]
```

**Red flag**: Any section justified purely by "I really believe in this" or "I think this is important" WITHOUT supporting data or audience signal = romantic attachment. Consider cutting or testing.

**Exception**: If this is an experiment piece (Workflow 03 tagged), romantic elements are acceptable because the EXPERIMENT is the test. But tag them for post-experiment review.

## Step 3: Testing Protocol (HK-6 — Ships FAST, Tests FASTER)

Grace's testing protocol is NOT perfectionism. It's rapid iteration:

### 3A: Pre-Publish Tests

Before the piece goes live, test these elements:

| Element | Test Method | # Variants | Time Required |
|---------|------------|-----------|---------------|
| **Title/Hook** | Generate 5-10 variants, score each on curiosity + specificity + proof signal | 5-10 | 15 min |
| **Opening Line** | Write 3 variants: reversal, confession, crystallization | 3 | 10 min |
| **Thumbnail/Visual** (if applicable) | Create 2-3 visual variants | 2-3 | 10 min |
| **CTA** | Write 2 variants: direct vs. soft | 2 | 5 min |

### 3B: Post-Publish Testing Plan

Plan what you'll test AFTER publishing (Grace's team tested ruthlessly post-publish):

```
POST-PUBLISH TEST PLAN
Metric to Watch: [primary metric for this platform]
Check-In Schedule: [24hr, 72hr, 7 days]
Kill Criteria: [What performance level triggers a pivot?]
Double-Down Criteria: [What performance level triggers amplification?]
Winner Graduation Path: [If this experiment wins, what's the next step?]
```

## Step 4: Composite Score

Rate the piece across Grace's Quality Rubric criteria:

| Criterion | Score (1-10) | Evidence |
|-----------|-------------|---------|
| **Differentiation** (Step 1) | | What makes this the best version? |
| **Anti-Romanticism** (Step 2) | | Nothing kept for emotional reasons alone? |
| **Testing Readiness** (Step 3) | | Pre-tests completed, post-test plan ready? |
| **Emotional Residue** | | Does it pass the 48-Hour Memory Test? |
| **Trust Pathway Alignment** | | Is it tagged and serving its trust stage? |
| **COMPOSITE** | **(avg)** | |

**Publish threshold**: Composite ≥7. If <7, identify the weakest dimension and fix it before publishing.

**Anti-perfectionism guard**: If you've scored ≥7 but are still hesitating → Ship it. HK-6: "Obsessive testing ships FAST and iterates FASTER. They didn't wait to ship the perfect version."

---

## Quality Gate

The piece clears the bar when:
- ✅ Competitive scan completed — can articulate what's different
- ✅ Anti-romanticism audit passed — no emotional-only sections
- ✅ Pre-publish tests run (title/hook variants, opening variants)
- ✅ Post-publish test plan written
- ✅ Composite score ≥7
- ✅ Piece is PUBLISHED (not stuck in review)
