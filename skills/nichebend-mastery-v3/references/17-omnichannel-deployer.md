## THE MECHANIC

### A — ONE CANON, MANY CONTAINERS

The fragment error: take a 14-minute video, cut a 45-second clip, pull three quotes, paste the transcript into a newsletter, screenshot a slide for LinkedIn. Five artifacts, one grammar, four mismatches. The clip has no opening obligation because the video's hook lived at 0:00 of a different contract. The quotes carry no argument. The pasted transcript reads as spoken language in a written market. The audience does not experience five assets — it experiences one asset arriving badly four times.

The bend operation instead: **hold the ontology constant, re-bend the format per channel.** The LinkedIn post is written as a LinkedIn post — natively, from the canon, by someone who has never seen the video. The X thread is architected as a thread. The email is written as an email. Every piece is a first-class asset in its own market, and every piece is unmistakably the same worldview, because the named mechanism, the lexicon and the POV claim survive translation intact.

The compounding effect is the point. Five unrelated posts buy five impressions. Five containers carrying one canon buy recognition — a viewer who meets the frame on Shorts, meets it again in a newsletter, and meets it a third time on LinkedIn is not seeing three pieces of content. They are watching one position get proven three ways. **Fragments accumulate reach. Canon accumulates a square.**

### C — THE CANON INVARIANTS RULE

Four elements appear **identically everywhere**, unbent, verbatim where possible:

1. **The named mechanism** — the thing you coined. Same name, same capitalization, every channel, every time.
2. **The lexicon terms** — 4–8 words whose meaning you own. Never paraphrased into synonyms for variety's sake; variety here destroys the compounding.
3. **The POV claim** — the one contestable sentence you would defend in public.
4. **The proof anchor** — the specific number, case, or artifact that earns the claim.

Everything else bends: length, structure, register, opening, ordering, visuals, ask. The test is blunt — if a reader who saw only the Shorts and only the email cannot name the same mechanism from both, the invariants leaked.

### D — SEQUENCING LOGIC

Order by **signal per production hour**, ascending in cost:

- **Cheap, high-signal first.** Text posts and threads cost 30–60 minutes and return a read on which framing of the POV claim provokes engagement. They are the title test of distribution — a free option on the whole deployment.
- **Mid-cost second**, informed by what the cheap tests revealed: the email (carrying the framing that won), the carousel, the Shorts.
- **Expensive last.** The long-form video, the podcast, the paid spend. Production cost is committed only after the cheap channels have identified the winning frame and, on paid, only after an organic piece has already proven the hook.

**Routing rules.** Each channel points to exactly one next destination, chosen by proximity to the ask — never to everything, never to a link tree.
- Short-form → the long-form asset (never to a sales page; the audience is cold and the trust gap is too wide).
- Text/social → the email list (the only owned surface).
- Email → the long-form asset or the offer, depending on subscriber tenure.
- Long-form → the offer, once, in the description and once verbally.
- Community → nothing above the fold; a resource named, linked only on request.

### E — DECAY-AWARE RELEASE WINDOW

Formats decay; the deployment window is bounded by the fastest-decaying channel in the set. Compress the full deployment into **7–10 days**. The cheap channels fire in the first 48 hours while the framing is still un-imitated; the expensive asset lands in days 4–7 while the cheap pieces are still circulating and can route into it; the paid amplification and the long-tail blog land last and hold the square after the window closes. A deployment stretched across six weeks is not patient — it is a bend published after the square filled.

## DEPLOYMENT PROTOCOL

**1 — EXTRACT THE CANON INVARIANTS.** Read the source bend and write the four invariants explicitly: named mechanism, lexicon table, POV claim in one sentence, proof anchor with its number. Everything downstream derives from this block.

**2 — CONFIRM GATE A ON EVERY TRAVELLING CLAIM.** Audit each invariant for host-market accuracy before it multiplies. A claim that is merely defensible in a 14-minute video becomes indefensible as a 40-second Short with no qualifiers attached. Cut or requalify any claim that cannot survive compression.

**3 — SELECT THE CHANNEL SET BY PRESENCE, NOT COMPLETENESS.** Choose 4–6 channels where the audience already is. Reject the rest explicitly and name the rejection reason. A ten-channel deployment executed at 60% quality loses to a four-channel deployment executed natively.

**4 — RE-BEND TO LAYER 3 MINIMUM PER CHANNEL.** For each selected channel, write the format bend: which grammar, which opening obligation, which structure. Packaging-only ports (Layer 1) are prohibited — the lexicon must carry into every piece.

**5 — WRITE EVERY PIECE IN FULL.** Finished copy. Real headlines, real line breaks, real on-screen text cues, real subject lines, real ad primary text. No placeholders and no beat lists standing in for copy.

**6 — SEQUENCE THE RELEASE.** Build the schedule with hour offsets, production hours, and explicit dependencies — which piece cannot ship until which result lands.

**7 — WRITE THE ROUTING MAP.** One destination per channel, with the exact routing line as it appears in the copy.

**8 — SET PER-CHANNEL MEASUREMENT.** For each channel, one primary metric against that channel's own baseline, plus the **leading indicator** that reads before the primary metric resolves.

**9 — DEFINE THE AMPLIFICATION TRIGGER AND KILL CRITERIA.** State the exact result on the cheap channels that authorizes producing the expensive asset, and the result that kills the deployment and returns the bend for re-framing.
