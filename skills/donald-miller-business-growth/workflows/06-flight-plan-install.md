# 06 — Flight-Plan Install (Sequencing + Engine Hand-Offs)

The integration workflow. The other workflows build individual parts; this one sequences the whole install and — critically — **routes the two engines out to the messaging skills** so nothing is rebuilt or hoarded. This is the "how do I actually implement the entire playbook" workflow.

## Pre-Flight Gate

Run this when:
- The flight-plan diagnostic (Wf 01) is done and multiple parts need work.
- The owner is overwhelmed by where to start ("do I really do all six at once?").
- You're assembling a full transformation across messaging + operations and need the cross-skill map.

**Do NOT** run this before the diagnostic — you need to know which parts are weak and out of proportion first.

## Skill Acquisition

Load `genius.md` (whole) + the "engine hoarding" anti-pattern. Have all four other Don Miller skills' workflow names ready (this workflow's whole job is correct routing).

## Execution

**Step 1 — Order by crisis, not by chapter.** You do NOT have to install Step 1→6. Start with the part that's crashing the plane:
- **Cash is the fire** → start with **Wf 03** (five accounts) for optics, then **Wf 04/engines** to get money moving.
- **No direction / chaos** → start with **Wf 02** (mission) then **Wf 05** (management).
- **Not converting** → start with the **engines** (route out — see Step 2).
Otherwise the natural order is Mission (02) → engines (out) → Products (04) → Management (05) → Cash Flow (03).

**Step 2 — Route the two engines OUT (the hand-off map).** This skill flies the plane but does NOT build the engines. Hand off:

| Airplane part | This skill? | Route to |
|---|---|---|
| Cockpit — Leadership/Mission | ✅ Wf 02 | — |
| **Right Engine — Marketing** | ❌ | `donald-miller-storybrand` (SB7 BrandScript, one-liner, funnel, wireframe) + `donald-miller-cognitive-load` (score/simplify the message) |
| **Left Engine — Sales** | ❌ | `donald-miller-messaging-evolution/02` (the 6-part color-key second-date pitch) + `donald-miller-storybrand` (Customer-is-the-Hero) |
| Wings — Products | ✅ Wf 04 | (positioning of a new product → `messaging-evolution/04` lane-discipline) |
| Body — Overhead/Ops | ✅ Wf 05 | — |
| Fuel Tanks — Cash Flow | ✅ Wf 03 | — |

*Why:* the engines are pure messaging and are already built to mastery in the other skills. Rebuilding them here is the cardinal anti-pattern (engine hoarding). The marketing one-liner, the BrandScript, the sales color-key — all live elsewhere; this skill *calls* them.

**Step 3 — Pace the install (take it slow).** Install one part, embed it until it's solid, then add the next — *"you can transform your entire small business in under a year."* Don't install all six at once (overwhelm). Each part is "a mini-book in itself."

**Step 4 — Check proportion after each install.** After each part, re-run the proportion check (Wf 01, Step 2): did this part grow the plane in balance, or create a new imbalance (e.g., new products with no engine to sell them)? Adjust the next install accordingly.

**Step 5 — Output the install roadmap.** A sequenced plan: which part, in what order, at what pace, who owns it (operator vs. owner vs. routed-out skill), and the explicit engine hand-offs — plus the re-proportion checkpoint after each step.

## Content Type Adaptations

| Situation | Sequencing emphasis |
|---|---|
| Cash crisis | Wf 03 first (optics), then engines (route out) to move money |
| Pre-revenue / launch | Mission (02) → engines (out) → first product (04 brief) |
| S-curve firefighting | Wf 02 + Wf 05 first (professionalize), then optimize wings/fuel |
| Full rebuild | Natural order, one part at a time, re-proportion after each |
| Messaging already strong | Skip engine routing; focus the four ops parts |

## Output Requirements

- **The install order**, crisis-first, with rationale.
- **The engine hand-off map** — marketing/sales routed explicitly to the named messaging skills/workflows.
- **The pace** — one part at a time, embed-then-advance.
- **Ownership** per part (operator / owner / routed-out skill).
- **Re-proportion checkpoints** after each install.

## Quality Gate

Reject if (per `genius.md`):
- It tries to build/teach the engines (marketing or sales) inside this skill instead of routing out.
- It forces a 1→6 order regardless of which part is actually crashing the plane.
- It installs everything at once (overwhelm, nothing embeds).
- It skips the re-proportion check, letting one part grow the plane out of balance.
