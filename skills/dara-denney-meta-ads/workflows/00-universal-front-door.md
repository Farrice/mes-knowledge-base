# `/dara-denney` — Universal Creative Strategy Front Door

Use this as the single entry point to Dara's complete capability lane. It routes by purchased job and evidence state, then loads only the selected component.

## Context Policy

Keep this workflow and the compact map below hot. Keep all component workflows, raw sources, prompts, and specialist owners cold until selected. Pass a short route handoff, not the full conversation history.

## Routing Protocol

1. Name the user's purchased job in one sentence.
2. Identify evidence state: `LIVE ACCOUNT EVIDENCE`, `SOURCE/RESEARCH EVIDENCE`, `NO LIVE EVIDENCE`, or `OUTCOME EVENT`.
3. Select one primary Dara workflow. Use one bounded support workflow only when its output changes the primary decision.
4. Load the selected workflow, its named reference, and its born-v2 prompt. Do not load the other Dara components.
5. If the request is executable and safe, run it now. Do not return a menu and make the user invoke a second command.
6. Preserve the handoff: objective, format/message/persona state, source evidence, claim/rights limits, selected workflow, missing input, stop condition.
7. Stop before rendering, spend, publishing, creator outreach/rights acquisition, or external writes unless explicitly approved.

## Quality Gate

- One function owner: Dara.
- One primary workflow; at most one bounded support workflow before production composition.
- The route matches the job and evidence state, not a keyword alone.
- Clear asks execute instead of returning a command menu.
- No component or source package is preloaded without need.
- Claim, rights, spend, rendering, publishing, and external-action boundaries survive routing.
- The result can be resumed from the receipt without hidden context.
