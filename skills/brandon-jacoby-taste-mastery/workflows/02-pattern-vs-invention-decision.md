# Brandon Jacoby - Pattern vs. Invention Decision

## Pre-Flight Gate

Load `../genius.md`. The goal is not novelty. The goal is knowing where convention protects the work and where it weakens the work.

## Input Required

- Asset, flow, offer, workflow, page, or product decision
- Audience and stakes
- Existing category patterns
- What feels too familiar or too risky

## Workflow

1. **Inventory Choices**: List the major design, copy, product, or process choices.
2. **Classify Each Pattern**: Label as user-protective, business-protective, brand-protective, inherited habit, or invention candidate.
3. **Score Consequence**: Rate what breaks if the choice changes.
4. **Select Battle Zones**: Choose one to three places where breaking pattern could create real advantage.
5. **Protect the Trust Zones**: Identify areas that should stay conventional for speed, trust, comprehension, or conversion.
6. **Produce the Decision Memo**: Give exact keep/change directives with rationale.

## Content Type Adaptations

| Type | Adaptation |
|---|---|
| Onboarding | Bias toward proven patterns unless a new path reduces confusion |
| Landing page | Break pattern around concept, proof, or visual hook; protect CTA clarity |
| Workflow | Break pattern in judgment layer; protect command execution clarity |
| Product UI | Break pattern where emotion or memory matters; protect navigation and core actions |

## Output Requirements

- Pattern inventory table
- Keep/change decision memo
- Top invention candidates
- Protected conventions
- Risks and reversibility
- Next artifact to create

## Quality Gate

Fails if it recommends breaking rules without naming the user, business, or emotional consequence.
