## Role & Activation

You are working in Nicolas Cole's nonfiction value architecture: "This skill makes nonfiction pieces valuable before sentence-level editing begins" (SKILL.md). This is the flagship build — a complete, drafting-ready outline assembled from spotlight selection, specificity, supporting modes, and skim-path discipline in one pass, per Hidden Knowledge: "The outline is not a container for the draft. It is the value proof."

## Input Required

- `[AUDIENCE]`
- `[TOPIC]`
- `[FORMAT]` — newsletter / LinkedIn post / long article / YouTube script / lead magnet
- `[READER'S CURRENT PROBLEM]` — if the audience is broad, define this before outlining
- `[EXISTING MATERIAL]` — optional: notes, prior drafts, source transcript

## Execution Protocol

1. **Define the reader's current state and desired state.** The outline exists to move the reader from one to the other.

2. **Choose the spotlight value mode** from the ten (tips, stats, steps, lessons, benefits, reasons, mistakes, examples, questions, story) — see genius.md's Ten Nonfiction Value Modes table for what each delivers and when to use it. One mode leads (Spotlight Discipline).

3. **Build the list of primary deliverables** — the actual tips, steps, mistakes, or reasons, not category placeholders (List-Level Architecture: "the list is the first product; prose is packaging").

4. **Run the Specificity Ladder on each deliverable** — flag bundled terms (love, push, accountability, consistency, mindset, discipline, authenticity, trust, authority, confidence, value, quality), ask "what does this look like in a literal moment," and add a measurable standard where possible.

5. **Add supporting modes where useful**, using this exact mapping:
   - Stat → strengthens belief
   - Example → creates pattern recognition
   - Question → creates self-diagnosis
   - Story → creates confidence

6. **Create title options** that clearly promise the value — not vague topic labels.

7. **Create subheads that act as receipts for the title** — apply the Subhead Skim Test logic: each subhead must survive a four-second skim as proof of the title's promise, not just a related label.

8. **Add draft notes under each subhead**: what to say, what not to say, and what proof/example/question to include.

### Content Type Adaptations

| Type | Adaptation |
|---|---|
| Newsletter | Include intro promise, 3-5 value sections, and closing reader action |
| LinkedIn post | Compress to hook, 3-5 points, and final implication |
| Long article | Include sections, examples, and transitions |
| YouTube script | Include cold open, promise, beats, and retention questions |
| Lead magnet | Include checklist/tool/template shape |

## Output Contract

- Reader state map (current state → desired state)
- Spotlight value mode with the value promise statement
- Title options (3-5)
- Full value-first outline — ordered sections/subheads, each traceable to the spotlight or a named supporting mode
- Specific subheads (post-skim-test quality, not generic labels)
- Support-mode notes (which subheads carry a stat/example/question/story, and why)
- Drafting brief per subhead: say / don't say / proof-to-include

## Output Skeleton

```
READER STATE MAP:
Current state: [where the reader is now]
Desired state: [where this piece takes them]

SPOTLIGHT MODE: [mode]
VALUE PROMISE: "The reader gets [mode] that help them [outcome]."

TITLE OPTIONS:
1. [title]
2. [title]
3. [title]

OUTLINE:
[Intro / cold open — promise stated]

Section 1: [subhead — specific, receipt-tested]
  Supporting mode: [stat/example/question/story, or "none"]
  Draft brief — Say: [ ] | Don't say: [ ] | Proof to include: [ ]

Section 2: [subhead]
  Supporting mode: [ ]
  Draft brief — Say: [ ] | Don't say: [ ] | Proof to include: [ ]

...

[Closing — reader action or implication]
```

## Quality Gate

- Applying the workflow's own fail condition — "The outline must be useful before the body is written. If the subheads do not already give value, revise the outline" — does every subhead pass this on its own?
- Is every section traceable to the spotlight mode or a named, deliberately chosen supporting mode (nothing floating unattached)?
- Does no subhead simply restate the title in different words?
- Does every section carry a drafting brief (no orphan sections without say/don't-say/proof notes)?

## Creative Latitude

This is where architecture becomes taste. The choice of which supporting mode strengthens which subhead, the ordering of sections for narrative pull (not just logical sequence), and the title options are genuine creative decisions — commit to the strongest structure rather than hedging across several safe options. Favor the outline that would make a skimming reader stop scrolling, even when it departs from the most obvious or symmetrical section breakdown.

## Deploy When

A full outline is needed for a newsletter, article, LinkedIn post, script, or lead magnet before drafting begins — the standard "build the whole thing" entry point for a topic that already has (or has just been given) a clear reader problem.
