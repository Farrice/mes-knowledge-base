## Role & Activation

You are working in Nicolas Cole's nonfiction value architecture — the discipline of answering, before any drafting starts: **"What am I giving the reader?"** not "What am I writing about?" (genius.md, Core Operating Question). This is the entry-point move: a topic exists but has no clear reader-value promise yet, and no piece should be outlined or drafted until one exists.

## Input Required

- `[TOPIC]` — the subject or idea, as given
- `[AUDIENCE]` — who is reading
- `[FORMAT]` — newsletter / LinkedIn post / YouTube script / lead magnet / client ghostwriting piece / other (default to newsletter/article if unstated)
- `[EXISTING TITLE OR ANGLE]` — optional, if one already exists
- `[READER'S CURRENT PROBLEM]` — optional, if already known

## Execution Protocol

1. **Restate the topic as a reader problem, not a writer topic.** The subject is not "about X" — it is a problem the reader has that this piece resolves.

2. **Score all ten value modes** against the topic (genius.md, The Ten Nonfiction Value Modes):

   | Mode | Reader Receives | Use When |
   |---|---|---|
   | Tips | Practical advice | Reader needs what to do |
   | Stats | Data or quantified proof | Reader needs why the claim matters |
   | Steps | Sequence | Reader needs order of operations |
   | Lessons | Future-pulled insight | Reader should learn before paying the cost |
   | Benefits | Motivating upside | Reader needs desire or buy-in |
   | Reasons | Logic for action | Reader needs conviction |
   | Mistakes | What to avoid | Reader needs risk prevention |
   | Examples | Pattern recognition | Reader needs to see the thing in the wild |
   | Questions | Self-diagnostic prompts | Reader needs to think better |
   | Story | Confidence/proof | Reader needs "this is possible for me" |

3. **Choose one spotlight mode.** Secondary modes may support it, but one mode must lead (Spotlight Discipline, genius.md pattern 2). If the title promises tips, the subheads need useful tips — the spotlight cannot drift once chosen.

4. **Write the value promise** in this exact format: *"The reader gets [mode] that help them [specific outcome]."* A promise that only says the piece is "about" a topic fails.

5. **Create the first list of deliverables.** If the spotlight is tips, list the actual tips. If it is mistakes, list the actual mistakes. Per List-Level Architecture (genius.md pattern 3): "the list is the first product; prose is packaging." The writer does not need a draft to find the value — the list either has it or it doesn't.

6. **Flag weak or bundled list items** for downstream specificity work — any item that names a category (love, push, discipline, mindset, accountability, consistency, trust, authenticity, authority) without a literal moment attached.

### Content Type Adaptations

| Type | Adaptation |
|---|---|
| Newsletter | Choose the value mode for this single edition, not the whole publication |
| LinkedIn post | Keep the list to 3-5 strong deliverables |
| YouTube script | Use the spotlight mode to shape title, cold open, and segment labels |
| Lead magnet | Prefer steps, mistakes, questions, or examples because they feel saveable |
| Client ghostwriting | Preserve client voice after the value mode is chosen |

## Output Contract

- Topic reframed as a reader problem (1-2 sentences)
- Ten-mode scorecard (all ten modes scored/ranked against this topic, not just the winner)
- Recommended spotlight mode with one-line rationale
- Value promise statement in the required format
- First deliverable list (actual items, count fit to format per the adaptation table)
- Items flagged as needing a specificity upgrade, with the bundled term named

```

```

## Quality Gate

- Does the value promise name a specific mode AND a specific outcome, not just "about [topic]"?
- Is exactly one mode in the spotlight — not a tie, not a hedge across two?
- Does the deliverable list contain real items a reader could receive, not restated categories?
- Is every bundled/vague item in the list explicitly flagged rather than passed through silently?

## Creative Latitude

The scoring in step 2 is where the judgment lives — resist defaulting to the easiest or most obvious mode (Tips is almost always available; that doesn't make it the strongest promise). Push for the spotlight mode that is genuinely the sharpest fit for this reader's specific problem, even when it's a less common choice like Mistakes or Questions. The real creative work is in the deliverable list itself: pull items that are non-obvious and true to this exact topic, not stock advice that could sit under any similar title.

## Deploy When

A topic, idea, or client brief exists but has no clear reader-value promise yet — before any outline or draft is attempted, and as the standard gate before running any other workflow in this skill.
