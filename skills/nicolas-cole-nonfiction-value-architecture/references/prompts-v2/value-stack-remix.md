## Role & Activation

You are working in Nicolas Cole's nonfiction value architecture, applying Secondary Value Stacking (genius.md, pattern 10): "Once the primary value is clear, other modes can deepen it. A tip can be supported by a stat, made easier with steps, clarified with an example, challenged with a question, and made credible with a story." This deliverable strengthens a piece whose primary value is already set but that still feels thin, under-proven, or not saveable enough.

## Input Required

- `[OUTLINE OR DRAFT WITH A CONFIRMED PRIMARY VALUE MODE]`
- `[WHERE IT FEELS THIN]` — if known
- `[FORMAT]` — newsletter / LinkedIn post / long article / YouTube script / lead magnet

**Pre-flight gate:** if the primary value mode is not yet confirmed, this is not the right entry point — run Value Spotlight Map first.

## Execution Protocol

1. **Confirm the spotlight value mode** as already established for this piece.

2. **Diagnose where the piece feels thin**, using this exact six-way mapping:
   - Needs belief → add stats or reasons
   - Needs action → add steps or tips
   - Needs clarity → add examples
   - Needs self-application → add questions
   - Needs confidence → add story
   - Needs risk protection → add mistakes

3. **Add only the secondary modes that strengthen the primary promise.** This is not a checklist to fill — pick the gaps that are real.

4. **Place the secondary modes inside the outline** without changing the main promise.

5. **Remove secondary additions that create a different article** — anything that pulls focus away from the spotlight rather than deepening it.

6. **Produce a cleaner value stack** — the minimum reinforcement that closes the diagnosed gaps.

### Content Type Adaptations

| Type | Adaptation |
|---|---|
| Newsletter | Keep secondary modes short so the edition stays focused |
| LinkedIn post | Use one secondary mode, usually example or question |
| Long article | Use secondary modes as subsections |
| YouTube script | Use secondary modes as retention beats |
| Lead magnet | Use secondary modes as worksheets, examples, or checklists |

## Output Contract

- Primary mode confirmation
- Weakness diagnosis — which of the six gaps apply, and exactly where in the piece
- Recommended secondary modes — mapped 1:1 to a diagnosed gap, not a grab-bag of extras
- Revised outline with stack notes — where each secondary mode slots in and why
- Cuts list — anything removed because it competed with the primary promise rather than compounding it

## Output Skeleton

```
PRIMARY MODE (confirmed): [mode]

WEAKNESS DIAGNOSIS:
- Location: [section/point] — Gap: [needs belief/action/clarity/self-application/confidence/risk protection]

RECOMMENDED SECONDARY MODES:
- Gap: [gap] → Secondary mode: [stat/steps/example/question/story/mistakes] — Where it goes: [location]
...

REVISED OUTLINE WITH STACK NOTES:
[Spotlight mode: X]
- [subhead 1] — Secondary mode added: [ ] or [none]
- [subhead 2] — Secondary mode added: [ ] or [none]
...

CUTS LIST:
- [item removed] — Why: [competed with primary promise / created a different article]
```

## Quality Gate

- Applying the workflow's own fail condition verbatim — "Secondary modes must compound the spotlight. If they compete with it, cut them" — does every kept addition pass this test?
- Does every recommended secondary mode trace to a specific diagnosed weakness (no mode added without a stated reason)?
- Is the primary promise unchanged after the remix (same value promise statement holds)?
- Is the cuts list non-empty whenever the audit actually surfaced competing content — was anything genuinely cut, or was this a rubber-stamp pass?

## Creative Latitude

The art here is restraint. Not every diagnosed thin spot needs reinforcement — some brevity is intentional. Recommend the minimum secondary modes that genuinely compound the spotlight rather than stacking all six reinforcement types just because the framework makes them available. When two secondary-mode options could close the same gap, choose the one that adds the least length for the most conviction.

## Deploy When

The primary value mode is already set (confirmed via Value Spotlight Map or an existing outline) but the piece still reads thin, under-proven, or unlikely to be saved/shared as-is.
