# Workflow 10: Consulting-to-SaaS Productization Path

> When you've done enough audits to see repeating patterns, productize them into a platform.

## Prerequisites
- **Load**: [genius.md](../genius.md)
- **Input Required**: Minimum 5-10 completed consulting engagements, pattern documentation
- **Best Stacked With**: @soowei (leverage architecture), @daniel-priestley (Oversubscribed)
- **NOT for beginners**: This is a Phase 3+ workflow. Complete 10+ audits first.

## Produces
1. Pattern recognition analysis across completed engagements
2. Productization opportunity assessment
3. MVP specification for the repeating-problem solution
4. Market validation framework
5. Transition plan from consulting to consulting + product

---

## Step 1: Pattern Mining

```
CROSS-ENGAGEMENT PATTERN ANALYSIS

Review all completed audits. What problems appear in 60%+ of clients?

| Pattern | Frequency | Industries Affected | Current Solution | Avg. Annual Waste |
|---------|-----------|-------------------|-----------------|-------------------|
| [Repeating problem 1] | [X/Y clients] | [List] | [What you built each time] | $[X] |
| [Repeating problem 2] | [X/Y clients] | [List] | [What you built each time] | $[X] |
...

TOP PRODUCTIZATION CANDIDATES:
Patterns that appear in 60%+ of engagements AND have similar solutions
each time are your best candidates. You're currently rebuilding the
same solution from scratch — that's the signal.

Andrew's insight: "The third career path... if you see that 300 of
your clients have the same problem, you can build a platform."
```

## Step 3: MVP Specification

```
MINIMUM VIABLE PRODUCT SPEC

PROBLEM: [The repeating problem in one sentence]
SOLUTION: [What you've been building custom — now productized]
TARGET USER: [Who uses this, role title + company size]

CORE FEATURES (V1):
1. [Feature that solves the primary pain point]
2. [Feature that replaces the most manual work]
3. [Feature that generates the measurable ROI]

NOT IN V1 (intentionally):
- [Feature that's nice-to-have but adds complexity]
- [Feature that only 20% of clients need]

PRICING MODEL:
- Based on value delivered (not cost of building)
- Monthly SaaS: $[X]/month (should be <10% of annual savings delivered)
- Annual discount: $[X]/year

VALIDATION BEFORE BUILDING:
- Pre-sell to 5 existing consulting clients
- If 3+ say yes with money committed → build
- If fewer than 3 → the pattern isn't strong enough yet
```

---

## Step 4: Transition Architecture

```
CONSULTING + PRODUCT HYBRID MODEL

DON'T stop consulting. Layer the product on top.

PHASE A: CONSULTING ONLY (Months 1-12)
- Deliver custom audits and implementations
- Document every engagement meticulously
- Track repeating patterns

PHASE B: CONSULTING + PATTERN PRODUCTS (Months 12-24)
- Continue consulting at same rate
- Build productized solution for highest-frequency pattern
- Offer to consulting clients first (beta users)
- Revenue: Consulting $X + Product $Y

PHASE C: PRODUCT-LED + ADVISORY (Months 24+)
- Product handles the repeating problems at scale
- Consulting reserved for complex/custom engagements
- Premium advisory for product users who need custom help
- Revenue: Product $X (growing) + Advisory $Y (high-margin)

EXIT POTENTIAL:
- Consulting firm: 1-3x annual revenue
- SaaS company: 5-15x annual revenue (if growing)
- This is why Andrew calls it "the most valuable career path"
```

## Quality Gate

- [ ] Minimum 5 completed engagements analyzed for patterns
- [ ] Pattern appears in 60%+ of clients (not an edge case)
- [ ] Productization scorecard completed with evidence
- [ ] MVP spec includes ONLY features that 80%+ of clients need
- [ ] Validation plan requires pre-sales before building
- [ ] Transition plan maintains consulting revenue while building product
- [ ] Pricing model based on value delivered (not cost)
