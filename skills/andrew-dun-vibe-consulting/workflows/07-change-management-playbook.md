# Workflow 07: Change Management & Adoption Playbook

> Ensure implementations don't "collect dust" — the #1 reason AI projects fail.

## Prerequisites
- **Load**: [genius.md](../genius.md)
- **Input Required**: Implementation plan from Workflow 04, team structure, current adoption challenges

## Produces
1. AI Champion identification and empowerment plan
2. Workforce resistance assessment
3. Training and upskilling program
4. Adoption metrics and monitoring dashboard
5. Intervention triggers for declining adoption

## Step 2: Resistance Assessment

```
TEAM RESISTANCE MAP

| Team Member | Role | Attitude Toward AI | Specific Concerns | Resistance Level |
|------------|------|-------------------|-------------------|-----------------|
| | | [Enthusiastic/Open/Skeptical/Resistant] | [Job security/complexity/etc.] | [1-5] |

RESISTANCE PATTERNS:
- "This will replace my job" → Counter: "This replaces the robot parts of
  your job so you can do the human parts that actually matter"
- "I've always done it this way" → Counter: Show the TIME savings in their
  day, not the company's money savings
- "This is too complicated" → Counter: Solar company voice note example —
  meet people where they are, don't force new behaviors

HIGH-RESISTANCE INDIVIDUALS:
- [Name]: [Strategy to bring them in]
- [Name]: [Strategy to bring them in]

REMEMBER: "Don't try to force a square peg into a round hole."
Design solutions that fit existing behavior patterns.
```

## Step 3: Training Program Design

```
TRAINING ARCHITECTURE

PHASE 1: AWARENESS (Week 1)
- All-hands presentation: "Here's what we found and what we're changing"
- Focus on THEIR benefits (less tedious work), not company metrics
- Champion introduces the initiative (peer credibility)

PHASE 2: HANDS-ON (Weeks 2-3)
- Small group training (5-8 people max)
- Live demonstrations with THEIR actual data
- Practice sessions with immediate feedback
- "Office hours" for questions

PHASE 3: SUPPORTED ADOPTION (Weeks 4-6)
- Go live with new processes
- Daily check-ins during first week
- Buddy system (pair adopters with resisters)
- Quick-fix support channel (Slack/Teams)

PHASE 4: INDEPENDENCE (Months 2-3)
- Reduce check-in frequency to weekly
- Monitor adoption metrics
- Celebrate early wins publicly
- Address remaining holdouts individually
```

## Step 4: Adoption Monitoring

```
ADOPTION METRICS DASHBOARD

| Metric | Target | Week 1 | Week 2 | Week 4 | Month 2 | Month 3 |
|--------|--------|--------|--------|--------|---------|---------|
| Active users (% of team) | 90%+ | | | | | |
| Daily usage rate | 80%+ | | | | | |
| Error/support tickets | Declining | | | | | |
| Time savings realized | Per ROI calc | | | | | |
| User satisfaction (1-5) | 4+ | | | | | |

INTERVENTION TRIGGERS:
- Active users < 60% by Week 4 → Champion escalation + individual coaching
- Daily usage < 50% by Month 2 → Process redesign (maybe the solution doesn't fit)
- Satisfaction < 3 → Gather feedback, adjust training approach
- Support tickets increasing → Technical quality issue, escalate to partner
```

## Quality Gate

- [ ] AI Champion identified with sufficient authority and personal interest
- [ ] Resistance map shows every team member's attitude and concerns
- [ ] Training program includes hands-on practice, not just presentations
- [ ] Adoption metrics defined with specific intervention triggers
- [ ] Solutions designed to fit existing behaviors (not force new ones)
- [ ] Champion has private briefing and escalation channel
