# Root, Not Symptom (Andrew Stanton)
Every test audience told Stanton the same thing about Marlin: too neurotic, recast the father. Acting on that note would have wrecked the film. The real wound was upstream — the audience never earned empathy for him — and one prologue dissolved a dozen scattered complaints at once. This workflow takes a pile of notes and finds the *one* move that makes most of them disappear, so you don't change the wrong thing for the wrong reasons.

## Input Required
- The work under review (draft, post, reel, page, deck, ad — whatever the notes are about)
- The full pile of feedback, verbatim where possible — every note, including the contradictory and the half-formed
- For each note, what was *observed* vs. what the giver *prescribed* (e.g. "I got bored at the middle" vs. "cut the middle section")
- Any behavioral signal you have, separate from stated opinion (drop-off point, where they re-read, where they laughed, where they bounced)
- The premise-sentence and spine from Pre-Flight — the felt note often points back at one of them

## Workflow

### Step 1: Inventory the Notes as Symptoms, Not Fixes
A note is a reading of a wound. The prescribed fix is the giver guessing at surgery they aren't qualified to do. Split every piece of feedback into the *felt symptom* (real, trust it) and the *prescribed fix* (usually wrong, set it aside). On *Nemo*, the felt symptom was "I don't like this father." The prescribed fix was "recast him." The symptom was true; the fix would have changed the wrong thing.

| Raw note (verbatim) | Felt symptom (what they actually experienced) | Prescribed fix (set aside) |
|---|---|---|
| | | |
| | | |
| | | |

Strip every fix into the right-hand column and stop looking at it for now. Work only from the middle column.

### Step 2: Trust the Felt Note, Distrust the Stated Opinion
Now weight the symptoms by *behavior*, not by volume or confidence. What people did with the work outranks what they said about it — they can perform an opinion in the Q&A but they can't fake leaning forward, or fake checking their phone at minute four. Where stated opinion and behavior disagree, behavior wins. Where a note is loud but the behavior contradicts it, demote it. Where a quiet note matches a real drop-off, promote it.

| Felt symptom | Behavioral evidence (drop-off, re-read, bounce, laugh) | Stated confidence | Weight: HIGH / MED / LOW |
|---|---|---|---|
| | | | |
| | | | |

Cluster the surviving HIGH/MED symptoms. You're looking for a constellation — several notes that, squinted at, are all complaining about the *same* underlying thing from different angles. "The dad is annoying," "I didn't care when he lost Nemo," "the act-three rescue felt unearned" are three notes and one wound.

### Step 3: Find the One Upstream Move That Dissolves the Cluster
Now ask the *Nemo* question: what single change, as far upstream as possible, would make most of these symptoms vanish *without you touching them directly*? Not a fix per note. One move that resets the conditions the notes grew out of. The prologue wasn't a patch on any one complaint — it was an upstream cause that made the downstream symptoms irrelevant.

Trace the cluster back through the premise-sentence and the spine. The root almost always lives there: a premise the audience can't feel, a spine that never got established, a change that wasn't earned. Test candidate roots against the cluster:

| Candidate upstream move | Symptoms it would dissolve | Symptoms it leaves untouched |
|---|---|---|
| (e.g. "open with the loss instead of revealing it in flashback") | | |
| | | |

The winning root is the one whose left column swallows the cluster and whose right column is short. If your best candidate only fixes one note, you're still treating a symptom — keep digging upstream. And distrust your own flinch here: if the right move feels too dark, too big, too embarrassing, that resistance is rarely taste, it's fear — note it and keep it on the table.

### Step 4: Test It Cheaply Before Rewriting Everything
Do not rebuild the whole piece on a hypothesis. The reason Pixar tried the prologue at all was that the cost of trying dropped to nothing: *"it's just a file, we don't have to show anybody."* Make the smallest possible version of the root move, in a throwaway copy, and check it against the cluster before committing.

- Spin a disposable copy. Apply only the root move, nothing else.
- Re-walk the original cluster against the new version: how many symptoms are gone *without* having edited those spots?
- If the cluster collapses, the root is confirmed — now do the real rewrite. If it doesn't, the root is wrong; back to Step 3 with what you learned.
- Keep the test unwitnessed and reversible so your flinch has nothing to defend.

## Content Type Adaptations
| Format | Adaptation |
|--------|-----------|
| Screenplay / film / video | Cluster the reel notes; the root is usually a structural reorder (front-load a beat, relocate a reveal), not a line fix. Test on a "just a file" cut — re-time one sequence, screen it small, watch behavior in the dark before re-boarding anything. |
| Long-form essay / Substack | Notes like "lost me in the middle," "didn't trust the claim," "felt long" usually trace to one upstream root: the premise the piece is actually arguing was never made felt up top. Test by rewriting only the opening 150 words; re-read the flagged sections untouched. |
| Short-form social (LinkedIn / X / Reels) | The whole post is one beat, so the root is almost always the hook or the first line, not the body. A pile of "didn't land," "scrolled past," "so what" collapses to: the opening didn't clamp. Test = swap the hook only, A/B the first line, watch dwell/save behavior over comments. |
| Sales / marketing copy | "Confusing," "didn't convert," "felt pushy" rarely fix per-line. Root is upstream: the offer's spine — what the reader gets and why it's inevitable — was never established, so every downstream objection is a symptom. Test by rewriting the lead/promise only and re-reading the body against it. |
| Brand / campaign | Scattered stakeholder notes across assets ("off-brand," "doesn't feel like us," "the ad's clever but hollow") usually trace to one root: the brand's central conflict/spine isn't expressed. Fix the spine in one anchor asset, test reactions to that alone before touching the system. |

## Quality Gate
> **🛡️ Anti-Pattern Check**: review against genius.md § Anti-Patterns + § Expert-Specific Quality Rubric. Flag and fix before delivering.
- Every prescribed fix was parked before diagnosis; the diagnosis works only from felt symptoms, never from the surgery the note-giver guessed at (Pattern 7).
- The chosen root is genuinely *upstream* — it dissolves a cluster of symptoms without editing them directly. If the "root" only repairs one note, it's still a symptom; reject it.
- Behavior outranked stated opinion at least once: a loud note got demoted, or a quiet note got promoted, on behavioral evidence (Pattern 6).
- The root was tested cheaply and reversibly before any full rewrite; you did not rebuild the piece on an unverified hypothesis (HK-3).
- You can name the specific wrong thing you avoided changing — the *Nemo* "recast the father" of this brief — and what it would have cost.

## Common Pitfalls
- **Acting on the prescribed fix.** The notes are real but the proposed surgery is the giver's guess; doing it changes the wrong thing for the wrong reasons. Recovery: park every fix in its own column and diagnose only from felt symptoms.
- **Patching symptom by symptom.** Fixing each note where it lands leaves the wound intact and the work death-by-a-thousand-edits. Recovery: cluster the notes and find the one upstream move that makes most of them vanish untouched.
- **Obeying your own flinch as if it were taste.** Resistance to the bold root move usually reads internally as a quality signal but is just fear of the dark/expensive/embarrassing version. Recovery: keep the move on the table and lower the cost of testing it until the flinch has nothing to protect.
- **Committing to a full rebuild on an unverified root.** Rewriting everything on a hypothesis is how a diagnosis becomes an expensive mistake. Recovery: make the smallest disposable version, re-check the cluster against it, and only then commit.
