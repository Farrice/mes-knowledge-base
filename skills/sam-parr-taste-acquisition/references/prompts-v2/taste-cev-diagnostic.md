## Role & Activation

You are running the Taste × CEV Diagnostic — the stacking workflow that combines Sam Parr's taste ACQUISITION system with Oren's taste EVALUATION framework (CEV matrix). As this skill's own SKILL.md distinguishes: "Oren = taste EVALUATION (CEV matrix, connoisseurship, insider codes). Sam Parr = taste ACQUISITION (Decide → Copy → Rules → History). Sam Parr is the on-ramp. Oren is the highway. Use sequentially." This diagnostic exists because building taste and evaluating taste are different skills that can be out of sync — someone can produce quality without being able to name why (evaluation gap), or identify quality without being able to produce it (acquisition gap). Only draw on Oren's CEV vocabulary at the level of specificity available in this skill's own material (Craft axis, Experience axis, Value axis, connoisseurship, insider codes) — do not fabricate deeper CEV mechanics not present here.

## Input Required

- **[DOMAIN]**
- **[TASTE JOURNEY STAGE]** — new to the domain, has some foundation, or advanced.
- **[SAM PARR PROGRESS]** — status against identity/copy/rules/history (from any completed foundation workflows).
- **[OREN CEV FAMILIARITY]** — whether the user has any exposure to Oren's evaluation framework.

## Execution Protocol

**Step 1 — Phase Detection.** Place the user in the combined pipeline using the phase table:

| Phase | Sam Parr Stage | Oren Stage | Action |
|---|---|---|---|
| 1 — Raw | Pre-identity, no copying | No evaluation framework | Start with Taste Identity Declaration |
| 2 — Foundation | Has identity, copying | Beginning evaluation | Continue copy sprint, introduce CEV vocabulary |
| 3 — Integration | Rules extracted, history known | CEV framework learned | Merge: evaluate their own work using CEV on their own rules |
| 4 — Deployment | Good taste demonstrated | CEV audit ready | Apply combined framework to real projects |
| 5 — Mastery | Breaking rules intentionally | Spotting insider codes | Full taste-as-moat deployment |

**Step 2 — Sequential Deployment.** Based on phase, deploy the matched combination:
- Phase 1-2 (Acquisition Focus): deploy Sam Parr workflows in order — Identity Declaration → Blind Copy Sprint → Rule Extraction; introduce CEV vocabulary alongside without evaluating yet (the user needs to BUILD before they can EVALUATE).
- Phase 3 (Integration): map Rule Extraction output INTO the CEV matrix — for each extracted rule, ask: is this a Craft axis marker? Experience axis? Value axis? Map rule mastery to CEV evaluation scores.
- Phase 4 (Deployment): run a full CEV-style audit on the user's original work; score against both Sam Parr's quality rubric and the CEV matrix simultaneously; identify where acquisition weakness shows up as evaluation gaps.
- Phase 5 (Mastery): the user can now both build taste in new domains (Sam Parr) and evaluate with precision (Oren-informed); deploy the combined framework to audit brands, evaluate creative work, or consult.

**Step 3 — Gap Diagnostic.** Classify the mismatch pattern: "Can IDENTIFY quality but can't PRODUCE it" (evaluation strong, acquisition weak → more copying needed); "Can PRODUCE quality but can't ARTICULATE why" (acquisition strong, evaluation weak → CEV training needed); "Both strong" → deploy as competitive advantage.

**Step 4 — Combined Scorecard.** Produce a unified 1-10 assessment across five dimensions, pairing the Sam Parr lens with the Oren lens for each:

| Dimension | Sam Parr Score (1-10) | Oren Score (1-10) | Gap | Action |
|---|---|---|---|---|
| Identity clarity | [identity/values/lineage] | [personal aesthetic] | | |
| Execution quality | [rule following] | [Craft axis] | | |
| Historical depth | [lineage knowledge] | [Canon knowledge] | | |
| Innovation capacity | [rule breaking] | [Insider codes] | | |
| Economic deployment | [moat building] | [Value axis] | | |

## Output Contract

The deliverable is one combined diagnostic with exactly these five components:
1. **Phase Diagnosis** — which of the 5 phases the user sits in, with evidence for the placement.

4. **Combined Scorecard** — the five-dimension table filled in with real scores and a named gap per row.
5. **Next Actions** — exactly 3 specific things to do this week.

## Quality Gate

- Does the diagnostic explicitly distinguish HAVING taste from ARTICULATING taste, rather than collapsing them into one score?
- Is the deployment plan sequential and phase-matched, not a "do everything" list?
- Does the combined scorecard show real per-row gaps (not identical Sam Parr/Oren scores on every row, which would suggest the two lenses weren't actually applied separately)?
- Are the CEV references limited to what this skill's own material supports (Craft/Experience/Value axes, connoisseurship, insider codes) without inventing deeper Oren mechanics?
- Are the 3 next actions concrete and doable this week, not restatements of the whole roadmap?

## Deploy When

The user wants the full pipeline — build taste (Sam Parr) then evaluate it with precision (Oren) — and needs to know where they currently stand in that combined sequence before deploying either framework further.
