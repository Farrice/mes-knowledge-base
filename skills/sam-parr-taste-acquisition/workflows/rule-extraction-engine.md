# Rule Extraction Engine

After copying, you can FEEL quality but can't ARTICULATE it. This workflow converts texture into named, sourceable rules. The rules become the constraint field for good taste.

## Pre-Flight Gate

- User should have completed `/taste-copy` (30-day blind copy sprint) or similar copying exercise
- Read `genius.md` — focus on Pattern 9 (History-as-Constraints), Pattern 10 (Good-to-Great Progression Gate), Hidden Knowledge: Gutenberg Typography Lineage
- User must provide: Their texture journal or notes from copying sessions

## Skill Acquisition


## Execution

### Step 1: Pattern Mining
Review all copying notes, texture journals, and exemplar libraries. Identify recurring patterns:
- What structural elements appear in every high-quality exemplar?
- What proportions, ratios, or relationships feel "right"?
- What elements are ABSENT in quality work that amateurs include?
- What do the "bad" versions of these violate?

### Step 2: Rule Naming
For each pattern, create a named rule with three components:
1. **The Rule**: One-sentence statement ("Headlines in this domain are never longer than 8 words")
2. **The Evidence**: Which exemplars demonstrated this ("All 15 sites used max 8-word headlines")
3. **The History**: Where this rule came from ("Newspaper headline conventions from the 1920s linotype constraints")

Aim for 10-15 rules per domain.

### Step 3: Rule Categorization
Sort rules into Sam Parr's framework:
- **Structural Rules** — layout, proportion, hierarchy (the skeleton)
- **Material Rules** — materials, textures, typefaces, instruments (what it's made of)
- **Tonal Rules** — mood, energy, emotional register (how it feels)
- **Cultural Rules** — traditions, conventions, insider signals (what community it belongs to)

### Step 4: Rule Testing
For each major rule, test with a counter-example:
- Find one highly-regarded work that BREAKS this rule
- Explain WHY breaking it works in that specific case
- This builds the foundation for the good → great gate

### Step 5: Constraint Field Map
Produce the visual map of all rules as a constraint field:
- Rules that are NON-NEGOTIABLE (violating these = bad taste)
- Rules that are STANDARD (following these = good taste)
- Rules that are BREAKABLE (violating these with mastery = great taste)

### Step 6: Reference Sourcing
For each rule, find the authoritative source:
- Book, designer, movement, or historical period that codified it
- This is the reading list for `/taste-lineage` and the authority base for future work

## Output Requirements

1. **Rule Inventory** — 10-15 named rules with evidence and history
2. **Category Map** — Rules sorted into Structural/Material/Tonal/Cultural
3. **Counter-Examples** — 3-5 rule-breaking successes with WHY analysis
4. **Constraint Field** — Non-negotiable / Standard / Breakable classification
5. **Reading List** — 5-10 authoritative sources for the rules' origins

## Quality Gate

Reference genius.md quality rubric:
- **Score 4**: Can say "this looks good" but not why
- **Score 7**: Names 3-5 specific rules with evidence
- **Score 10**: Explains the historical origin of each rule and when breaking it is justified
- **Minimum to pass**: Score 7. If the user can't name rules, they need more copy reps.
