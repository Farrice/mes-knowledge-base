# Sean Macintyre × Luke Iha — Armor-Matched Proof Ladder

## Role

You are running a stack: Sean's awareness-armor diagnostic feeds Luke Iha's proof ladder construction. Standard proof ladders apply a generic "weak proof → strong proof" sequence regardless of audience. The Sean-stack adds armor-state matching: a State-2 (Defended) audience's proof needs differ structurally from a State-3 (Apathetic) audience's. Same product, same testimonials available — but different ladders.

The stack produces proof that *closes the specific resistance pattern* of the audience, not just proof that's "high quality" abstractly.

**Before executing**:
1. Read `genius.md` § "Genius Pattern 1: Awareness-Armor Diagnostic"
2. Read `references/awareness-armor-map.md`
3. Run Workflow 01 first to establish audience state
4. Load Luke Iha's proof ladder skill (`skills/luke-iha-*`) for the standard ladder framework

## Input Required

1. **Audience State Output** (from Workflow 01): State 1 / 2 / 3 + sub-state
2. **Available Proof Inventory**: Testimonials, case studies, data, expert endorsements, results, regulatory clearances, awards, client lists, etc.
3. **Product / Offer**: What's being sold
4. **Copy Context**: Where does this proof ladder sit? (Sales page, VSL, email, ad, etc.)
5. **Sophistication Level** (Schwartz 1-5 — see `references/awareness-armor-map.md` for mapping)

> **Pre-Flight Gate**: Workflow 01 must be complete. State-blind proof ladders default to "throw all the proof in" which fails on State-2 and State-3 audiences. The state determines structure.

## Workflow

### Phase 1: Resistance Pattern Map (per audience state)

Before selecting proof, name the *specific resistance pattern* the audience deploys against proof:

#### State 1 (Problem-Aware)
- **Resistance pattern**: minimal. Reader is shopping; proof reduces last-mile friction.
- **Implication**: proof ladder is short. 2-3 rungs. Heavy guarantee, minimal convincing.

#### State 2 (Defended)
Sub-state-specific resistance:
- **Burned-defended**: "I've been promised this before and got burned." Resistance against unverifiable claims.
- **Identity-defended**: "Solution implies I should change, which threatens self-concept." Resistance against transformation framing.
- **Sophistication-defended**: "I've heard every version of this." Resistance against familiar proof types.
- **Status-defended**: "If this works, I'm not as advanced as I think." Resistance against beginner-positioned proof.

#### State 3 (Apathetic)
Sub-state-specific resistance:
- **Saturation-apathetic**: "I tune out everything in this category." Resistance against typical category conventions.
- **Category-apathetic**: "This whole category is bullshit." Resistance against any category-internal proof.
- **Trust-apathetic**: "Everyone here is a scammer." Resistance against any high-energy claim.
- **Energy-apathetic**: "I don't have bandwidth to evaluate." Resistance against requiring evaluation.

### Phase 2: Proof-Type-to-Resistance Matching

Map proof types to the resistance pattern they best dissolve:

| Proof type | Best for | Why |
|---|---|---|
| **Specific named-customer case study** | Burned-defended | Verifiable; customer can be reverse-searched, dissolves "I've been burned" |
| **Mechanism-explained-by-third-party-authority** | Sophistication-defended | Outside expert verifies the mechanism survives digging |
| **Identity-affirming testimonial** ("I'm the kind of person who…") | Identity-defended | Lets reader keep self-concept while accepting the solution |
| **Advanced-customer quote** ("I knew everything until I found this") | Status-defended | Makes the proof status-flattering rather than status-threatening |
| **Anti-pattern testimonial** ("I tuned out 100 of these ads, then…") | Saturation-apathetic | Mirrors the reader's apathy and shows it being broken |
| **Outside-the-category proof** (e.g., NYT mention for an info product) | Category-apathetic | Comes from outside the distrusted ecosystem |
| **Specific numbers + boring presentation** | Trust-apathetic | Anti-hype framing; proof in a register the reader trusts |
| **Single overwhelming proof + low evaluation cost** | Energy-apathetic | Doesn't require the reader to weigh multiple inputs |
| **Standard testimonials, results, guarantee** | Problem-aware (State 1) | Reduces last-mile friction without overinvesting |

### Phase 3: Ladder Construction

Build the ladder using Luke Iha's standard ladder structure (rung 1 lowest stakes → rung 5 highest stakes), but populate each rung with proof selected via Phase 2 matching.

#### State 1 ladder (3 rungs):
1. Single strong testimonial or result
2. Guarantee / risk reversal
3. Authority signal or credential

#### State 2 ladder (5 rungs):
1. **Anti-hype opening**: signal of category awareness ("I know what you're thinking — another [category] promise")
2. **Sophistication-respecting proof**: proof that acknowledges the audience's sophistication
3. **Mechanism dig-survivor**: proof that the mechanism holds up to research (paired with Workflow 02)
4. **Identity-affirming case**: testimonial from someone the reader can identify with
5. **Risk reversal that respects intelligence**: not a desperate guarantee, but a structurally-sensible one

#### State 3 ladder (5-7 rungs, with state transition):
1. **Pattern-violation hook**: proof presented in a format the reader doesn't expect (anti-ad)
2. **Outside-category authority**: proof from outside the distrusted ecosystem
3. **Anti-pattern testimonial**: someone who shared the apathy and broke through
4. **Specific quantified result**: precise numbers in a low-energy register
5. **State transition signal**: language indicating the reader has moved from State 3 to State 2 (e.g., "if you've read this far, you're already on the other side of apathy")
6. **State-2 proof rung** (sophistication-respecting; matches Phase 4 of State 2 ladder above)
7. **Final low-evaluation-cost ask**: minimal-decision close

### Phase 4: Iha Layer Application

For each rung, apply Luke Iha's standard proof construction (intensity calibration, visual / format choices, sequencing logic). The Sean stack determines *what* proof goes on each rung; Iha determines *how* the proof is rendered.

Reference Iha's `proof-ladder-builder` workflow for the construction layer.

### Phase 5: Three-Vector Verification

Score each rung — and the ladder as a whole — on the three-vector standard:

| Vector | Question per rung |
|---|---|
| Emotional | Does this rung produce a specific emotional movement (relief, recognition, validation)? |
| Intellectual | Does this rung's proof survive dig-testing? |
| Personal | Does this rung speak to *this specific reader*, not a generic reader? |

## WHAT MATTHEW SEES

The standard proof ladder approach is "stack everything." Testimonials, case studies, guarantees, badges, reviews — pile them on, hoping the volume convinces. This works on State-1 audiences because they're already shopping; the volume is reassurance.

On State-2 audiences, volume reads as desperation. On State-3 audiences, the entire stack is noise — they're not evaluating, they're tuning out. The standard ladder gets ignored.

Sean's diagnostic, applied to proof: *"There's nothing in [generic copy frameworks] that really helps you reach an audience that has an armor around them."* The proof has to be *selected for the resistance pattern*. The Iha ladder is the structure; the Sean diagnostic is what fills it.

## Content Type Adaptations

| Content type | Adaptation |
|---|---|
| **Sales page** | Full 5-7 rung ladder; rungs become page sections |
| **VSL** | Compress to 4-5 audio rungs; State 3 transition is critical for retention through middle of video |
| **Cold ad** | Single rung — the strongest single proof asset matched to the predicted ad audience state |
| **Email sequence** | One rung per email; sequence mirrors the ladder; State transition happens mid-sequence |
| **Long-form thought leadership** | Ladder embedded in narrative — proof rungs are the demonstrable receipts |
