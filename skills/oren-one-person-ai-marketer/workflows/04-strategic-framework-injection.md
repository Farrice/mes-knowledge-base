## Workflow

### Phase 1: Stock the Library (the 1-page named-framework menu)
Produce a single page that lives inside the brand-voice Project as substrate block four. Do not write essays on persuasion theory. Write a routing menu.

1. **Select 3–5 REAL established frameworks** that match the brand's actual deliverable mix. Direct response is mandatory (Oren names it explicitly). Stock the rest from the partner skills, not from invention — candidates: Problem-Agitate-Solve, AIDA, the Awareness-Stage Ladder (Schwartz five stages), a proof-ladder structure, a mechanism-led structure.
2. **For each framework, write exactly four lines** in the library entry — no more:
   - **Name** (the literal label the prompt will say out loud: "direct-response").
   - **Architecture** (the ordered moves: e.g. direct-response = *lead with the persona's dominant emotion → agitate the cost of inaction → present the product as the mechanism → close with risk-reversal*).
   - **Fits when** (the message-type / awareness-stage trigger that routes a message here).
   - **Tell** (the one structural marker that proves the framework actually fired in the output — if you can't point to it, it didn't fire).
3. **Paste the page into the Project instructions** as block four, beneath positioning, personas, and voice samples. The leverage is the persistent substrate, not the prompt. If you find yourself re-typing a framework per chat, the library has degraded and the leverage is gone.

### Phase 2: Build the Selection Rubric (message-type → architecture)
This is the non-delegable artifact — the operator's whole contribution is here. Produce a one-screen table that maps each input to the framework it requires.

1. **Build the routing table** with columns: `Message (from monthly list)` · `Awareness stage` · `Dominant emotion (persona)` · `Selected framework` · `Why this one (1 line)`.
2. **Route every message on this month's list** through the table. The weekly copy task is now a routing decision, not a writing task: *"this month's hero message is awareness-stage → Awareness-Stage Ladder; the retargeting message is product-aware + frustration → direct-response."*
3. **Flag the mismatches.** Where no framework cleanly fits a message, that is the signal to either reframe the message or add a real framework to the library — never force an ill-fitting architecture, because a mis-selected framework is the failure the harness is built to catch.

### Phase 3: Write the Naming Prompt Pattern (selection → execution)
Produce the exact, copy-pasteable prompt skeleton the operator runs inside the Project for every Class A deliverable. It must NAME the architecture — refusing "write me a version of X" is the entire point.

1. **Write the skeleton verbatim**, with slots:
   > *"Write the [deliverable] for [persona] using the [NAMED framework] structure: [paste the framework's ordered moves]. Lead with [persona's dominant emotion]. Apply [voice reference]. Carry this month's [message]. Output must hit the framework's tell: [the structural marker from the library]."*
2. **Produce 2–3 filled examples** from this month's actual routing table so the operator sees the pattern executed on real messages, not a template.
3. **Hardcode the ban.** Append the rule to the prompt pattern: *no naked "write a version" requests ever leave the Project.* The named framework is a quality gradient; drop the name and the output snaps back to the model's homogenized default.

### Phase 4: Run the A/B Harness (the falsifiable proof)
Produce a repeatable test that proves the framework lifted conversion — or proves the operator mis-selected. This is what makes the whole protocol falsifiable instead of faith-based.

1. **Generate the matched pair** on the one live brief: Version A = the same brief with the named framework and its ordered moves; Version B = the identical brief pasted naked ("write me an ad for X"). Same persona, same message, same voice reference — the only variable is the named architecture.
2. **Ship both into the same Class A surface** (an ad set split, two landing-page variants, an email A/B) and read the result in the capped Performance block per Workflow 09 — never eyeball it.
3. **Apply the verdict rule, written into the harness:**
   - Framework-injected version measurably outperforms → the framework was correctly selected; promote it as the default route for that message-type and log it in the rubric.
   - Framework-injected version does NOT outperform → **the framework was MIS-SELECTED. This is a taste failure (wrong selection), not an AI failure (bad execution).** Re-route the message to a different architecture in the library and re-run. Do not blame the model; the model executed exactly what you named.
4. **Log the win.** Every confirmed-winning message-type → framework pairing becomes a hardened entry in the selection rubric, so next month's routing is faster and the library compounds.

## AI Leverage × Taste Gate  (THE dual requirement — non-negotiable)
- **AI Leverage**: Frameworks are how a non-copywriter borrows a copywriter's brain through AI. The model already "knows" direct response and the established architectures — so the solo operator's job collapses from composition to recognition. You never have to write the framework cold; you only NAME the right one. One operator becomes a framework-literate copy department, and the named architecture is a quality gradient that pulls every output off the homogenized midbaseline toward a high-conversion form. *"It will improve your copy versus just saving you time and actually make it so it's built for marketing conversion."*
- **Taste Gate**: Never prompt "write me an ad for X." The operator supplies SELECTION (which architecture fits this message — non-delegable); AI supplies EXECUTION. The falsifiable check is the A/B harness: run the same brief with vs. without a named framework, and if the framework-injected copy does not measurably outperform, the framework was MIS-SELECTED — a taste failure, not an AI failure. The model did exactly what it was told; the operator named the wrong architecture.

## Quality Gate
1. **Library reality check** — every framework in the library is a REAL established copywriting architecture (direct response confirmed present); zero invented or AI-named "frameworks." A fabricated framework fails the gate outright.
2. **Selection is explicit** — the rubric routes every message on this month's list to a named architecture with a stated reason; no message ships through a naked "write a version" prompt.
3. **The naming prompt names the architecture** — the prompt pattern literally states the framework and its ordered moves and demands the output hit the framework's tell; the "no naked version" ban is hardcoded.
4. **The harness is falsifiable and correctly attributes failure** — the A/B is a true matched pair (only the named framework varies), runs in a real Class A surface, and its verdict rule classifies any non-improvement as a SELECTION (taste) failure, not an execution (AI) failure.
5. **Both halves present** — the deliverable carries BOTH the AI-leverage mechanic (model executes named architecture the operator couldn't write cold) AND the taste gate (operator owns non-delegable selection, A/B proves it). Either half missing = fail.
