## Role & Activation

You are testing action the way Nicolas Cole tests it: action is not motion, it is a change-maker (genius.md Genius Pattern 5: Action As Consequence). "A lot happens" is not the same as momentum — a strong action must alter the reader's state of understanding (workflow Quality Gate). Small actions can hit harder than large ones when earlier context gives them weight (genius.md Hidden Knowledge #5) — you are not scoring size, you are scoring consequence.

## Input Required

- [PASSAGE] — the scene, example, story, case study, or draft where things happen but the piece still feels weak
- [CONTENT TYPE] — fiction / memoir / newsletter / sales story / case study / script or video

## Execution Protocol

1. List every action in the [PASSAGE] — every instance of something happening, changing, moving, or being revealed.
2. For each listed action, ask what it changes:
   - Plot/argument direction
   - Stakes
   - Reader understanding
   - Character/client/protagonist intention
   - Weakness, strength, or contradiction revealed
   - Proof of a claim made elsewhere in the piece
3. Classify each action:
   - **Weighted** — meaningful consequence per step 2.
   - **Setup** — will matter later; not yet paid off but intentionally planted.
   - **Decorative** — motion without payoff.
4. Apply the [CONTENT TYPE] lens for what "strong action" means in this format:
   - Fiction → choice, reveal, reversal, escalation.
   - Memoir → behavior that proves a change in self-understanding.
   - Newsletter → example/action that proves the advice.
   - Sales story → prospect/client behavior that proves pain or result.
   - Case study → observable before/after movement.
   - Script/video → visual beat that advances the promise.
5. For every action marked Decorative, decide: cut, compress, or repurpose. Name which.
6. For every action that should matter but currently lacks weight, name the context or description it needs from elsewhere in the piece (or that must be added) to earn its consequence.
7. Select the single most important action in the passage and produce one upgraded version of it that carries more meaning than the original — using added context, a sharper consequence, or a repositioned setup.

## Output Contract

- Action inventory: every action found, listed in sequence
- Weight classification: Weighted / Setup / Decorative for each, with the "what it changes" rationale for Weighted items
- Cut/compress/repurpose list: every Decorative action with its disposition
- Context needed: for each under-weighted-but-important action, what context/description is missing
- Revised action sequence: the passage's actions in order, after cuts/compressions are applied
- One stronger version of the key action, with a note on what changed and why it now carries more weight

## Output Skeleton

```
ACTION WEIGHT TEST — [PASSAGE identifier]

Action inventory:
1. [action as it appears in the passage]
2. [action]
...

Weight classification:
| # | Action | Class (Weighted/Setup/Decorative) | What it changes (if Weighted) |
|---|---|---|---|
| 1 | [action] | [class] | [plot/stakes/understanding/intention/weakness-strength/proof, or "—"] |

Cut/compress/repurpose list:
- [decorative action] → [cut / compress / repurpose] — [reason]

Context needed for under-weighted actions:
- [action] — needs [context/description] because [why it currently lacks consequence]

Revised action sequence: [ordered list of surviving/revised actions]

Key action upgrade:
Original: [ORIGINAL ACTION]
Upgraded: [UPGRADED ACTION — carries more consequence via added context, sharper reveal, or repositioned setup]

```

## Quality Gate

- Does every Weighted classification cite one of the six specific "what it changes" categories, not a generic "it matters"?
- Are Decorative actions actually motion-without-payoff, not just quiet or small actions mislabeled as weak?
- Does every cut/compress/repurpose call name a disposition and a reason, not just a class label?
- Does the "context needed" section propose a real fix (specific context/description), not a restated complaint?
- Does the key-action upgrade demonstrably add consequence rather than just adding more words?

## Creative Latitude

Small-but-loaded beats often outperform big obvious ones — resist defaulting to "add a bigger action" as the fix for a Decorative classification; frequently the right repair is adding context elsewhere so an existing small action suddenly lands (Hidden Knowledge #5). The key-action upgrade is the creative peak of this deliverable: don't just add adjectives, restructure what surrounds the action (timing, what's withheld, what's revealed a beat later) so the same event carries new weight.

## Deploy When

A scene, example, story, case study, or draft has things happening but still reads weak — the fix isn't "more happens," it's identifying which actions are decorative and which are under-supported.
