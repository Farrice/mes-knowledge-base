## 1. What lifting means concretely

Plugin Forge takes an existing skill, prompt-set, or workflow family and emits one installable Claude Code plugin: `.claude-plugin/plugin.json` (name, semver, description) + `commands/*.md` (workflows become slash commands) + `skills/<name>/SKILL.md` (skills carry over with references/) + optional `hooks/hooks.json`, with all intra-plugin paths on `${CLAUDE_PLUGIN_ROOT}`. Output lands in a repo-local `plugins/` directory and installs from local path only.

Toolchain is entirely existing machinery:

| Step | Owner (already in repo/harness) |
|---|---|
| Readiness gate | `execution/plugin_readiness_audit.py` + `verify_plugin_readiness_stdout.py` |
| Structure + validation | plugin-dev skills; `plugin-dev:plugin-validator` agent |
| Prompt/contract audit | `execution/renaissance_audit.py` (0 fail) |
| Portability drift | `execution/platform_compiler.py` pattern (core markdown harness-neutral, wiring in thin outer layer) |
| Spine | F0–F7 unchanged; F5 PROVE is exactly this cold-start plan |

The lift adds zero new engines. It authorizes running the packaging step the toolchain was built for.

## 2. Cold-start proof plan (must pass BEFORE any packaging is considered proven)

Four fixtures, one per class the standing decision names. Protocol per fixture: build the candidate plugin in a scratch directory, install local-only, open a **fresh session**, run the five operator-core checks (direct invocation, natural-language trigger, missing-info behavior, `${CLAUDE_PLUGIN_ROOT}` resolution, fresh-session), diff output shape against the artifact's existing golden fixture, uninstall, confirm clean teardown. All local, $0 paid APIs, ~15 min each.

| Fixture | Input | Pass condition (deterministic) |
|---|---|---|
| **F-REV** (revenue) | One revenue-lane workflow command (e.g., a `/copy-engine` sub-workflow) packaged as `commands/` | Fresh session: `/command` fires; output matches the workflow's Output Contract skeleton section-for-section vs the repo-native golden run |
| **F-CRE** (creative) | One forge-os prompts-v2 prompt packaged inside a plugin skill | Fresh session: skill auto-triggers from a natural-language ask; output passes its Quality Gate + `prose_classifier.py check` |
| **F-SYS** (system) | One hook + helper script in `hooks/hooks.json` | Hook registers and fires on its event; script echoes a resolved `${CLAUDE_PLUGIN_ROOT}` path; `plugin-dev:plugin-validator` returns 0 errors |
| **F-REG** (regression) | The repo itself, after F-REV–F-SYS install/uninstall | `git status` clean; repo-native `/command` still routes to `.agent/workflows/` (no shadowing); `renaissance_audit.py` 0 fail; golden-fixture replay of the source artifacts byte-shape identical |

Gate rule: all four pass in one run, or the boundary stays. Partial passes do not accumulate across sessions.

## 3. Risks with eyes open

| Risk | Failure looks like | Guardrail |
|---|---|---|
| Global-scope pollution | Plugin lands in `~/.claude`, leaks into every project | Local-path install only; F-REG teardown check; standing "no global writes without explicit ask" stays binding post-lift |
| Marketplace exposure | Internal IP (extractions, client voice) published | Out of scope entirely: "no plugin marketplace edits" survives any lift; marketplace needs a separate explicit decision |
| Version drift vs repo originals | Plugin copy fossilizes while the repo skill evolves | Repo is the single source of truth; plugins are regenerated by the build step, never hand-edited; semver bump + golden-fixture compliance replay on each rebuild |
| Portability lock-in | Claude-specific wiring leaks into methodology core | Portability Spine enforced: contract core stays plain markdown; harness wiring isolated in the layer `platform_compiler.py` already manages |

## 4. Decision framing

- **Lift now (full):** unlocks marketplace too. Rejected framing; exposure risk is the one irreversible item.
- **Lift partially — local-only plugins, no marketplace, gated on Section 2 passing:** authorizes packaging with every failure reversible (uninstall + clean git).
- **Keep deferred:** costs nothing today; leaves a built, validated toolchain idle and the operator-core route (`plugin-readiness-audit`) dead-ended.

**Recommendation: lift partially — local-only, no marketplace, effective only when all four fixtures pass in a single run.** Strongest reason: the entire packaging and validation toolchain already exists and sits idle; the fixtures convert the standing condition into one cheap deterministic checklist, and local-only scope keeps every possible failure reversible.
