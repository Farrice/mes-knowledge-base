# Cheri Tree B.A.N.K. Buyology - Genius Context

## How to Use This Skill (Model Calibration)

The four codes are intuition primitives, not a checklist to recite. Absorb the values, motives, and clues for Blueprint, Action, Nurturing, and Knowledge, then diagnose and translate — never announce the machinery on the page. If a deliverable opens with "this is a Blueprint buyer, so here are some Blueprint-style bullet points," that is reciting B.A.N.K. vocabulary, not doing B.A.N.K. work. The test: would Cheri Tree recognize this as a code-aware asset built for a real, observed prospect, or as generic sales copy with a code label bolted on afterward? If it reads like the second, rebuild from the values and clues, not from the label.

Specifically:
- Do NOT open a deliverable by naming the diagnosed code before the asset has earned it — lead with the evidence (dress, pace, punctuality, data requests, warmth), name the code once for internal reference, then let the asset do the work without re-announcing it.
- Do NOT write four "variants" that only swap an adjective per code. Each code needs a distinct proof type, sequence, and sales posture: Blueprint gets risk-reduction and process, Action gets speed and status, Nurturing gets relationship and mission, Knowledge gets data and defensible reasoning. Same-shape copy with a synonym swapped is the skill's own named failure mode (see Anti-Patterns below).
- Texture: Tree's method is forensic and behavioral, not psychographic or poetic. Clues are observable — punctuality, dress, pace, data requests — not vibes or astrology-style typing. Stay concrete and checkable; a code call with no cited clue is a guess wearing a diagnosis costume.
- Polish is the tell-class warning here: a beautifully written four-way translation that never once references an actual observed clue, a real objection, or a specific trigger from `references/bank-code-field-guide.md` is decoration, not B.A.N.K. work. Ground every deliverable in at least one concrete clue or trigger from the field guide before it ships.

## Core Genius

Cheri Tree's method turns selling from a single-script guessing game into buyer-code translation. A prospect does not buy because the seller explained harder. The prospect buys when the offer is presented in the sequence, evidence, emotional frame, and risk profile that matches the prospect's dominant buying values.

The system is built on four buying codes — stated in the skill's own source notes as "the four B.A.N.K. types: Blueprint, Action, Nurturing, Knowledge" (`references/source-notes.md`, committed 2026-07-02; sourced from the codex-harvest extraction dated 2026-06-11):

- **Blueprint**: buys safety, order, proof, process, budget control, and risk reduction.
- **Action**: buys speed, status, opportunity, excitement, freedom, and winning.
- **Nurturing**: buys trust, care, purpose, belonging, ethics, and human connection.
- **Knowledge**: buys logic, data, accuracy, expertise, due diligence, and certainty.

## Genius Patterns

1. **Code Before Pitch**: Do not present until the buyer's dominant value order is known or strongly inferred.
2. **Values Beat Demographics**: Age, income, title, and industry are secondary. Buying behavior follows value hierarchy.
3. **One Offer, Four Doorways**: The same offer can be entered through risk reduction, status gain, mission fit, or logical certainty.
4. **Sequence Creates Meaning**: In Power Scripting, the same proof points feel different depending on whether credibility, emotion, or logic comes first.
5. **Objection as Code Mismatch**: Many objections signal that the seller used the wrong code language, not that the offer is weak.
6. **Ask When Possible, Infer When Necessary**: Direct card sorting or intake is strongest. Forensic coding is the backup when direct coding is impossible.
7. **Segment the Funnel, Not Just the List**: B.A.N.K. data should change landing pages, opt-ins, emails, calls, CRM tags, and proof assets.
8. **Weakest Code Becomes Blind Spot**: The seller's lowest code often causes the most lost sales because those buyers feel unseen.
9. **Closeable Sales Need Translation**: The method does not force bad fit. It improves odds when a sale is closeable and the buyer's values are honored.
10. **Human Motive Under Business Action**: Every B.A.N.K. asset must connect business outcomes to the buyer's deeper motive: safety, victory, love, or rightness.

## Signature Moves

- **Sort the Values**: Present the four value sets and have the person rank them from most to least like them.
- **Spot the First Clue**: Punctuality, flash, warmth, or data hunger often reveals the dominant code before the pitch begins.
- **Translate the Same Claim Four Ways**: Reframe one value proposition for B, A, N, and K before deploying it.
- **Pre-Load the Missing Proof**: Send documentation to K, risk safeguards to B, social proof/status cues to A, and mission/community proof to N.
- **BANKify the System**: Store code in the CRM and let it drive routing, emails, sales prep, and follow-up — the skill's own hidden-knowledge notes put the stakes plainly: "If code insights stay in the seller's head, they disappear. If code is stored and routed, the whole business can send better messages." (`references/hidden-knowledge.md`, "CRM Is Where B.A.N.K. Becomes Compounding")

## Quality Rubric

| Criterion | Acceptable | Strong | Master-Level |
|---|---|---|---|
| Code accuracy | Names a likely code | Gives evidence and confidence | Separates dominant, secondary, and uncertainty with next test |
| Asset translation | Changes surface wording | Changes proof, CTA, and objections | Rebuilds the whole buyer path around code priorities |
| Practical output | Gives ideas | Produces deployable copy/assets | Produces a complete field-ready kit with tests and next actions |
| Ethical use | Avoids crude manipulation | Frames as service and fit | Protects buyer autonomy while increasing relevance |
| Multi-code handling | Picks one code | Handles primary and secondary | Creates segmented variants and routing rules |
| Evidence discipline | Makes broad claims | Grounds claims in observable cues | Shows cue, inference, counter-signal, and confidence |
| Entrepreneur fit | Generic sales advice | Maps to offer and audience | Maps to funnel, CRM, social, sales, and campaign calendar |

The rubric's ceiling is the field guide's own discipline: "A person's full code is an ordered stack, not a single label." (`references/bank-code-field-guide.md`, "Code Order") — master-level work always shows the stack, not just the top hit.

## Anti-Patterns

- Treating B.A.N.K. as a horoscope or fixed identity. *(Contradicts the field guide's Code Order note that a person's code is "an ordered stack, not a single label" — `references/bank-code-field-guide.md`, 2026-07-02.)*
- Using one code label with no evidence. *(Contradicts Genius Pattern 1, "Code Before Pitch": "A pitch delivered before code diagnosis is a guess." — `references/genius-patterns.md`, 2026-07-02.)*
- Writing four variants that only swap adjectives. *(Contradicts Signature Move "Translate the Same Claim Four Ways," which requires distinct proof per code, not a synonym swap — `references/bank-code-field-guide.md` + `references/genius-patterns.md`, 2026-07-02.)*
- Selling Action-style hype to Knowledge buyers. *(Knowledge's documented Avoid list names exactly this: "blanket statements, drama, excessive praise... speculation, shortcuts, unsubstantiated evidence." — `references/bank-code-field-guide.md`, "Knowledge," 2026-07-02.)*
- Selling Knowledge-style data dumps to Action buyers. *(Action's documented Avoid list: "boredom, budgets, details, instructions, limits, paperwork, waiting, routine, over-planning." — `references/bank-code-field-guide.md`, "Action," 2026-07-02.)*
- Making Nurturing buyers feel manipulated or rushed. *(Nurturing's documented Avoid list: "arguments, coldness, deceit, ego, greed, manipulation, rudeness, selling tactics, tension, unfairness." — `references/bank-code-field-guide.md`, "Nurturing," 2026-07-02.)*
- Making Blueprint buyers feel surprised, rushed, or exposed to risk. *(Blueprint's documented Avoid list: "chaos, delays, exaggeration, unclear instructions, surprises, missed deadlines, overspending, risk, rule breaking." — `references/bank-code-field-guide.md`, "Blueprint," 2026-07-02.)*
- Using code diagnosis to pressure people instead of serving their decision criteria. *(Contradicts Genius Pattern 10, "Translation Preserves Fit": "The method should help the right buyer understand the right offer. It should not pressure a poor-fit buyer into a bad decision." — `references/genius-patterns.md`, 2026-07-02.)*
