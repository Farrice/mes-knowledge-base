# The Fan Flywheel

Micro-moments #5-7 as one compounding system: customers write products → get featured → watch the brand show up every single week → become "raving fans" who buy "five, six, seven times" (claimed). This is the layer that turns the Factory Loop's transactions into membership. The flywheel's engine is rhythm: "Trust is rhythm. A brand is like a heartbeat. Nobody notices it until it stops" — and a broken rhythm quietly kills every other moment.

## Pre-Flight

1. `skills/meg-heckman-buyer-trigger-os/genius.md` — Trust Mechanics moments 5-7 + trust-layer operating notes, Exemplar 6 ("Need your help" email)
2. Customer evidence on hand: past replies, photos, reviews, UGC (or confirm none exists yet)

> **Pre-Flight Gate**: requires ≥1 real customer (a purchase, a reply, a follower who engages). Pre-launch brands route to `/meg-micro-moments` (moments 1-3 come first — the ladder runs in lifecycle order).

## Input Required

- Brand, sub-identity, named human signer
- Current state: reply volume, UGC on hand, last 5 customers reachable? drop cadence + last drop date
- One product/drop in motion to anchor the feature and the ask

## Workflow

### Step 1: FEATURE — Celebrate One Customer Properly
"You don't need 42,000 clips. You need one photo of one customer celebrated properly" (GoPro anchor — LIKELY). Build the "spotted" feature: real customer, named (with permission + thank-you), in the wild — the message is the CUSTOMER, product as set dressing. Plus the 5-customer photo-request DM and a review-flow tweak that rewards photos/video. Nielsen 92% peer-trust framing (LIKELY) available for client briefs.

Execution prompt: `references/prompts-v2/spotted-feature-pack.md`

### Step 2: BUILD RULE — The Co-Creation Loop Closes Here
Standing rule installed with the operator: every reply mined ("we mine the replies on purpose"); when one makes you laugh out loud → build it → send that customer one free → feature the origin story when it ships ("a customer literally wrote our product in one sentence completely for free"). IKEA effect: people fall in love with what they helped build (Lego Ideas royalty precedent — LIKELY).

### Step 3: RHYTHM — Never Skip a Week
Named drop day on the calendar. What ships weekly (design, email, feature — size declared irrelevant: "the size of the drop matters way less than the fact that it never misses"). The no-applause clause in writing: "some weeks the drop lands and nobody claps. But that doesn't matter. The drop happens anyways." 10-minute fallback version of the weekly artifact for overloaded weeks. Anchor for the client conversation: Costco's $1.50 hot dog since 1985 — "one unbroken promise being worth more than any campaign."

### Step 4: FLYWHEEL WIRE
Connect the three: features harvest photos → photos seed next features · replies seed products → product origins seed features · the weekly drop is the container all of it ships in. One operating row per week: [drop day] — [what ships] — [which customer gets celebrated] — [which reply is under build review].

## Content Type Adaptations

**POD/merch (core)**: as written. **Coaching**: feature = client-win spotlight (permissioned); build rule = programs from client questions; rhythm = weekly office hours that never move. **Newsletter**: feature = reader-reply-of-the-week; build rule = editions from reader questions; rhythm = send day is sacred. **Local business**: feature = customer-of-the-week on the counter and the feed; rhythm = the weekly special that never misses.

## Quality Gate

- Feature celebrates the CUSTOMER by name; product is set dressing (inverted = catalog with faces = fail)
- Build rule includes the free-product send and the origin-story feature
- Rhythm has a named day AND the written no-applause clause AND a fallback
- Lifecycle honored: no flywheel install on a zero-customer brand
- All claims labeled per ledger
