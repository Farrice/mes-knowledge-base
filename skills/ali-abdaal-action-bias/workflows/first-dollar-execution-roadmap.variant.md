## Workflow

### Phase 1: The "Prison" Diagnosis & Deconstruction
*Identify the mental friction preventing the first dollar.*
- **Identify the Block**: Categorize the user's delay as Offer Clarity, Audience Anxiety, or Launch Theater (building systems instead of shipping).
- **The Two-Way Door Reframe**: Classify the launch as a "Two-Way Door" decision—reversible, low-risk, and high-learning.
- **The Identity Shift**: Define the "First Dollar Goal" not as profit, but as the psychological transformation from "Aspiring" to "Entrepreneur."

### Phase 1.5: Diagnostic Action Sequencing (NEW — Evolution Layer)

*Classify every proposed action as SIGNAL or BUILD, then sequence signals before builds.*

Before designing the 30-day roadmap, map the **information dependency graph** — what you need to LEARN before you can BUILD correctly.

**Step 1: Action Classification**
Classify every action the user could take into two categories:
- **SIGNAL actions**: Produce learning, reveal market truth, test assumptions. Cost: time only. Examples: sending a DM to a potential buyer, posting a specific offer to see who responds, having 3 discovery calls, running a 48-hour flash offer.
- **BUILD actions**: Produce infrastructure, assets, systems. Cost: time + often money. Examples: designing a course curriculum, building a website, creating a content calendar, recording video modules.

**The Iron Rule**: SIGNAL actions always precede BUILD actions in the same domain. You never build what you haven't validated through signal.

**Step 2: Uncertainty Stack Ranking**
List the user's top 3-5 uncertainties in order of how much they would change the plan if resolved:
1. **Plan-Changing Uncertainty**: If the answer is different than assumed, EVERYTHING downstream changes. (e.g., "Will anyone pay for this?" — if no, nothing else matters.)
2. **Direction-Changing Uncertainty**: If the answer is different, the APPROACH changes but the goal stays. (e.g., "Which audience segment responds strongest?" — changes targeting, not the offer itself.)
3. **Optimization Uncertainty**: If the answer is different, a DETAIL changes. (e.g., "What price point converts best?" — changes pricing, not the business.)

**Step 3: Minimum Viable Signal (MVS) Design**
For each Plan-Changing Uncertainty, design the single cheapest action that produces a definitive answer:
- **Time limit**: Must be executable in under 2 hours
- **Cost limit**: $0 required, $20 max
- **Signal quality test**: "After this action, I will KNOW [specific thing] that I currently ASSUME"
- **Kill criteria**: Define what result would mean "stop — this path is wrong" vs. "proceed — this path has signal"

**Step 4: Dependency Mapping**
Draw the sequence: which signals must fire BEFORE which builds make sense?

```
MVS #1 (Will anyone pay?) 
  → IF YES → MVS #2 (Which segment?) 
    → IF [segment A] → BUILD: offer tailored to A
    → IF [segment B] → BUILD: offer tailored to B
  → IF NO → PIVOT: reframe offer or change audience
```

Each BUILD action now has a SIGNAL action that justifies it. No orphan builds — every piece of infrastructure traces back to a validated signal.

**Step 5: The Signal Calendar**
Reorganize the 30-day roadmap as SIGNAL-FIRST:
- **Days 1-3**: Execute all Plan-Changing MVS actions (the ones that could kill the entire plan)
- **Days 4-7**: Execute Direction-Changing signals (now that the plan is validated, find the right vector)
- **Days 8-14**: First BUILD sprint (building only what signals validated)
- **Days 15-21**: Deliver + collect Optimization signals from real buyers
- **Days 22-30**: Iterate builds based on buyer feedback signals

This replaces time-based sequencing with information-dependency sequencing. The calendar adapts to what you LEARN, not what day it is.

### Phase 2: The Minimum Viable Offer (MVO) Design
*Strip the expertise down to its most sellable, unscalable unit.*
- **The 80/20 Offer**: Identify the 20% of the user's knowledge that provides 80% of the value.
- **The "Embarrassingly Simple" Package**: Design an offer that requires zero infrastructure (e.g., a 60-minute diagnostic call, a 5-page PDF, a 1-week live cohort).
- **The No-Brainer Price**: Set a price high enough to be "real" but low enough to remove buyer friction (e.g., $50 - $250).

### Phase 3: The Rapid Experiment Architecture
*Convert the business idea into a scientific test.*
- **Core Hypothesis**: State exactly what we are testing (e.g., "Founders will pay $150 for a supply chain audit").
- **Success Metrics**: Define the "Validation Threshold" (e.g., 3 sales or 5 discovery calls).
- **The "Cheapest Viable Test"**: Design the experiment that costs $0 and takes <10 hours to run.

### Phase 4: The 30-Day Execution Roadmap
*A signal-sequenced, dependency-driven protocol for the first month.*

**NOTE**: This roadmap follows Phase 1.5's Diagnostic Action Sequencing. Every action traces back to a signal that validated it. The day ranges flex based on signal results — if a Plan-Changing signal fires negative on Day 2, the pivot happens immediately rather than on "schedule."

#### Days 1-3: Plan-Changing Signals (Existence Proof)
- **Day 1**: Warm Network Mapping. Identify 20 "Tier 1" contacts. Send 5 "Would you pay for X?" messages (NOT sales — pure signal collection).
- **Day 2**: Analyze responses. Score: 3+ "yes/tell me more" = proceed. 0-2 = reframe offer before continuing.
- **Day 3**: If proceed: run 2 discovery calls with strongest responders. Extract: exact language they use, price they'd pay, urgency level. If pivot: redesign MVO using Day 2 feedback, re-test with 5 new contacts.

#### Days 4-7: Direction-Changing Signals (Vector Finding)
- **Days 4-5**: The "Non-Salesy" Outreach to remaining Tier 1 contacts, using EXACT language from Day 3 discovery calls (not your assumptions — their words).
- **Day 6**: Score segment response rates. Which group responded fastest? Which used the most urgent language? That's your beachhead segment.
- **Day 7**: First Close attempt. Secure one paid engagement or one "Letter of Intent." This is the final signal: will someone actually transact?

#### Days 8-14: First BUILD Sprint (Signal-Validated Only)
- Build ONLY what Day 1-7 signals validated. If discovery calls revealed they want a PDF guide, don't build a course. If they want live coaching, don't build a self-paced product.
- **The Content Paralysis Breaker**: Shift from "Creating Masterpieces" to "Documenting the Process."
- **The 5-Post Sequence**: Generate 5 specific posts (The Origin, The Mistake, The Framework, The Case Study, The Offer) — using buyer language from signals, not your own assumptions.
- **Platform Strategy**: Focus on ONE platform where signal responders already congregate.

#### Days 15-30: The Delivery + Optimization Signal Loop
- **Days 15-21**: Execute the MVO for the first buyer. During delivery, collect optimization signals: What surprised them? What did they value most? What would they pay more for?
- **Days 22-25**: Extract the exact language the buyer uses to describe their transformation (not their problem — their AFTER state).
- **Days 26-30**: The Pivot/Scale Decision — informed by ACTUAL delivery data, not hypothetical planning:
  - Signal says "double down" → raise price, expand to adjacent segment
  - Signal says "pivot niche" → same offer, different audience
  - Signal says "pivot offer" → same audience, different package

### Phase 5: The MVP Tech Stack (Anti-Complexity)
*Eliminate "Procrastination via Tool-Selection."*
- **Hosting**: Google Drive, Notion, or a simple Carrd page.
- **Payment**: Stripe/PayPal link or Gumroad. No checkout funnels.
- **Delivery**: Zoom, Email, or a shared folder.
- **The "Good Enough" Checklist**: If it takes more than 30 minutes to set up, it's too complex for V1.

### Phase 6: The Math of Inaction
*Calculate the cost of waiting vs. the cost of the experiment.*
- **Opportunity Cost**: Calculate the revenue lost by delaying 6 months.
- **Learning ROI**: Compare 100 hours of "research" vs. 10 hours of "market contact." Frame using Phase 1.5: 10 hours of SIGNAL actions produce more certainty than 100 hours of BUILD actions done blind.

## Quality Gate
1.  **The Simplicity Test**: Is the MVO deliverable within 48 hours of a sale?
2.  **The Friction Check**: Does the plan require building a website or "growing a following" before asking for money? (If yes, reject and simplify).
3.  **The Action Ratio**: Does the roadmap prioritize "Market Contact" (outreach/posting) over "Internal Prep" (design/planning) at a 4:1 ratio?
4.  **The Signal-Before-Build Test (NEW)**: Does every BUILD action trace back to a specific SIGNAL action that validated it? Are there any orphan builds (infrastructure built on assumptions rather than market data)?
5.  **The Dependency Test (NEW)**: Are Plan-Changing uncertainties resolved in the first 3 days, BEFORE any significant building begins? Would a negative signal on Day 2 trigger an immediate pivot rather than continuing to Day 14 on autopilot?
6.  **The Ali Voice**: Does it sound like a supportive but no-nonsense mentor who values "Done > Perfect"?
7.  **The Two-Way Door**: Are all proposed actions reversible and low-financial-risk?
