# /compliant-rewrite — Convert Flagged Copy Without Losing the Sale

Take copy flagged by `/claim-audit` (or drafted fresh) and rewrite it using the compliant-but-converting patterns (genius.md GP-07). The goal is never "hedge until it's safe" — it's "get more specific until it's both safe and more persuasive than the disease-claim version."

## Pre-Flight Gate

**Use this when**:
- `/claim-audit` returned hard-stops or net-impression flags that need fixing
- A brand's existing copy is legally risky but the underlying selling point (ingredient, mechanism, experience) is real and worth keeping
- Copywriting is being drafted from scratch for a claim-sensitive category (weight management, sleep, cognitive, joint, hormone/testosterone)

**Do NOT use this when**:
- No audit has been run yet on existing copy — run `/claim-audit` first so you know exactly what's flagged and why
- The claim in question needs an evidence check, not a rewrite — first confirm via `/claim-substantiation-map` whether ANY compliant version of the claim is supportable at all
- You're generating hooks from a blank page — use `/claim-safe-hooks`, which front-loads compliance into ideation rather than retrofitting it

## Skill Acquisition

Load before executing:
- `genius.md` — GP-07 (Compliant-But-Converting Rewrite Patterns), GP-01 (Taxonomy, to confirm the target bucket)
- `references/red-flag-word-bank.md` — full swap table

## Execution

### Step 1: Diagnose Before Rewriting (Anti-Uniform-Treatment Gate)

For each flagged unit, identify WHICH failure mode it is before choosing a fix — do not apply the same swap mechanically to every flag:
- **Disease-claim language** (Bucket 1/2) → apply GP-07 Move 1 (mechanism over outcome)
- **Outcome-guarantee language** → apply GP-07 Move 3 (social proof over guarantee) + Move 4 (realistic-expectation framing)
- **Disease-claim testimonial** → apply GP-07 Move 2 (review-language mining for emotion/experience, drop the disease-outcome framing even if it's a real quote)
- **Evidence-strength overclaim** ("clinically proven" without Tier-5 evidence) → downgrade to the accurate evidence-tier language (genius.md GP-02) — do not just delete the claim if a truthful, weaker version still sells

### Step 2: Rewrite Each Unit

For each unit, produce:
- **Original** (flagged version)
- **Rewrite** (compliant version)
- **Which GP-07 move was applied**
- **What was preserved** (the underlying selling point — mechanism, ingredient, real customer experience) vs. **what was cut** (only the non-compliant framing, never the substance if a compliant version exists)

### Step 3: Re-Run Net Impression on the Rewritten Piece

Rewriting unit-by-unit can still leave a net-impression failure if the pieces add up wrong (genius.md GP-03). Re-read the full rewritten piece as a skimming stranger before declaring it clean.

### Step 4: Two-Experts Test (genius.md GP-08)

For the finished rewrite, answer explicitly:
- Would a regulatory attorney sign off unchanged? [yes/no + why]
- Would a direct-response copywriter sign off unchanged (i.e., does it still convert)? [yes/no + why]

If either answer is no, revise again — a compliant rewrite that reads like compliance theater has failed the copywriter's half of the test, and ships flat, unpersuasive copy that doesn't actually serve the brand.

## Content Type Adaptations

| Content type | Rewrite priority | Watch for |
|---|---|---|
| **Weight-management copy** | Realistic-expectation framing (GP-07 Move 4) is mandatory — the FTC Gut Check (GP-09) auto-fails absolute claims regardless of rewrite quality | Don't rewrite an auto-fail claim into a softer version of the same false claim — cut it and rebuild the hook from a real mechanism |
| **Sleep/cognitive/mood copy** | Mechanism specificity (Move 1) tends to work best — these categories have real, tellable ingredient stories | Don't let "supports calm" become so vague it stops converting — pair with a specific mechanism detail |
| **Testimonial-heavy pages** | Review-language mining (Move 2) — extract the feeling, not the outcome-diagnosis | Re-verify the "typical result" disclosure requirement (GP-05) on every testimonial kept |
| **Amazon listings** | Also re-run against `references/platform-rules.md` Amazon section — token-level scanning catches things net-impression rewriting alone won't | A compliant rewrite can still contain a disease-name token in an unrelated clause |

## Output Requirements

1. Original + rewrite shown side by side for every flagged unit — never present only the rewrite (loses the audit trail)
2. Each rewrite names which GP-07 move was applied
3. Net impression re-checked on the full rewritten piece, not assumed clean from unit-level fixes
4. Two-experts test answered explicitly, not implied
5. If any claim cannot be made compliant while keeping any persuasive value, say so directly — do not force a rewrite that's technically compliant but so hedged it misrepresents what the audit actually found

## Quality Gate

Score against genius.md Quality Rubric criteria 1 (classification), 3 (net impression), 7 (two-experts), 8 (converts, not just survives) specifically:

- [ ] No rewritten unit still contains a disease claim (express or implied)
- [ ] Net impression re-verified on the finished piece
- [ ] Two-experts test answered for both roles, not skipped
- [ ] The rewrite is demonstrably MORE specific/credible than the flagged original, not just shorter or vaguer

If any check fails, revise the weakest unit and re-run Step 3-4 once before shipping as-is with the gap explicitly named.
