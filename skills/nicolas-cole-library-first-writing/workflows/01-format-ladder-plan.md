# Format Ladder Plan

## Input Required

- Raw idea or existing asset.
- Audience and intended outcome.
- Current proof state and permission limits.
- Available time and operator skill level.
- Current platform/account evidence, if distribution is part of the goal.
- Voice owner and publishing boundary.

## Execution

1. Build the library-unit card: claim, audience problem, mechanism, proof, story/example, reusable blocks, permissions, and open risk.
2. Stop if the core claim is unsupported and the requested asset would make it public. Route the proof gap first.
3. Classify the idea shape: sharp observation, compact lesson, visual/list process, nuanced anchor, or repeated task.
4. Name the operator's current rung and the one capability the next format should add.
5. Select one primary format. Treat platform reach as `UNTESTED` unless current or local evidence exists.
6. Add at most two derivatives, only when they perform different jobs.
7. Assign bounded craft handoffs and name the human checkpoint.
8. Define what language, proof, and performance data save back after use.

Execution prompt: `../references/prompts-v2/library-first-format-plan.md` — honor its Output Contract.

## Output Contract

Produce one Markdown plan containing:

- Library Unit Card.
- Primary Format Decision.
- Skill-Rung Rationale.
- Optional Derivatives, each with a distinct job.
- Conditional Handoffs.
- Human Checkpoint.
- Save-Back Rule.
- Evidence Status and Remaining Risk.

## Quality Gate

- The primary format follows from idea shape, operator rung, and outcome.
- No dated platform claim appears as timeless truth.
- Unsupported claims do not multiply.
- Derivatives are bounded and non-duplicative.
- The final step improves the library unit.
