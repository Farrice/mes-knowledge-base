# Nicolas Cole Library-First Writing

This skill turns ideas and existing assets into compounding library units. Its job is not to publish everywhere. It identifies what is worth preserving, chooses the smallest format that advances the operator's craft or business goal, and saves the improved material and evidence back for future reuse.

## Core Decisions

1. **Name the library unit first:** claim, audience problem, mechanism, proof, story, reusable blocks, permissions, and open risk.
2. **Choose the format by job:** compression, integrated practice, visual sequencing, nuanced expansion, or prompt harvesting.
3. **Move one useful rung:** do not force every idea through every format.
4. **Separate durable craft from dated distribution:** platform claims need current evidence or an `UNTESTED` label.
5. **Save back:** a finished asset must improve the underlying library unit, not become an orphaned post.
6. **Harvest prompts after proof:** articulate and test the manual process before turning it into an AI or product asset.

## Non-Negotiables

- Never turn platform rankings into permanent doctrine.
- Never multiply an unsupported claim across formats.
- Never call a prompt a product before the underlying process works and has an observable result.
- Never treat generated visual files as proof of taste or design quality.
- Never produce every format merely because the source lists five.
- Publishing, client delivery, and product/pricing actions still require approval.

## Quality Test

A strong run leaves behind an inspectable library unit, one justified primary format, at most two useful derivatives unless the user asks for a full pack, a named craft owner where needed, and a save-back rule. It must be usable without hidden chat context.
