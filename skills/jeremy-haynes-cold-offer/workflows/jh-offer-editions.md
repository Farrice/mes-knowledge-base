# /jh-offer-editions — Closer's Edition Kit

The Mastros move, productized: core offer stays clean for the majority buyer; contextual additions live in the closer's pocket, deployed only "where the offer is aligning to them and it makes sense." Some buyers won't close without the truffle butter; most just want the steak.

## Pre-Flight Gate

- A defined core offer must exist. No core → `/jh-offer-stack` first (editions strengthen a near-close; they can't rescue a misaligned core).
- Editions are NOT discounts. Price moves are a different lever — out of scope here.

## Skill Acquisition

- `genius.md` — pattern 7 (offer layers), pattern 8 (next-problem absorption), signature move "reserve the editions"
- `/jh-objection-mine` fragment slices if available (best edition source)

## Execution

1. **Source the editions**: from fragment-frequency objections, situational next-problems, and persona-specific circumstances (the Miami buyer needs the tit job; the five-kid buyer needs the construction-loan path; the staff-heavy buyer needs team logins).
2. **Map each edition**: name → buyer situation that reveals the need → the recognition cue (what the buyer says/asks that signals it) → the deployment line (exact sentence the closer says) → cost/margin note.
3. **Deployment rules**: editions fire only on commitment signals — "reaches a certain stage in the sales process where the offer is aligning to them." Never in the opening pitch, never as desperation sweeteners on a dead deal, never stacked (one edition per signal).
4. **Equip**: package as a one-page floor reference — situation → cue → line. Salespeople must be "equipped on" these in advance, not improvising.
5. **Feedback loop**: editions that fire in a majority of deals get flagged for promotion into core (back through `/jh-objection-mine` triage).

Execution prompt: references/prompts-v2/closer-editions-kit.md — honor its Output Contract.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Real estate | Editions = subcontractor network, landscaper, financing paths, architect intro |
| Coaching/info | Editions = 1-on-1 access tier, staff logins, extended support window, implementation sprint |
| SaaS | Editions = migration service, training seats, SLA tier — held for the commit-stage call |
| Self-serve (no closer) | Editions become checkout-stage conditional upsells triggered by qualification answers |

## Output Requirements

Edition Kit: edition table (name/situation/cue/line/cost), deployment rules block, promotion-watch list, one-page floor-reference version.

## Quality Gate

- Every edition tied to a real observed situation (not invented add-ons)
- Deployment lines written verbatim, natural spoken register
- No edition duplicates a core component
- Promotion loop defined
