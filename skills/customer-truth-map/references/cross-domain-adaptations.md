# Cross-Domain Adaptations — The Master Key

The method is universal; the *execution* is not. The six phases (Gather → Clean → Map → Jobs → Gaps →
Apply/Refresh) and the honesty spine never change. What changes is **where the unprompted language
lives, what shape the pains/gains take, and what "put the map to work" produces.** This file is the
translation layer: pick your vertical row, read across, and you have a deployment spec.

Load [`../genius.md`](../genius.md) first if not hot — it owns the *why* and the verbatim rule; this
file owns the *where it lands in each business.*

> Honesty spine, every cell: real language in, organized language out. Never fabricate a quote, a
> pain, or a source to fill a column. If a vertical genuinely has no unprompted talk in a channel,
> say so and use own-data (Hidden Knowledge #1) — don't invent one.

---

## How to read this file

1. Run the `../genius.md` Pre-Flight Decision Framework first (one customer / one problem cluster?
   own data we already hold? real sources named? verbatim armed? which output? fresh or stale?).
2. Find your vertical block in **Table A**. Read across: gather sources → richest-language location →
   pains/gains shape → how Apply changes.
3. Then use **Table B** to translate the six map categories into the specific asset you're building.
4. All adaptations: the columns are *prompts for where to look*, never templates to fill blindly.
   Narrow the target first (Hidden Knowledge #2) — a vertical is not a target; a person inside it is.

## Table A — The method across 8 verticals/contexts

| Vertical | Best gather sources | Where the richest *unprompted* language lives | Dominant pains/gains shape | How "put the map to work" changes |
|---|---|---|---|---|
| **B2B SaaS** | G2/Capterra reviews (yours + competitors'), churned-account exit notes, support tickets, sales-call transcripts, niche Slack/Discord, subreddits | One-star/3-star reviews and churn notes — the "I switched because…" sentence; the workaround-spreadsheet confession in support tickets | Pains = workflow friction, integration gaps, "had to build a manual workaround," seat/price justification to a boss; Gains = look competent to the team, fewer tabs, hit the metric | Lead with the widest *workflow* gap; copy = objection-handlers for the buyer-vs-user split; offer = the missing integration/onboarding the workarounds reveal |
| **Local service business** | Google/Yelp reviews (yours + 3 nearest competitors), Nextdoor threads, neighborhood Facebook groups, the front-desk's "what they actually called about" notes | Reviews describing the *fear before they called* and the *relief after*; Nextdoor "can anyone recommend…" posts naming the exact worry | Pains = trust/risk ("will they rip me off," "will they show up"), urgency, mess/disruption; Gains = peace of mind, "done right the first time," neighbor-grade trust | Copy speaks to the pre-call fear in their words; content = the "what to watch out for" piece; offer = a guarantee/transparency lever aimed at the trust gap |
| **Real estate / first-time homebuyer** | Reddit (r/FirstTimeHomeBuyer, r/RealEstate), Zillow/forum Q&A, agent DMs, buyer-consult call notes, lender's FAQ inbox | The terrified, jargon-confused questions asked anonymously at midnight ("am I being dumb for…"); the "I had no idea X would cost me" post-close vent | Pains = overwhelm, fear of a costly mistake, opaque process/jargon, "am I even qualified"; Gains = confidence, "I won't get taken advantage of," the keys-in-hand feeling | Copy decodes jargon in their exact phrasing; content series = the step-by-step "things nobody told me"; offer = a hand-holding/education layer matched to the overwhelm gap |
| **E-commerce / DTC product** | Amazon + own-site reviews (★1–3 first), TikTok/IG comments, unboxing videos, return-reason fields, post-purchase survey verbatims | Review titles and comment threads describing the *moment of use* ("works great until…"), and return reasons — the cleanest unmet-need signal in retail | Pains = fit/quality/expectation gaps, shipping, "photos lied," compatibility; Gains = identity/aesthetic, the result/feeling, "finally one that…" | Copy = quote-to-slot from review titles into PDP headlines; content = the "how it actually performs" piece; offer = bundle/variant/guarantee aimed at the top return reason |
| **Info-product / course creator** | YouTube comments on the topic, Reddit/Quora questions, replies to your free content, refund-request reasons, community posts | The "I've tried everything and still can't…" comment; the half-embarrassed question under a free video — the exact gap your course should close | Pains = tried-and-failed cycles, overwhelm/where-to-start, impostor doubt, "is this for someone like me"; Gains = transformation/identity ("become the person who…"), clarity, a result they can show | Copy = the failed-attempt story in their words; content = grounded ideas (one quote each) feeding the funnel; offer = curriculum/positioning shaped to the widest "still can't" gap |
| **Coaching / wellness** | Reddit (condition/goal subs), Facebook support groups, intake-form free-text, session notes, reviews of competing coaches/programs | Support-group posts where people describe the problem to peers, not to a coach — raw, unguarded, identity-laden | Pains = stuck/relapse cycles, shame, conflicting advice, "I know what to do but don't do it"; Gains = identity shift, relief, being understood, sustainable change | Copy names the unspoken shame in their phrasing; content = recognition-first ("if you've ever…"); offer/positioning = the belief/identity gap (route deep via `/ctm-deepen`) |
| **Agency / freelancer (client work)** | The client's *own* customers' reviews + the client's sales-call transcripts and support inbox (you're mapping *their* buyer, not yours) | Wherever the client's end-customer talks unprompted — and the client's existing call recordings, the most under-used asset in agency work | Pains = whatever the client's buyer feels (varies by their vertical) + the client's pain = "my marketing doesn't sound like my customers"; Gains = the client's buyer's gains + client's = evidenced, defensible positioning | Deliverable = a map *as the product* the client executes against; copy/positioning recommendations each cite a real client-customer quote (un-arguable in the review meeting) |
| **Newsletter / creator** | Reply emails, comment sections, DMs, poll/survey free-text, the "this resonated" replies, audience subreddit/Discord | Direct replies to issues — the most concentrated unprompted language a creator has; the "this is exactly what I needed" / "I wish you'd covered…" reply | Pains = info-overwhelm, "no one explains this for people like me," time/trust; Gains = belonging, feeling-seen, the next-step clarity, identity as "someone who reads X" | Content ideation = grounded ideas from reply language; copy = subject lines lifted from replies; offer = paid tier/product shaped to the most-repeated "I wish you'd…" gap |

**Reading the table:** the columns are the four variables that move per vertical. The *constant* —
true in every row — is the spine: gather unprompted talk, keep it verbatim, sort it into the six
categories, reframe pains to jobs, rank the widest gaps, and put the map to work. Narrow inside the
vertical before you gather: "DTC product" is not a target; "a 28-year-old who returned the running
shoe because the toe box was too narrow" is.

## Table B — The six map categories across asset types

Each cell = what that map category *becomes* when you build that asset (Phase 5, "put the map to
work"). The map is the input; these are the outputs. Every cell still carries a real, sourced quote.

| Map category ↓ / Asset → | Sales page | Email | Social post | VSL | Content series | Offer design |
|---|---|---|---|---|---|---|
| **SAY** (stated, direct) | H1 / sub-H1 lifted from a verbatim line (quote-to-slot, Pattern 8) | Subject line = a real said sentence | The hook = their exact words, unedited | Opening line = their stated complaint, spoken back | Episode titles = direct quotes | Offer *name* echoes how they describe the want |
| **THINK** (implied belief) | The "you might be thinking…" objection block | The reframe paragraph that surfaces the assumption | The contrast turn ("you assume X…") | The belief the VSL exists to shift | The myth-busting episode | The hidden objection the offer must dissolve |
| **FEEL** (emotion) | Empathy line above the offer; tone of the whole page | The "I know how this feels" beat | The relatable emotional open | The emotional valley before the turn | The recognition-first series spine | The emotional outcome the offer promises (not the feature) |
| **DO** (actions + workarounds) | The "stop doing the manual workaround" proof block | The "here's what you're doing now" mirror | The "tag someone who still does this" hook | The current-broken-process demo | The "the [workaround] trap" episode (Do-category goldmine, Pattern 5) | The feature/service that replaces the workaround |
| **PAINS** (problems/risks) | The problem-agitation section, in their words | The body's core pain, one per email | The single pain the post owns | The stakes/cost-of-inaction segment | The widest-gap pain = the series' through-line | The pain the offer is *positioned against* (Pattern 7) |
| **GAINS** (outcomes/wishes) | The outcome promise + the proof it's real | The "imagine if…" close | The aspirational payoff line | The transformation payoff before CTA | The "what becomes possible" arc/finale | The headline outcome the offer is sold on |

**Reading the table:** read *down* a column to build one asset from the whole map; read *across* a row
to see how one category travels across every format. Pains → Gains is the spine of any persuasive
asset; Do (workarounds) is the secret weapon — the proof block and the offer both live there.

## Cross-cutting adaptation rules (true in every vertical and asset)

- **The vertical is not the target.** Every block above must be narrowed to one person + one problem
  cluster before gathering (Hidden Knowledge #2). A vertical tells you *where to look*; the map is
  built about *one customer*.
- **Own-data first, everywhere.** In every vertical, the richest source is usually already in-house —
  your (or the client's) reviews, call transcripts, and support inbox (Hidden Knowledge #1). Check
  Recall + `memory_facade.py` before scraping.
- **Unprompted beats prompted in every column.** Across all eight verticals, the gold lives where
  people talk to peers, not to you — peer threads, reviews, replies, support venting (Pattern 2).
- **Apply changes the output, never the spine.** Sales page vs VSL vs offer differ in Table B, but
  each cell is still a real sourced quote put in a slot — never a generic line written to fill the
  grid (Pattern 8, Pattern 9).
- **Confidence-label across sources.** When a vertical spans several communities, split Consistent
  Truths from Source-Specific before acting (Pattern 10).

## Quality Gate

This reference passes the `../genius.md` rubric when:
- **Narrowness (#3):** every vertical block is usable only after narrowing to one person/problem — the
  table prompts *where to look*, never substitutes for a narrow target.
- **Unprompted Sourcing (#2):** every "richest language" cell points at unsolicited talk or own-data,
  never at a survey.
- **Do-Category Mining (#5):** the DO row in Table B and the workaround language in Table A keep the
  goldmine visible in every asset and vertical.
- **Put-to-Work Fidelity (#8):** every Table B cell routes the map to a *specific* slot in a real
  asset, carrying a sourced quote — nothing generic.
- **Verbatim Integrity (#1 — the veto):** no cell, vertical, or asset may invent a quote/pain/source
  to fill a slot. Real language in, organized language out — always.

**Self-check (one line):** Could a sub-agent open one vertical row and one asset column it has never
worked in, narrow to a single customer, and produce on-format output grounded in real, sourced
language — without fabricating a single line? If not, the cell is too generic.
