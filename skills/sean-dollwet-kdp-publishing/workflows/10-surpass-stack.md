# Surpass Stack — Bounded Quality Support Without Expert Soup

## Pre-Flight Gate

Sean and the Book One conductor remain the function owner. Use this only when a named weakness cannot be solved well by the native workflow. Specialist support never changes the approved reader, promise, evidence class, policy rule, or approval status.

Do not fire every option. Load a specialist only after choosing `FIRE`, and pass only the approved artifact plus a compact brief.

## Candidate Slots

| Stage | Native owner | Optional bounded support | FIRE only when |
|---|---|---|---|
| Reader | Workflows 01–02 | Avatar/ICP depth | Identity or buying-state detail materially changes the approved angle |
| Title/listing | Workflow 02 | Conversion copy | A specific listing clarity or promise gap remains after metadata constraints |
| Manuscript | Workflow 03 | Nicolas Cole value/prose architecture | Reader-quality evidence shows the native chapter structure is not enough |
| Cover | Workflow 02 + cover brief | Creative direction | Dated visual conventions are the named attack surface and rights are controlled |
| Organic | Workflow 06 | Content psychology | An observed hook/format bottleneck exists after initial experiments |

## Execution

For each slot:

1. Decide `FIRE` or `SKIP` and name the evidence.
2. If `FIRE`, define one input artifact, one deliverable, exclusions, acceptance tests, and time/spend impact.
3. Require rights, privacy, AI disclosure, source, and policy continuity.
4. The specialist returns an artifact and change note; the conductor reconciles it into the cockpit.
5. Record exactly what changed because of the contribution. An expert name alone is not proof.
6. Send the integrated artifact to the existing Farrice approval checkpoint.

Quality is demonstrated by claim support, reader usefulness, distinctiveness, craft, rights, and test evidence—not by speed, review volume, or number of experts.

## Output Requirements

- Function owner and locked reader/promise.
- FIRE/SKIP table for all five slots.
- Bounded brief and acceptance tests for each fired slot.
- Integration ledger: before, contribution, after, evidence of change, remaining risk.
- Time/spend/permission boundary.
- Next existing Book One checkpoint.
