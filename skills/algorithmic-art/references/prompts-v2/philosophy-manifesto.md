## Role & Activation

You are writing the manifesto stage of a generative art movement — the document a "master-level" computational artist would produce before a single line of code exists. The skill's own framing: "Write a manifesto for a generative art movement. The next phase involves writing the algorithm that brings it to life." Here you stop at the manifesto — an algorithmic philosophy, not a description of a static image, not a code plan.

## Input Required

```
[USER REQUEST] — the subtle input/instruction to take as foundation, without letting it constrain creative freedom
[CONCEPTUAL SEED, if discernible] — a niche reference implicit in the request that should shape the philosophy's language and imagery without ever being named outright
```

## Execution Protocol

**Step 1 — Deduce the conceptual seed first.** Before writing anything, find the subtle, sophisticated thread inside the request — not always literal. This becomes the philosophy's quiet soul: it should be feel-able in the language and imagery of the manifesto without being named. Someone who knows the reference should sense it; everyone else should just read a strong piece of art writing.

**Step 2 — Name the movement (1-2 words).** Coined, evocative, in the register of a real art-movement name — not a literal description of the algorithm. Do not reuse the skill's own worked examples ("Organic Turbulence," "Quantum Harmonics," "Emergent Stillness," "Recursive Whispers," "Field Dynamics," "Stochastic Crystallization") — those are illustrations of tone, not a library to draw from.

**Step 3 — Write 4-6 substantial paragraphs** that capture the ALGORITHMIC essence — how the philosophy would manifest through, if built: computational processes and mathematical relationships; noise functions and randomness patterns; particle behaviors and field dynamics; temporal evolution and system states; parametric variation and emergent complexity. This is prose about a computational worldview, not pseudocode and not a literal spec — the next implementation phase needs interpretive room.

**Step 4 — Apply the critical guidelines:**
- **No redundancy** — each algorithmic aspect appears once; if you return to noise theory, particle dynamics, or a mathematical principle, it must add genuinely new depth, not restate.
- **Emphasize craftsmanship repeatedly, explicitly, in the actual prose** — the manifesto must stress more than once that the eventual algorithm will feel like it took countless hours, was refined with care, is the product of someone at the absolute top of their field. Use language in that register — "meticulously crafted," "the product of deep computational expertise," "painstaking optimization," "master-level implementation" — not as decoration but as a real constraint the manifesto is setting for whoever builds from it.
- **Leave creative space** — specific enough to give a real direction, concise enough that an implementer retains room for high-craftsmanship interpretive choices.

**Step 5 — Hold the governing constants:** process over product (beauty lives in the algorithm's execution, each run is unique — say this, don't just imply it); parametric expression (ideas communicate through mathematical relationships, forces, behaviors — never through static composition language); artistic freedom (the manifesto guides, it does not dictate every implementation choice); pure generative art (living algorithms, not static images dressed up with randomness).

## Output Contract

One markdown document, 4-6 paragraphs, opening with the movement name. No code, no parameter lists, no UI description — those belong to the implementation phase and are explicitly out of scope here. Length: substantial paragraphs (not one-liners), but the whole document should read in under two minutes — dense, not padded.

## Output Skeleton

```markdown
# [MOVEMENT NAME]

[Paragraph 1 — the core computational/philosophical premise: what tension or truth this movement expresses]

[Paragraph 2 — how it manifests through noise functions, randomness patterns, or mathematical relationships]

[Paragraph 3 — particle/field/structural behavior and how the system evolves over time or iterations]

[Paragraph 4 — parametric variation: what varies, what stays constant, why that split matters — plus craftsmanship framing]

[Paragraph 5, optional — deepens one thread from above without repeating it; reinforces craftsmanship language again]

[Paragraph 6, optional — closes on process-over-product: why each run/seed will be unique, why beauty lives in execution]
```

## Quality Gate

- Does the manifesto stay in prose/philosophy register throughout — zero code, zero parameter tables, zero UI/control description?
- Is craftsmanship/mastery language present more than once, in more than one paragraph, not just as a single closing line?
- Does each paragraph add a genuinely new algorithmic aspect rather than restating noise/particle/mathematical concepts already covered?
- Is the movement name original — not one of the skill's own worked examples reused verbatim?
- Is the length 4-6 substantial paragraphs, not padded to hit a count and not thinned to two?

## Creative Latitude

The manifesto is where the conceptual seed does its quietest work — let it shape metaphor choice, sentence rhythm, and the specific mathematical/natural phenomena invoked (waves vs. crystals vs. branching vs. erosion), never a stated reference. Movement-name and tone are genuinely open: philosophical, scientific, poetic, or stark — whatever register the deduced concept calls for. Resist the pull toward the skill's five worked examples as a template; they exist to calibrate tone and paragraph density, not to be lightly reskinned.

## Deploy When

User wants the conceptual/philosophical grounding for a generative art piece on its own — a manifesto, a written aesthetic direction, an artist's statement for a movement — without immediately requesting the p5.js implementation.
