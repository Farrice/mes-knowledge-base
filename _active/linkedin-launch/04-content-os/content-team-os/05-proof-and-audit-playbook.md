# 05 - Proof And Audit Playbook

## Purpose

This is the trust layer. It keeps the launch honest while still making the work commercially useful.

The rule:

Proof gets manufactured through visible judgment, not invented through fake authority.

## Proof Classes

### Class 1 - Stated Source Proof

What it is:

- public source
- citation
- official guidance
- study
- product page
- prompt log
- screenshot

Use for:

- claim ledgers
- article proof notes
- audit receipts

Rule:

Every public factual claim needs a source label: VERIFIED, LIKELY, or UNCONFIRMED.

### Class 2 - Judgment Proof

What it is:

- Farrice's read on a claim boundary
- physiology mechanism explanation
- buyer-language diagnosis
- content rewrite
- audit lens

Use for:

- Teardown Tuesday
- Proof Vs Claim
- Founder Proof Port

Rule:

Make the reasoning visible. Do not just state the verdict.

### Class 3 - Process Proof

What it is:

- before/after rewrite
- prompt sequence
- five-prompt visibility test
- one-page audit object
- proof tracker update

Use for:

- zero-proof launch phase
- audit sales bridge
- Featured section

Rule:

Show the steps without pretending the outcome is a client result.

### Class 4 - Outcome Proof

What it is:

- named client result
- verified visibility change
- revenue result
- citation screenshot over time

Use for:

- case studies
- pricing increase
- stronger sales pages

Rule:

Do not use outcome proof until it is real and documented.

## Audit Objects

### Object 1 - AI-Search Visibility Test

Purpose:

Show the wall.

Inputs:

- site
- category
- one competitor
- 5 to 7 prompts
- screenshots or prompt logs

Output:

- present, absent, or weakly described
- competitor contrast
- first source or proof gap
- recommended next asset

Use:

- free lead magnet
- DM follow-up
- article example

### Object 2 - Claim-Safe Citation Audit

Purpose:

Paid entry product.

Inputs:

- top 8 to 12 objective claims
- source links
- product pages
- ads or founder posts
- category prompts

Output:

- claim inventory
- substantiation risk
- citation-worthiness read
- safe wording
- unsafe wording
- source gap
- asset recommendation

Use:

- $500 pilot audit
- retainer upsell

Boundary:

This is not legal advice and does not replace counsel.

### Object 3 - Soft-Line Audit Demo

Purpose:

Zero-proof visible demonstration.

Inputs:

- anonymized or archetypal brand
- one public claim
- one buyer prompt
- one proof gap

Output:

- what the claim says
- what the source can carry
- what the buyer might wonder
- what the machine might flatten
- what to build next

Use:

- public post
- carousel
- Featured section proof

Boundary:

Do not make it so generic that it loses diagnostic force.

### Object 4 - Source-To-Search Map

Purpose:

Show the retrieval layer.

Inputs:

- buyer questions
- source types
- current brand surfaces
- competitor surfaces
- off-site mentions

Output:

- current proof surface
- missing source surface
- long-tail questions
- answer-page opportunities
- LinkedIn reinforcement posts

Use:

- creative strategy intensive
- GEO ghostwriting retainer

## Prompt Log Protocol

When running AI-search tests, save:

- date
- engine
- exact prompt
- account/location caveat if relevant
- answer summary
- whether brand appeared
- competitors named
- sources shown, if any
- screenshot path or note

Never claim "AI names X" without this receipt.

## Screenshot Protocol

Screenshots should show:

- date or saved filename
- query/prompt
- engine
- answer portion
- source links when visible

Store screenshots in a dated proof folder before using them in public copy.

## Claim Boundary Rules

Never produce:

- diagnosis
- treatment recommendation
- supplement dosing
- disease prevention claim
- "cures"
- "treats"
- "prevents"
- personalized health advice

Prefer:

- "supports"
- "may help"
- "the evidence suggests"
- "the source can safely carry"
- "the proof does not support that stronger version"
- "this needs a clearer receipt"

## Zero-Proof Launch Rule

Until there are real case studies, use:

- audit demos
- prompt logs
- public teardowns
- source-backed articles
- proof-in-progress notes
- Farrice's visible judgment

Do not use:

- implied client results
- fake screenshots
- inflated authority claims
- "trusted by" language
- "we got cited" without proof

## Proof Tracker Fields

For each proof object, track:

- date
- asset name
- type
- source links
- claim label
- buyer pressure
- offer rung
- public link or local file
- outcome observed
- next asset to build

## The Proof Bar

A proof object is good enough when a skeptical buyer can see:

- the exact thing being evaluated
- the standard used to evaluate it
- the source or receipt
- the practical consequence
- the asset Farrice would build next

If any of those are missing, the proof object is not ready for the offer page.
