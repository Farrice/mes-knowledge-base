# Content Production Playbook

## Purpose

This is the morning operating manual for producing the content. Open this when you wake up and follow the run-of-show.

The goal is not to decide from scratch every day. The goal is to know:

- what asset today calls for
- what source packet it needs
- what format it should become
- what proof object it strengthens
- what to publish
- what to do after publishing

## The Morning Run-Of-Show

### Step 1 - Identify The Day

Use the default rhythm:

| Day | Primary Job |
|---|---|
| Monday | Source packet and angle selection |
| Tuesday | Teardown Tuesday flagship |
| Wednesday | Distribution, comments, buyer language |
| Thursday | Mechanism, claim-boundary, or AI-search post |
| Friday | Proof object and tracker |
| Saturday | Founder/trust post |
| Sunday | Review and next-week setup |

If you missed a day, do not double the workload. Ship the highest-value asset still alive.

Priority order:

1. Teardown Tuesday
2. proof object
3. mechanism post
4. founder/trust post
5. comments
6. optional DM bridge

### Step 2 - Choose The Production Mode

Pick the version that matches the morning you actually have.

| Time Available | Mode | Output |
|---|---|---|
| 20 minutes | Minimum viable | one comment sprint or proof tracker row |
| 45 minutes | Standard | one publishable text post plus first comment |
| 90 minutes | Strong | post plus carousel outline plus comment sprint |
| 2 hours | Flagship | post, carousel, proof notes, first comment, DM bridge |

Do not choose the 2-hour mode on a 45-minute morning. The system should survive real life.

### Step 3 - Fill The Morning Brief

Open `06-morning-content-brief-template.md`.

Fill:

- day
- asset type
- buyer
- pressure
- source or proof
- offer rung
- format
- one GET
- post-publish action

If the brief is weak, do not write yet. Gather sharper source material or use the day for comments.

### Step 4 - Build The Source Packet

Minimum packet:

- one claim, prompt, page, trend, or buyer line
- one source or proof note
- one claim boundary
- one buyer anxiety
- one next asset

Label:

- VERIFIED
- LIKELY
- UNCONFIRMED

Never hide uncertainty. The label is part of the trust signal.

### Step 5 - Pick The Format

Use the format decision tree:

| If the asset needs... | Use... |
|---|---|
| speed and sharpness | text post |
| save value and visible structure | carousel |
| source trail and durable proof | article |
| trust and human presence | direct-to-camera |
| market listening and distribution | comment |
| conversion after specific value | DM |
| reusable evidence | proof object |

Format follows the job. Do not make a carousel because it feels more official.

### Step 6 - Produce The Asset

Use the asset SOP below.

### Step 7 - Run The Publish Gate

Do not ship until these pass:

- specific buyer
- real pressure
- one useful GET
- source or limitation near factual claim
- no fake result
- no medical advice
- no hard CTA unless earned
- one offer rung strengthened

### Step 8 - Publish And Stay Present

For 30 to 60 minutes after posting:

- reply to comments
- save buyer language
- identify one comment thread to enter
- do not pitch unless someone asks

Posting without staying present wastes the asset.

### Step 9 - Update The Proof Rail

Save:

- source links
- prompt logs or screenshots if used
- final post file
- first comment
- buyer-language snippets
- proof tracker row
- next asset

## Asset SOPs

### Text Post SOP

Use for:

- mechanism post
- founder/trust post
- fast claim-boundary read
- AI-search observation

Build:

1. Hook: name a real pressure.
2. Scene: show the buyer moment.
3. Turn: reveal the more useful read.
4. Proof: source, mechanism, or boundary.
5. GET: one question, check, prompt, or decision.
6. Close: recognition, not hype.

Length:

- 350 to 900 words for flagship
- 180 to 500 words for standard

Do not:

- open with "Here is why"
- end with a cheap question
- use a hard CTA unless the post is an offer bridge

### Carousel SOP

Use for:

- Teardown Tuesday
- Claim Receipt
- AI-Search Visibility Test
- Soft-Line Audit Demo

Build:

1. Cover: specific problem.
2. Claim or prompt.
3. Buyer pressure.
4. What is strong.
5. What is missing.
6. Claim boundary.
7. Stronger rewrite or next asset.
8. Receipt.
9. Practical GET.
10. Optional soft bridge.

Length:

- 8 to 10 slides
- one idea per slide
- no decorative filler

### Article SOP

Use for:

- source-backed proof surface
- monthly flagship
- asset that should live in Featured

Build:

1. buyer scene
2. market shift
3. proof problem
4. source-backed analysis
5. audit lens
6. offer bridge
7. source note

Article standard:

The article should be strong enough to send privately to a serious buyer.

### Comment SOP

Use daily.

Build:

1. acknowledge the real point
2. add one layer
3. name the decision
4. stop

Do not pitch.

Good comment types:

- claim-boundary
- source logic
- buyer anxiety
- founder voice
- AI-search implication
- proof surface

### DM SOP

Use only after specific value exists.

Build:

1. context
2. specific read
3. one asset you would build
4. low-pressure offer to send the one-page read

No cold pitch from generic interest.

### Proof Object SOP

Use Friday or after any flagship.

Build:

1. asset name
2. source or input
3. claim or buyer question
4. proof standard
5. boundary
6. rewrite or next asset
7. outcome observed
8. next build

Proof object must be inspectable. If it feels like a marketing claim, it is not proof yet.

## Format Production Brief

Every production brief inherits these 10 sections:

1. Spine reminder
2. Asset job
3. ICP and audience state
4. Reader pressure
5. Source packet
6. Format spec
7. Structure pattern
8. Draft task
9. Self-check
10. Post-publish action

If any section is blank, the asset is not ready.

## Morning Decision Tree

Ask:

1. Is today Tuesday?
   - Yes: Teardown Tuesday.
2. Is there a live source or claim boundary worth acting on?
   - Yes: mechanism/newsjack post.
3. Did a proof object exist this week?
   - No: build proof object.
4. Has Farrice shown enough human judgment this week?
   - No: founder/trust post.
5. Is the feed active but quiet?
   - Comment sprint.
6. Did someone engage with a specific asset?
   - DM bridge.

## The Daily Minimum

On a hard day, do this:

1. Leave 10 serious comments.
2. Save 3 buyer-language snippets.
3. Add one proof tracker row or source note.

That keeps the system alive.

## The Standard Day

On a normal day, do this:

1. Fill the morning brief.
2. Produce one post.
3. Write the first comment.
4. Leave 10 serious comments.
5. Save one proof note.

## The Flagship Day

On a high-output day, do this:

1. Fill the morning brief.
2. Produce the flagship text post.
3. Produce carousel outline.
4. Write proof notes.
5. Write first comment.
6. Draft DM bridge.
7. Update proof tracker.
8. Leave 10 to 20 comments.

## End-Of-Day Closeout

Before stopping, answer:

- What did I publish or produce?
- Which offer rung did it strengthen?
- What proof did I save?
- Which buyer phrase did I capture?
- What asset should tomorrow produce?

If those are answered, the day counts.
