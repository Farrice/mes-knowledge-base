# Portable Usage Guide

## Choose the correct mode first

### Use master-brand mode when

- Farrice's point of view is the subject;
- the asset teaches product truth, buyer belief, or a useful distinction;
- lived retail or coaching experience supplies context; or
- the asset should still make sense if The Angle Map disappeared.

### Use offer mode when

- The Angle Map is the explicit subject;
- three campaign arguments are being compared;
- a lead recommendation is being shown; or
- the commercial invitation is `DM ANGLE`.

If neither description fits, stop and clarify the asset's job before designing it.

## Human designer workflow

1. Read `01-BRAND-FOUNDATION.md` and `02-DESIGN-CONTRACT.md`.
2. Confirm the mode, exact copy, platform, dimensions, and approval state.
3. Open the closest editable SVG source. Use the PPTX as an editable source only for the 12-page field guide; the carousel PPTX is a flat-page sequencing container.
4. Replace content without changing the hierarchy law.
5. Remove any component that does not earn its place.
6. Export the final PNG or PDF.
7. Run `quality/QA-CHECKLIST.md`.
8. Return the editable source, export, alt text, and review receipt.

## AI-assisted workflow

1. Load the eight files listed in `00-READ-ME-FIRST.md`.
2. Complete `ai/REQUEST-BRIEF-TEMPLATE.md`.
3. Tell the AI to preserve exact approved copy and state labels.
4. Ask for one primary execution—not a field of stylistic variations.
5. Use the nearest existing template as the structural parent.
6. Require editable source plus export.
7. Run a second pass against the visual, claim, identity, and portability gates.

## Image-generation boundary

AI image generation may create:

- nonrepresentational paper or fog textures;
- quiet background fields;
- abstract atmospheric layers that contain no copy, logo, face, product, or claim.

AI image generation may not create or modify Farrice's face. It should not render final typography when an editable layout tool can typeset the exact copy.

## New asset workflow

When no exact template exists:

1. Use the closest surface recipe in `tokens/asset-recipes.json`.
2. Preserve the twelve-column grid and one-third open-space rule.
3. Use no more than three hierarchy levels.
4. Reuse approved components only when they perform their actual function.
5. Keep the asset in `draft` until it passes QA.
6. Move it to `review` only after editable source and export both exist.
7. Do not mark it `approved` without Farrice's explicit decision.

## File naming

Use:

`fc-pm1_[surface]_[subject]_[state]_v##.[ext]`

Examples:

- `fc-pm1_li-insight_hook-vs-angle_review_v01.svg`
- `fc-pm1_li-carousel_proof-boundary_draft_v02.pptx`
- `fc-pm1_li-banner_evergreen-farrice_review_v01.png`

Valid states are `draft`, `review`, and `approved`. Never use `final-final2`.

## Handoff receipt

Every returned asset should state:

- mode used;
- template or recipe used;
- exact copy source;
- dimensions;
- editable source format;
- export format;
- font availability;
- portrait source, if any;
- claim/proof boundary;
- QA result; and
- approval state.
