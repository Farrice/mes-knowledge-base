# The Full Picture: Social-Scrape-to-Notion Systems

Source: a YouTube demo (https://youtu.be/gOx37on-iA8, creator/title TBD, transcript pending) showing an AI system that scrapes social content into a Notion database with video, transcript, and marketing agents attached. This doc separates what such a system actually costs to run from what this repo already has built, so the next move on this branch is informed rather than reactive.

## 1. TL;DR

This repo already has roughly 80% of what the demo is showing off: a governed 17-actor scraper (`execution/apify_client.py`), a hand-pinned Notion writer (`execution/notion_api.py`), free transcript fetching (`execution/fetch-transcript.py`), a video-context pipeline with frame/OCR analysis (`execution/fetch-video-context.py` + `skills/youtube-video-context-analysis/`), and scheduled social listening (`execution/social_pulse.py`) — none of which the typical demo mentions running a cost gate on. There are four real gaps, not eighty: no LinkedIn scraper anywhere in the whitelist, no single script that chains scrape → Notion write (this is shipping right now as `execution/social_to_notion.py` on this same branch), no automated media-file download into Notion (the transcript/frame pipeline exists but nothing pushes video files into Notion pages), and no `GROQ_API_KEY` configured for the Whisper fallback path that already exists in code but currently just fails clean instead of transcribing. Everything else the demo would need, this system either already has or has a documented, cheaper substitute for.

## 4. The 4 gaps, honestly costed

**LinkedIn scraping.** No actor in the 17-item whitelist touches LinkedIn. Three real options exist: (a) Apify has LinkedIn-scraping actors, but running them violates LinkedIn's ToS and the practical failure mode is burned accounts and burned proxies, not just a warning; (b) Scrape Creators has LinkedIn endpoints on some plans, which shifts the ToS risk to their infrastructure rather than ours, cost unverified — check current plan coverage before assuming it's included; (c) LinkedIn's official API is partner-gated and not something you can just sign up for. Recommendation: defer. Lowest-risk path if this becomes a real need is a manual export (LinkedIn's own data-export tool) or a vetted ToS-compliant service, decided deliberately rather than bolted on because a demo showed it. Do not buy anything here without that decision being made explicitly.

**Media file download.** Not actually a capability gap — `execution/fetch-video-context.py` already pulls files locally via yt-dlp as part of its frame-extraction pass. What's missing is the last step: pushing that file (or a Notion-hosted copy of it) into a Notion page as an attachment rather than just a transcript/frame report living in `extractions/`. This is a storage-and-plumbing question, not a new-capability question, and it's inside the scope of what `execution/social_to_notion.py` is being built to close.

**Whisper transcription key.** The code path is already written — `execution/fetch-video-context.py --whisper` calls Groq's Whisper endpoint when native captions don't exist, and Groq has a free tier. But `GROQ_API_KEY` isn't currently set anywhere in this repo's `.env` handling, and — more importantly — the pattern isn't in `execution/hooks/cost_gate_hook.py`'s `PAID_PATTERNS` list. That means if the key ever does get added and someone crosses from Groq's free tier into paid usage, nothing in this system would catch it. Flagging this as a system-hardening TODO: add the key when there's an actual uncaptioned-video need, and add a Whisper/Groq pattern to the cost gate at the same time — not one without the other.

**End-to-end glue.** This is what's shipping right now on this branch: `execution/social_to_notion.py` plus `.agent/workflows/social-to-notion.md`. It's the piece that takes a URL, runs it through the existing scrape layer, normalizes the result, and writes a Notion page with embed + transcript + ledger entry — the actual "system" the demo is showing, built from parts this repo already had.

## 5. Cost-gate posture

Nothing in this branch spends money. The new glue script (`execution/social_to_notion.py`) is a T1 change per `directives/orchestration-doctrine.md`'s Blast-Radius Autonomy Tiers — files/commits in this repo, $0 APIs, established patterns — so it doesn't require a wait-for-nod checkpoint on its own. Any future move to buy a LinkedIn-scraping service, add a paid Whisper tier, or subscribe to anything not already in the existing stack is T2 (outward/paid/novel) and gets a Mission Card + explicit yes before anything is purchased. The glue script inherits the Apify wrapper's existing fallback contract — when the budget ledger hits Red, calls return `{"status":"budget_exhausted","fallback":true}` rather than raising or silently retrying, so a scrape failure downstream in the Notion-write step is always a budget signal, not a mystery.

## 6. What we do that he almost certainly doesn't

- **Budget governance on the scraper itself.** Green/Yellow/Red states with a hard stop at 90% of the Apify budget, tracked in `.agent/apify-usage.json`, documented in `directives/apify-usage-policy.md`. Most "I scrape everything" demos run until the invoice shows up.
- **A pinned, version-locked Notion client.** `execution/notion_api.py` hard-pins `Notion-Version: 2022-06-28` specifically because a newer official client silently broke schema updates. That's a failure mode from having actually run this in production, not from a one-time demo recording.
- **Evidence-lane separation in video analysis.** `skills/youtube-video-context-analysis/` runs an 8-workflow ledger system (`/video-transcript-ledger` through `/video-multi-compare`) that keeps spoken evidence, visual/OCR evidence, and uncertainty explicitly separated rather than blending everything into one confident-sounding summary.
- **A memory layer over the captured content, not just storage of it.** Recall (3,000+ cards) plus `.memory/sovereign.db`, fed nightly from a Notion mirror (`execution/mirror_notion.py`, launchd `com.antigravity.mirror-nightly`), queryable through a single `execution/memory_facade.py` front door. The demo's Notion database is a filing cabinet; this is a filing cabinet with a research assistant attached.
- **A fallback contract that never raises.** The Apify wrapper returns a typed `{"status":"budget_exhausted","fallback":true}` object instead of throwing when budget runs out, so every downstream consumer (including the new glue script) can handle "we're out of budget" as a normal state instead of a crash.
- **Quality gates before anything gets called done.** Every deliverable this system produces runs through a scored finalize step (`execution/chain_runner.py finalize`) with a factual-grounding veto — score below 6 on that dimension blocks delivery regardless of the composite score. A scrape-to-Notion pipeline with no equivalent check will happily write garbage into a database and call it captured.
