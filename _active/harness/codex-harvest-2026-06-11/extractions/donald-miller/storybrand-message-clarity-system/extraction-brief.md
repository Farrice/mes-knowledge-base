# StoryBrand Message Clarity System Extraction Brief

## Build Boundary

This is an expansion of the existing Donald Miller stack, not a new expert island. The two source videos strengthen and connect:

- `skills/donald-miller-storybrand/`
- `skills/donald-miller-cognitive-load/`
- `agents/donald-miller/`
- existing command surfaces such as `/storybrand`, `/one-liner`, `/message-audit`, and `/storybrand-copy`

## Operating Thesis

The source material teaches that messaging fails when customers cannot quickly name the problem a business solves, understand the offer without mental effort, or repeat the message to someone else. The durable system response is a single orchestrated command that starts with problem ownership, reduces cognitive load, creates locked sound bites, then maps those words into StoryBrand structure and channel deployment.

The `SzugliCQ3XY` source adds a case-study proof layer: BELAY's growth story shows messaging as a repeated operating practice, not a one-time tagline exercise. It especially strengthens lane discipline, service-line pain separation, and internal adoption of simple language.

## Core Mechanics Extracted

| Mechanic | Meaning | Implementation |
|---|---|---|
| One-hole lock | The message must own one specific customer problem. | Runtime input gate requires one primary problem before generating sound bites. |
| Cognitive-load autopsy | Existing words are weighed before they are rewritten. | Load `01-cognitive-load-autopsy.md` when copy, URL text, headline, or offer language is supplied. |
| PEACE sound bites | Problem, Empathy, Answer, Change, and End Result create the message foundation. | Load `02-peace-soundbite-generator.md`; keep the selected five phrases locked. |
| StoryBrand alignment | Sound bites need story structure so the customer stays hero and the product stays guide/tool. | Load BrandScript and one-liner workflows for alignment notes and the final sentence. |
| Repetition discipline | Message clarity compounds when exact words repeat across touchpoints. | Load deployment matrix workflow and include a monthly consistency audit. |
| Three-phase campaign | Sound bites are not standalone copy; they feed curiosity, enlightenment, and commitment. | Deployment output must classify first collateral by phase. |
| Case-study message gate | Growing companies can add services faster than customers can understand them. | Add `/low-cognitive-load-message-gate` before content, writing, and copy systems polish or publish an unclear message. |
| Service-line pain separation | Different offers may solve different felt problems under one brand. | The gate forces one offer/problem per message pass and hands separate pains into separate downstream assets. |

## Reuse Decision

- Do not create a new `donald-miller-soundbite-strategy` skill.
- Do create `/storybrand-message-clarity-system` as an orchestrator because the value is in step order and handoffs across existing components.
- Do create `/low-cognitive-load-message-gate` as a cold companion gate because the value is stop-condition enforcement across adjacent writing/content/copy workflows.
- Do repair the missing reference files so both Donald Miller skills pass validation and can be used as stable components.

## Failure Modes To Prevent

- Starting with the product, company history, mission, or credentials.
- Solving multiple problems in the same message pack.
- Treating sound bites as brainstorming variants instead of locked language.
- Producing a BrandScript without a cognitive-load pass.
- Producing a one-liner without a deployment matrix.
- Claiming visual or slide evidence from transcript-only source packages.
- Treating the new BELAY case study as a replacement for the existing StoryBrand orchestrator.
- Letting downstream craft polish cognitively heavy language before the one-hole problem and repeatability lock are fixed.

## Quality Bar

A good Message Clarity Pack should let a non-specialist understand:

- what problem the business solves
- why that problem matters to the customer
- how the business helps
- what changes for the customer
- what phrase should repeat everywhere
- where the phrase gets deployed first
