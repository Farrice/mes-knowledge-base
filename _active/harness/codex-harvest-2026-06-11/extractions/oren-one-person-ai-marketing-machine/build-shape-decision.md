# Build Shape Decision

## Verdict

Build `/oren-solo-ai-marketing-machine` as a workflow inside `oren-archetype-social-strategy`, with source and cold command bridges. Do not create a new hot skill, new expert, real subagent, global mirror, or duplicate Oren package.

## Why This Shape

The source teaches an operating cadence, not a standalone domain. It connects planning, content, paid creative, conversion, email, creator sourcing, and referral loops. A workflow is the right surface because it can orchestrate existing Oren capabilities while keeping the source-specific solo-AI method compact.

## Rejected Shapes

| Shape | Reason rejected |
|---|---|
| New Oren skill | Existing Oren skill family already owns the domain; this would duplicate expertise. |
| Semantic primitive only | The user wants executable marketing behavior, not just a concept note. |
| Hot command wrapper | Existing Oren workflows mostly use lightweight cold bridges; no need to expand the hot surface. |
| Content-team architecture replacement | Solo-AI mode is a constrained mode before or beside a pod, not a replacement for the pod system. |
| External export | The work is an internal capability enhancement, not a client deliverable. |
