## Core Mechanism

### The Work Primitive Layer

Every valuable business process contains smaller units of meaning:

- what the action is for
- what input counts as valid
- what source of truth controls the decision
- what the agent may do
- what it must not do
- what good output looks like
- where a human decision is required

Most SOPs describe steps. Most prompt libraries describe requests. Neither gives an AI agent the operating meaning it needs.

The Work Primitive Layer converts messy business knowledge into semantic documents and command surfaces that make the work executable, testable, and maintainable.

## Objection Handling

| Objection | Strong Response |
|---|---|
| "We already have SOPs." | Good. SOPs are the source material. The question is whether an agent can execute from them without hidden explanation. Most SOPs explain steps, not authority, failure modes, examples, counterexamples, and validation. |
| "Could we just write better prompts?" | Sometimes. But prompts collapse when the work has recurring judgment, source-of-truth rules, approval boundaries, or quality tests. That is when you need an operating layer, not another phrasing attempt. |
| "We are not ready for full automation." | That is exactly why this starts before automation. First make the work legible, bounded, and testable. Automation should come after the operating layer proves itself. |
| "How do we know this will work?" | We do not ask you to believe it from a deck. We test one workflow cold-start: current asset versus semantic primitive. If the agent still needs hidden explanation, the document is not done. |
| "Is this just documentation?" | No. Documentation tells people what to do. This defines meaning, authority, validation, command surfaces, and maintenance so humans and agents can operate from the same source of truth. |
