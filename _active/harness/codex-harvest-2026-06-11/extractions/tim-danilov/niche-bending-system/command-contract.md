# Niche Bending Command Contract

## Invocation

`/niche-bending-system [expertise/domain/platform/outcome]`

## Required Inputs

- Core expertise or niche
- Target audience or market
- Primary platform
- Desired outcome: growth, authority, lead generation, offer differentiation, or content series

If these cannot be inferred, ask only for the missing execution-critical field.

## Optional Inputs

- Current content or format rut
- Competitors or benchmark creators
- Scout markets or borrowed format sources
- Existing proof, examples, constraints, or offers

## Components

- `/source-to-skill-system` for source-to-system framing.
- `/extraction-governor-agent` for build-shape and duplicate-system governance.
- `skills/tim-danilov-niche-bending/` for expert method.
- `extractions/video-context/fLDrB_wmbNE/` for timestamped evidence.
- `extractions/tim-danilov/niche-bending-system/` for command contract and source package.
- Existing Tim Danilov component workflows for market identification, viral format engineering, high-conversion content design, and multi-platform growth.

## Human Checkpoint

Ask when:

- the user has not provided or implied core expertise,
- the target audience is unclear,
- the platform changes the format rules,
- live external research or paid/quota-bound tools are required.

Skip the checkpoint when the missing detail only affects polish; state the assumption and continue.

## Context Policy

Keep the command workflow compact. Load source evidence, the Tim Danilov skill, and only the component workflow needed for the current phase. Do not preload every prompt in the skill package.

## Validation

The command output must pass:

- expertise constraint,
- proven-format evidence,
- empty-square logic,
- borrowed-fluency depth,
- visual-language specificity,
- platform-native execution,
- first-experiment clarity.
