# Lean Canvas Diagnostic

## Pre-Flight Gate

Use when an idea is still feature-led, fuzzy, or overbuilt in the founder's head. Do not recommend building until the business model and highest-risk assumption are explicit.

Load:
- `skills/ash-maurya-founder-systems/genius.md`
- `skills/ash-maurya-founder-systems/references/genius-patterns.md`

Required inputs:
- idea or current offer
- intended customer
- problem being solved
- current alternative
- desired outcome
- price or economic value guess
- available customer evidence

## Execution

1. **Extract The Raw Model**
   - Summarize the idea in one sentence.
   - Name the product/service, customer, outcome, and current alternative.
   - Mark anything invented by the founder as an assumption.

2. **Build The One-Page Model**
   - Customer segment: who is most likely to have the problem now?
   - Problem: what is painful, current, costly, and repeated?
   - Existing alternatives: what do they use, tolerate, or pay for today?
   - Unique promise: what outcome becomes possible?
   - Solution package: what minimum delivery proves the promise?
   - Channel: where can the founder reach triggered prospects this week?
   - Revenue: what price is anchored to the old way?
   - Cost: what must be spent or built to deliver the first proof?
   - Traction: what behavior proves the model is working?
   - Unfair advantage: what gets stronger after every validation loop?

3. **Rank Risks**
   - Score each block 1-5 for uncertainty and impact.
   - Identify the top three risks.
   - Convert each into an experiment question.

4. **Choose The Next Evidence Gate**
   - If problem is unproven, run `/ash-problem-validation`.
   - If segment is vague, run `/ash-customer-interview`.
   - If offer is unproven, run `/ash-offer-test`.
   - If demand is promising, run `/ash-traction-roadmap`.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Startup | Emphasize problem, early adopter, price, and commitment |
| Service | Emphasize delivery package, buyer pain, and paid audit path |
| Digital product | Emphasize outcome, channel, and proof before course/app build |
| Client work | Produce a diagnostic memo and validation sprint recommendation |

## Output Requirements

- One-page business model
- Top three risks
- Evidence score by block
- Next validation workflow
- Decision: proceed, narrow, pivot, or pause

## Quality Gate

Pass only if the output separates facts from assumptions and names one concrete behavior test. Fail if it praises the idea without identifying the riskiest unknown.
