# Demo-Sell-Build Sprint

## Pre-Flight Gate

Use when the founder wants to move fast without building blind. The sprint creates an offer test and commitment ask before product development.

- `skills/ash-maurya-founder-systems/genius.md`
- `skills/ash-maurya-founder-systems/references/hidden-knowledge.md`

## Execution

1. **Day 0: Choose The Assumption**
   - Pick the customer/problem/offer assumption that matters most.
   - Define what commitment proves it.

2. **Day 1 Morning: Discovery Calls**
   - Talk to 5-10 prospects.
   - Ask only behavioral questions.
   - Capture current alternative, trigger, cost, and frustration.
   - Start with: "Walk me through the last time you encountered this situation and tell me where you struggled."
   - Listen for pet peeves, struggles, workarounds, fired alternatives, and buying criteria.

3. **Day 1 Afternoon: Offer Assembly**
   - Restate the problem in the customer's words.
   - Name the old way and why it broke.
   - Convert repeated pet peeves, struggles, and workarounds into the offer promise.
   - Define outcome promise.
   - Create minimum demo: mockup, deck, walkthrough, sample, concierge flow, or Wizard of Oz process.
   - Anchor price to the old way.

4. **Day 2 Morning: Sell The Demo**
   - Return to qualified prospects.
   - Say: "Based on what you told me, I put together a way to solve this specific problem. Can I show you?"
   - Walk through last-time story, old-way failure, buying criteria, promise, demo, timeline, price.

5. **Day 2 Afternoon: Ask For Commitment**
   - Level 4: payment or deposit.
   - Level 3: signed pilot or calendar commitment.
   - Level 2: intro to budget owner or data access.
   - Level 1: interested but no cost.
   - Level 0: polite compliment.

6. **Decide**
   - Build if enough Level 3-4 commitments exist.
   - Revise if objections are concentrated.
   - Pivot if problem/segment is weak.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Software | Demo can be clickable mockup or manual backend |
| Service | Demo is delivery outline and first artifact preview |
| Course/product | Demo is transformation map and sample module |
| Internal tool | Demo is workflow simulation and adoption commitment |

## Output Requirements

- 48-hour sprint plan
- Demo outline
- Offer script
- Commitment ladder
- Build decision

## Quality Gate

Pass only if the sprint asks for a real resource commitment. Fail if the outcome is "people liked the demo."
