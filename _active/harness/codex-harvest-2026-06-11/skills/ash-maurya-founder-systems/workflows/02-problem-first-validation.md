# Problem-First Validation

## Pre-Flight Gate

Use when the founder has an idea but not enough evidence that the problem is worth solving. The goal is not to test the solution. The goal is to prove the problem exists without pitching.

## Execution

1. **Name The Problem Hypothesis**
   - Write the problem as a customer struggle, not a product gap.
   - Identify the current alternative and likely workaround.

2. **Define Early Adopter Candidates**
   - Segment by trigger, not demographics.
   - Look for people with recent urgency, active workaround, budget, or visible stakes.

3. **Design The Evidence Hunt**
   - Find 5-10 reachable prospects this week.
   - Use advice-seeking outreach: "I'm studying this problem and would value your experience."
   - Avoid showing the solution.

4. **Run Behavioral Questions**
   - "Walk me through the last time this happened."
   - "What triggered it?"
   - "What did you try?"
   - "What happened next?"
   - "What did it cost in time, money, delay, or reputation?"

5. **Score Problem Intensity**
   - Recent: happened in the last 30-90 days.
   - Repeated: not a one-off annoyance.
   - Costly: measurable pain or opportunity cost.
   - Active: they tried something already.
   - Urgent: they would spend resources to fix it.

6. **Decide**
   - Proceed if at least 30% show high intensity.
   - Narrow if intensity exists in only one segment.
   - Pivot if the problem is mostly theoretical.
   - Pause if prospects cannot be reached.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| New app | Do not show screens until the problem is proven |
| Consulting offer | Validate paid urgency and current vendor/workaround |
| Creator product | Validate actual attempts to solve, not audience likes |
| B2B | Ask about last workflow, budget owner, delay cost, and current tool |

## Output Requirements

- Problem hypothesis
- Early adopter segment
- Interview target list
- Evidence table
- Problem intensity score
- Proceed/narrow/pivot/pause decision

## Quality Gate

Pass only if evidence is behavioral. Fail if the validation is based on "people said they liked it."
