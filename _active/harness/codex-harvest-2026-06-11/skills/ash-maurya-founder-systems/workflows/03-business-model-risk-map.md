# Business Model Risk Map

## Pre-Flight Gate

Use when a founder has many possible next moves. This workflow prevents random action by identifying the riskiest assumption that can kill the model fastest.

Load:
- `skills/ash-maurya-founder-systems/genius.md`
- `skills/ash-maurya-founder-systems/references/quality-rubric.md`

## Execution

1. **Inventory Assumptions**
   - Customer: who has the problem now?
   - Problem: what hurts enough?
   - Alternative: what gets fired?
   - Promise: what outcome matters?
   - Price: what value anchor supports the ask?
   - Packaging: what minimum delivery proves the promise?
   - Channel: where are prospects reachable?
   - Commitment: what signal counts?

2. **Classify Risk Type**
   - Desirability: do they want it?
   - Viability: will they pay enough?
   - Feasibility: can we deliver?
   - Reachability: can we find them?
   - Defensibility: will learning compound?

3. **Score Each Assumption**
   - Impact: 1-5
   - Uncertainty: 1-5
   - Evidence strength: 0-5
   - Risk score: impact plus uncertainty minus evidence

4. **Select The Next Test**
   - Choose the highest-risk assumption that can be tested within 48 hours to 2 weeks.
   - Define pass/fail threshold.
   - Define what changes if the test fails.

5. **Create The Experiment Queue**
   - Now: one test to run immediately.
   - Next: two follow-up tests.
   - Later: tests blocked by current evidence.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Pre-product startup | Bias toward customer/problem/price risk |
| Existing product | Bias toward switching force and conversion risk |
| Service offer | Bias toward willingness to pay and delivery proof |
| Internal system | Bias toward adoption behavior and workflow fit |

## Output Requirements

- Assumption inventory
- Ranked risk map
- First experiment brief
- Pass/fail threshold
- Decision rule

## Quality Gate

Pass only if the founder knows exactly what not to do yet. Fail if the output produces a generic backlog.
