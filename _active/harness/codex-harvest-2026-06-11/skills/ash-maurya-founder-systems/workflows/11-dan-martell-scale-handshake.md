# Dan Martell Scale Handshake

## Pre-Flight Gate

Use only after problem, offer, and demand have meaningful evidence. Do not scale guesses.

Load:
- `skills/ash-maurya-founder-systems/genius.md`
- `skills/dan-martell-business-scaling/SKILL.md`
- `skills/dan-martell-business-scaling/genius.md`

## Execution

1. **Verify Validation Evidence**
   - Segment.
   - Problem intensity.
   - Offer.
   - Price.
   - Commitments or revenue.
   - Delivery constraints.

2. **Translate To Scaling Inputs**
   - What customers bought.
   - Why they switched.
   - What delivery promise must be protected.
   - What breaks if demand triples.

3. **Run Constraint Handoff**
   - If delivery breaks, use Dan's constraint audit.
   - If founder time breaks, use buyback audit.
   - If offer economics break, use irresistible offer architect.
   - If growth loop is unclear, use flywheel designer.

4. **Create Scale-Ready Plan**
   - Protect validated promise.
   - Remove first bottleneck.
   - Define leading indicators.
   - Prevent premature product-line expansion.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Service | Convert delivery constraint into SOP/delegation sequence |
| SaaS | Convert pilot learnings into onboarding and retention metrics |
| Productized offer | Preserve narrow promise before adding tiers |
| Agency/client | Hand off evidence into implementation roadmap |

## Output Requirements

- Validation summary
- Scaling constraint diagnosis
- Dan Martell workflow recommendation
- 30/60/90 scale plan
- Metrics to protect

## Quality Gate

Pass only if the handoff preserves the validated customer promise. Fail if scaling advice ignores what customers actually bought.
