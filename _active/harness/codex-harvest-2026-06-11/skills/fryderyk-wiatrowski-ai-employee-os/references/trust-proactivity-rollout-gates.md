# Trust, Proactivity, And Rollout Gates

## Proactivity Ladder

| Stage | Behavior | Gate |
|---|---|---|
| 0. Silent observe | Learn context without interrupting. | Only allowed data sources. |
| 1. Responsive suggest | Suggest when asked or clearly relevant. | No action taken. |
| 2. Ask to draft | Ask before preparing a deliverable. | User confirms direction. |
| 3. Draft for review | Produce a reversible draft. | Human review required. |
| 4. Sandbox action | Act in a local/test environment. | No external effect. |
| 5. Approved action | Act after explicit approval. | Audit trail required. |
| 6. Narrow autonomy | Act inside a small proven scope. | Regression checks stay clean. |
| 7. Broader activation | More users/surfaces. | Security, trust, and quality proof. |

## Rollout Sequence

1. Local private run.
2. Repeated successful runs on known tasks.
3. Small trusted cohort.
4. Scoped team surface.
5. Broader activation only after proof.

## Proactivity Kill Switches

- User says stop, pause, quiet, no notifications, or no next steps.
- Sensitive data appears outside approved scope.
- Regression guard detects tone, leakage, or output drift.
- Integration owner revokes access.
- The system cannot explain why it is interrupting.
