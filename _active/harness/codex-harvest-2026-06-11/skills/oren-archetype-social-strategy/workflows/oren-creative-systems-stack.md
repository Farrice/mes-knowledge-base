# Oren Creative Systems Stack

## Pre-Flight Gate

Load `../genius.md` and `../../oren-operational-systems/genius.md` if available. Install one system first; do not prescribe all systems unless the user is building an org-wide operating layer.

## Input Required

- Current creative bottleneck
- Work type: content, client work, campaigns, design, writing, brand social, agency, or internal team
- Team size and collaborators
- Tools already in use
- Immediate goal: ship faster, organize ideas, manage clients, delegate, measure content, or scale team output

## Execution

1. **Find The Friction**
   - Reference hunting
   - Idea chaos
   - Blank calendar
   - Lost footage/assets
   - Client/stakeholder anxiety
   - Team task invisibility
   - Delegation failure
   - Content pillar drift

2. **Choose The First System**

| Bottleneck | First System |
|---|---|
| Reference hunting | Reference repository |
| Too many ideas/no schedule | Ideas list plus calendar |
| Lost footage | Phone folders plus favorites |
| Client anxiety | Weekly update |
| Invisible team work | Team tracker |
| Hiring/delegation chaos | Loom-first process docs |
| Content inconsistency | Signature series |
| Strategy guessing | Content pillar measurement |

3. **Design The Schema**
   - Keep it minimal on day one.
   - Include growth columns that can be used later.
   - Define update cadence and owner.

4. **Write The Operating Rule**
   - When the system is updated.
   - Who updates it.
   - What gets stored.
   - How it is reviewed.
   - What decision it supports.

5. **Add The Next Two Systems**
   - Sequence systems by dependency.
   - Do not activate them until the first system is usable.

## Content Type Adaptations

| Use Case | Adaptation |
|---|---|
| Solo creator | Start with ideas/calendar and phone folders |
| Freelancer | Start with weekly updates and process docs |
| Small agency | Start with team tracker and process docs |
| Brand social team | Start with content pillar measurement and reference repository |
| Creative director | Start with reference repository and weekly review rhythm |

## Output Requirements

Produce:

- **Friction Diagnosis**
- **First System Verdict**
- **System Schema**
- **Operating Rule**
- **Setup Checklist**
- **30-Day Use Protocol**
- **Next Two Systems**
- **Skip List**

## Quality Gate

The system fails if it requires heroic maintenance. It passes if the user can update it during normal work without scheduling a separate productivity ceremony.
