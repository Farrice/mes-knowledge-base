# Brandon Jacoby - Taste Operating Profile

## Pre-Flight Gate

Load `../genius.md`. Treat taste as operating judgment, not aesthetic preference.

## Input Required

- User, brand, client, or system being calibrated
- Current body of work or representative examples
- What "good enough" currently looks like
- What higher-standard work must change

## Workflow

1. **Extract Standards**: Identify recurring likes, dislikes, references, avoidances, and moments where the user says something feels off.
2. **Name the Consequence**: Define what the user's taste must improve: clarity, status, trust, memorability, revenue, speed, beauty, or originality.
3. **Classify Defaults**: Separate useful conventions from stale inherited habits.
4. **Write the Taste Persona**: Produce a reusable agent profile with decision rules, anti-patterns, and preferred pressure tests.
5. **Create the Taste Bar**: Define minimum acceptable, strong, and master-level markers.
6. **Set the Practice Loop**: Prescribe weekly artifact review, reference capture, and push-past-good-enough exercises.

## Content Type Adaptations

| Type | Adaptation |
|---|---|
| Personal brand | Focus on signature point of view, reference lineage, and public standards |
| Client work | Focus on decision rules that survive business pressure |
| Product design | Focus on pattern/invention judgment and user feeling |
| Agent system | Focus on reusable quality gates and routing rules |

## Output Requirements

- Taste-master persona
- Decision principles
- Pattern vs. invention defaults
- Good-enough warning signs
- Personal quality rubric
- First 7-day taste practice loop

## Quality Gate

Fails if the output is a list of preferences without operational decision rules.
