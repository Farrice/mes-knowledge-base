# Value Spotlight Map

Use this when the user has a topic but the piece does not yet have a clear reader-value promise.

## Pre-Flight Gate

Confirm the input includes at least a topic, audience, and intended format. If format is unknown, default to newsletter/article.

Before drafting, answer Cole's core question: **what am I giving the reader?**

## Skill Acquisition

Load:

- `skills/nicolas-cole-nonfiction-value-architecture/genius.md`
- `skills/nicolas-cole-nonfiction-value-architecture/references/source-map.md`

## Execution

1. Restate the topic as a reader problem, not a writer topic.
2. Score all ten value modes against the topic:
   - Tips
   - Stats
   - Steps
   - Lessons
   - Benefits
   - Reasons
   - Mistakes
   - Examples
   - Questions
   - Story
3. Choose one spotlight mode. Secondary modes may support it, but one mode must lead.
4. Write the value promise in this format: "The reader gets [mode] that help them [specific outcome]."
5. Create the first list of deliverables. If the spotlight is tips, list the tips. If it is mistakes, list the mistakes.
6. Flag weak or bundled list items for the Specificity Ladder.

## Content Type Adaptations

| Type | Adaptation |
|---|---|
| Newsletter | Choose the value mode for this single edition, not the whole publication |
| LinkedIn post | Keep the list to 3-5 strong deliverables |
| YouTube script | Use the spotlight mode to shape title, cold open, and segment labels |
| Lead magnet | Prefer steps, mistakes, questions, or examples because they feel saveable |
| Client ghostwriting | Preserve client voice after the value mode is chosen |

## Output Requirements

Return:

- Topic reframed as reader problem
- Ten-mode scorecard
- Recommended spotlight mode
- Value promise
- First deliverable list
- Items needing specificity upgrade

## Quality Gate

Do not proceed to drafting until the value promise names what the reader receives. Reject outputs that only say the piece is "about" a topic.
