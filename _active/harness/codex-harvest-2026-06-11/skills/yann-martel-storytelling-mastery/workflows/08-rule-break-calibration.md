# Rule Break Calibration

## Pre-Flight Gate
Inputs required:
- Draft or planned experiment.
- The rule being broken.
- Purpose of the break.
- Reader tolerance level.

Load `../genius.md`.

## Skill Acquisition
Use Martel's rule principle: know the rule, break it for a reason, and preserve enough structure for the reader.

## Execution
1. **Name the Rule**: State the convention clearly.
2. **Name the Payoff**: Explain what the break creates that normal form cannot.
3. **Find the Handrails**: Choose which conventions remain intact.
4. **Stress-Test Annoyance**: Identify where the reader may feel the author showing off.
5. **Produce the Calibrated Version**: Give a plan or rewrite with the break serving the piece.

## Content Type Adaptations
| Type | Adaptation |
|---|---|
| Fiction | Break form while preserving scene pressure |
| Essay | Break structure while preserving argument clarity |
| Landing Page | Break pattern only if clarity improves |
| Visual Text | Use layout only when it carries meaning |
| Social Content | Avoid gimmicks that outshine the idea |

## Output Requirements
Produce:
- `Rule Being Broken`
- `Purpose`
- `Reader Handrails`
- `Risk Points`
- `Calibrated Execution`

## Quality Gate
- The break has a reason.
- The reader has orientation.
- The effect is not self-advertising.
- At least one stabilizer remains.
