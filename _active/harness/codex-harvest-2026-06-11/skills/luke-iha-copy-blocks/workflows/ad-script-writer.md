## PHASE 2: INPUT REQUIREMENTS

Collect from user:
- **Product/Offer**: What's being sold?
- **Target Audience**: Who is this for?
- **Ad Format**: Text, video script, static image, carousel?
- **Length**: Short (< 60 sec / 200 words), Medium (60-120 sec / 200-500 words), Long (120+ sec / 500+ words)
- **CASH Selection** (optional): If from a CASH matrix, which Concept × Angle × Style?
- **Mechanism** (optional): If using a mechanism from `million-dollar-mechanisms`, provide name + one-sentence explanation
- **Key Proof Points** (optional): Testimonials, data, credentials to include

## PHASE 3: HOOK GENERATION

Write 3 hook variants using different architectures:
1. **Solve Hook**: Identifies the problem and implies a solution
2. **Show Hook**: Demonstrates a result
3. **Wild Card**: Contrarian, story, proof-of-work, or confession — whatever fits best

Each hook: 1-2 sentences max. Should stop the scroll and create momentum into the body.

## PHASE 3.5: BELIEF-STATE SEQUENCING

**Before writing body copy, map the reader's belief journey.** Block order is not fixed — it adapts to what the reader needs psychologically at each transition point.

### Step A: Entry State Diagnosis

After the hook lands, diagnose the reader's psychological state:

| Dimension | Question | Answer for THIS reader |
|-----------|----------|----------------------|
| **Problem Awareness** | Do they already feel the pain, or does it need to be surfaced? | [High/Medium/Low] |
| **Solution Awareness** | Do they know solutions exist, or is this category new? | [High/Medium/Low] |
| **Trust Level** | Are they skeptical of this type of offer, or open? | [Skeptical/Neutral/Open] |
| **Urgency** | Is there natural time pressure, or does it need to be created? | [Inherent/Needs Creation] |
| **Identity Fit** | Will they immediately self-identify, or need to be qualified in? | [Obvious/Needs Framing] |

### Step B: Sequence the Blocks by Belief Need

Use this decision logic — what the reader NEEDS at each transition determines the next block:

**After Hook (reader is curious but uncommitted):**
- If Problem Awareness is LOW → next block = **Pain** (surface what they're ignoring)
- If Problem Awareness is HIGH → next block = **Promise** (they know the pain — show the exit)
- If Trust Level is SKEPTICAL → next block = **Proof** early (earn the right to keep talking)
- If Identity Fit NEEDS FRAMING → next block = **Conditions** (qualify them in through recognition)

**After Pain (reader feels the problem):**
- If they doubt solutions exist → **Curiosity** (open a loop about the mechanism)
- If they're ready for hope → **Promise** (show the outcome)
- If the pain needs to compound → **Conditions** (qualify: "if you're the type who...")

**After Promise (reader wants the outcome):**
- If they're thinking "too good to be true" → **Proof** (evidence immediately)
- If they're thinking "how?" → **Curiosity** then **Proof** (tease mechanism, then prove it)
- If they're thinking "is this for me?" → **Conditions** (qualify them in)

**After Proof (reader believes it's possible):**
- If they're thinking "but what about [objection]?" → **More Proof** (different type — stack)
- If they believe but aren't moving → **Constraints** (urgency/scarcity)
- If they believe but need the mechanism → **Curiosity** (open the "how" loop)

**After Constraints (reader feels urgency):**
- Almost always → **Promise** restatement + **CTA**
- If trust still shaky → one final **Proof** then CTA

**After Conditions (reader self-identifies):**
- If qualified in → **Promise** (personalized to their situation)
- If needs proof → **Proof** (specific to their segment)

### Step C: Write the Belief-State Map

Output a 6-8 step sequence showing:
1. The block
2. What the reader BELIEVES at entry to this block
3. What the reader should BELIEVE at exit
4. Why THIS block comes next (the transition logic)

Example:
```
1. [HOOK — CU] Reader: scrolling. → Reader: "Wait, what?"
2. [PAIN — P] Reader: curious but unaware. → Reader: "Oh... I have this problem." 
   WHY: Low problem awareness — need to surface pain before promising anything.
3. [CURIOSITY — CU] Reader: feels pain, wants escape. → Reader: "There's a method for this?"
   WHY: Reader is now motivated but doesn't know solutions exist. Tease before revealing.
4. [PROOF — PF] Reader: intrigued but skeptical. → Reader: "OK, this actually works."
   WHY: Curiosity without proof creates doubt. Earn credibility before the full promise.
5. [PROMISE — PR] Reader: believes it's possible. → Reader: "I want this result."
   WHY: Proof unlocked trust — now the promise lands with weight instead of feeling hollow.
6. [CONDITIONS — CO] Reader: wants outcome. → Reader: "This is specifically for someone like me."
   WHY: Reader needs to self-identify before they'll act. Generic desire ≠ personal decision.
7. [CONSTRAINTS — CN] Reader: wants it, identified with it. → Reader: "I need to act now."
   WHY: Desire without urgency = "I'll do it later" (never).
8. [CTA — PR/CO] Reader: motivated, identified, urgent. → Reader: takes action.
```

## PHASE 4: BODY COPY CONSTRUCTION

Build the body following the Belief-State Map from Phase 3.5 — NOT a fixed template.

For each block in the sequence:
- Write copy that moves the reader from the ENTRY belief to the EXIT belief
- Tag each section with its copy block code AND the belief transition
- Ensure each block uses a fresh angle if the same block type reappears

Maintain velocity rules from genius.md:
- No block dominates more than 3 consecutive sentences
- Opening hits 3+ blocks in first 5 sentences
- Pre-CTA velocity drops deliberately to create weight

## PHASE 5: VELOCITY CHECK

Before outputs:
1. Map the block sequence of the complete script
2. Check for velocity drops (4+ consecutive same-block sentences)
3. Verify opening hits 3+ blocks in the first 5 sentences
4. Confirm each block uses fresh angles on reappearance
5. Verify each block transition follows from the Belief-State Map logic — no block should appear without a psychological reason
