# Comedy Rep Loop

## Use When

A recurring idea, story, post type, keynote bit, or content theme needs repeated development instead of one-pass polish.

## Inputs

- Premise.
- Audience.
- Current version.
- Where it has been tested, if anywhere.
- Feedback or response signals.

## Steps

1. Write the premise in one sentence.
2. Generate 10 rough versions, including dumb versions.
3. Sort by charge, recognition, surprise, and trust risk.
4. Pick the top three to test.
5. Define the smallest test: conversation, internal review, post, email, or live delivery.
6. Capture response evidence.
7. Revise only after response.

## Output

```markdown

- **Premise:**

- **Test surface:**
- **Response signal to capture:**

- **Stop condition:**
```

## Quality Gate

Do not call a recurring bit finished after one pass. It needs response evidence or a clear reason to stop.
