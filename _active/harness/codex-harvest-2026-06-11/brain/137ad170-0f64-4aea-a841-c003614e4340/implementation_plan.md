**Pipeline**:

3. **Accommodation Design** → Surprise + relevance + safety triggers engineered into the hook, body, and CTA (Pattern 2, HK 12)

**Cross-stack**: McRaney × Luke Iha proof ladder × Luke Iha copy blocks.

**Primary patterns**: 2, 16, 24, 25 | HK 1, 12

### 3. `/accommodation-audit` — Accommodation vs Assimilation Content Audit

**Produces**: Pass/fail diagnosis on any content piece + rewrite prescriptions. Universal quality gate.

**Pipeline**:
1. **Assimilation Test** → Can this message be comfortably absorbed into the reader's existing worldview without changing anything? (Pattern 2)
2. **Surprise Diagnosis** → Does this contain genuine cognitive surprise — something the audience's current model can't explain? (HK 12)
3. **Relevance Check** → Is the personal stake specific enough to warrant processing effort? (Pattern 24)
4. **Safety Scan** → If it IS surprising, is there a face-saving path for the reader to update? (Pattern 11)
5. **Rewrite Prescription** → Specific rewrites for any failing dimension

**Cross-stack**: Plugs into ANY content workflow as a final gate. Compatible with `/slop-check`, `/grace-quality-gate`, `/word-sprint`.

**Primary patterns**: 2, 11, 24 | HK 1, 12

### 4. `/belief-dissolve-copy` — Belief Dissolution Copywriting

**Produces**: Copy/content specifically engineered to dissolve a blocking belief that prevents purchase, signup, or action.

**Pipeline**:
1. **Belief Identification** → Name the specific blocking belief (Pattern 1 resistance classification)
2. **Origin Trace** → Trace belief to its emotional/experiential root using Lefkoe's method (HK 11, Pattern 17)
3. **Metacognitive Activation** → Engineer process questions that make the reader examine how they arrived at the belief — not whether it's correct (Pattern 26)
4. **Cognitive Dissonance Design** → Create the experience/evidence that the current model genuinely can't contain (Pattern 20, HK 12)
5. **Permission + Face-Saving** → Pre-build the identity bridge and face-saving narrative before the shift (Patterns 7, 11, 21)
6. **New Framework Delivery** → Provide the replacement belief structure only after dissonance has created the vacuum (Pattern 2)

**Cross-stack**: Can feed into Luke Iha VSL leads, Nicolas Cole ghostwriting, or any content engine.

**Primary patterns**: 1, 2, 7, 11, 17, 20, 21, 26 | HK 11, 12

### 5. `/resistance-proof-rx` — Resistance-Matched Proof Prescription

**Produces**: A proof strategy document specifying exactly which proof types to deploy against which resistance types — then produces the proof-fortified copy.

**Pipeline**:
1. **Resistance Diagnosis** → Classify audience resistance as technique rebuttal, topic rebuttal, or mixed (Pattern 25)
2. **Investment Scan** → Is sunk-cost protecting the belief? (Pattern 23)
3. **Proof Type Matching** → Map resistance type to Luke Iha's 22-type proof arsenal:
   - Technique rebuttal → transparency proof, permission proof, metacognitive questions
   - Topic rebuttal → empirical proof, third-party proof, demonstration proof
   - Sunk-cost anchoring → investment-acknowledgment proof, gradual-migration proof
4. **Proof Sequencing** → Order proofs using staged delivery logic (Pattern 16)
5. **Copy Production** → Produce proof-braided copy using the matched proof stack

**Cross-stack**: McRaney × Luke Iha proof ladder + copy blocks. The bridge between "why they resist" and "what proof dissolves it."

**Primary patterns**: 16, 23, 25 | HK 1

### 6. `/threshold-campaign` — Threshold-Optimized Campaign Builder

**Produces**: Multi-touchpoint campaign where each touchpoint targets a specific variable in the threshold equation.

**Pipeline**:
1. **Threshold Equation** → Score all 8 variables 1-10 (Pattern 13)
2. **30% Calibration** → Calculate evidence burden vs social cost ratio (HK 13)
3. **Binding Constraint ID** → Name the single variable that, if changed, tips the balance (Pattern 18)
4. **Social Death Audit** → Score tribal/face/relationship/status costs (Pattern 5)
5. **Campaign Architecture** → Design touchpoints:
   - If binding constraint is evidence → Evidence-delivery campaign (central route)
   - If binding constraint is social cost → Social permission campaign (Patterns 6, 21)
   - If binding constraint is identity → Identity bridge campaign (Pattern 7)
   - If binding constraint is trust → Trust-before-persuasion sequence (Pattern 15)
6. **Touchpoint Sequencing** → Each touchpoint shifts exactly one equation variable (Pattern 16)
7. **Content Brief per Touchpoint** → Deliverable spec for each piece

**Primary patterns**: 5, 6, 7, 13, 15, 16, 18, 21 | HK 13

### 7. `/metacognitive-content` — Metacognitive Thought Leadership Engine

**Produces**: Thought leadership content (LinkedIn, newsletters, YouTube scripts, articles) that triggers genuine self-examination in the reader — not just information delivery.

**Pipeline**:
1. **Topic → Belief Audit** → What does your audience currently believe about this topic? (Pattern 1)
2. **Evaluation Mode Activation** → Engineer the opening to shift readers from production mode (defending position) to evaluation mode (examining reasoning) (Pattern 22, Pattern 9)
3. **Metacognitive Question Design** → Build process questions into the content structure: "How did you first come to think about it this way?" patterns embedded in the narrative (Pattern 26)
4. **Surprise Engineering** → Design the genuine cognitive surprise — the thing their model can't contain (HK 12)
5. **Resolution Architecture** → Provide the replacement framework only after metacognition is active (Pattern 2)
6. **Accommodation Gate** → Final check: does this produce "I never thought of it that way" or "Yeah, I already knew that"?

**Cross-stack**: Feeds into Nicolas Cole ghostwriting, Lara Acosta LinkedIn, Grace Andrews media company workflows. Works for any platform.

**Primary patterns**: 1, 2, 9, 22, 26 | HK 1, 12

### 8. `/elm-content-strategy` — ELM-Informed Content Strategy

**Produces**: Platform × processing route matrix with matched content prescriptions for every channel.

**Pipeline**:
1. **Audience Processing Profile** → For this specific audience, score motivation + ability per platform (Pattern 24)
2. **Route Map** → Central, peripheral, or dual for each platform:
   - LinkedIn long-form → likely central among engaged followers, peripheral for feed browsers
   - Instagram/TikTok → predominantly peripheral (low ability due to format)
   - Email to subscribers → high motivation, central capable
   - YouTube → dual (peripheral hook, central depth)
3. **Mismatch Diagnosis** → Identify where current content uses central-route messaging on peripheral-route platforms (the #1 structural error)
4. **Format Prescriptions** → For each platform × route combination, specify:
   - Content format (story vs argument vs demonstration)
   - Proof type (credibility cues vs evidence vs social proof)
   - Hook style (authority signal vs curiosity vs relatability)
5. **Content Calendar Architecture** → Map content types to platforms with route-matched messaging

**Cross-stack**: Informs Lara Acosta LinkedIn strategy, Grace Andrews media company build, Kallaway content psychology.

**Primary patterns**: 24 | HK 1, 12

### 9. `/social-permission-campaign` — Social Permission & Norm-Shift Campaign

**Produces**: Campaign designed to reduce the social cost of adopting/buying — for when the problem isn't information but social risk.

**Pipeline**:
1. **Social Death Calculation** → Score tribal/face/relationship/status costs (Pattern 5)
2. **Pluralistic Ignorance Detection** → Does the audience privately agree but publicly resist because they think they're alone? (Pattern 6)
3. **Permission Architecture** → Map all required permissions: self, social, authority, peer (Pattern 21)
4. **Anxiety Diagnosis** → Is the real objection anxiety-based rather than logical? (Pattern 8)
5. **Environment Design** → Design the context that makes change feel safe (Pattern 10)
6. **Face-Saving Narrative** → Pre-build the story that lets them change without looking wrong (Pattern 11)
7. **Campaign Architecture** → Produce content/ads/touchpoints that:
   - Surface the pluralistic ignorance ("you're not alone")
   - Provide each permission type in sequence
   - Offer the face-saving narrative before asking for the change
   - Create social proof of the norm shift

**Primary patterns**: 5, 6, 8, 10, 11, 21 | HK 2, 5, 7

### 10. `/belief-creative-brief` — Belief-Layer Creative Brief

**Produces**: The master pre-production document. A brief that any copywriter, content strategist, or creative director reads before producing anything — with belief architecture built in.

**Pipeline**:
1. **Quick Canvass** → Compressed version of `/mcraney-deep-canvass` — surface beliefs, resistance hierarchy, top 3 processing chains (Patterns 1, 4)
2. **ELM Diagnosis** → Central/peripheral/dual + rebuttal type prediction (Patterns 24, 25)
3. **Threshold Summary** → Binding constraint + 30% calibration + minimum viable intervention (Patterns 13, 18, HK 13)
4. **Accommodation Triggers** → Specific surprise/relevance/safety design for this brief (Pattern 2, HK 12)
5. **Social Cost Map** → Social death scores + permission requirements (Patterns 5, 21)
6. **Messaging Prescriptions**:
   - Hook direction (matched to ELM route)
   - Proof types needed (matched to rebuttal type)
   - Belief sequence (order of shifts)
   - Identity bridge language
   - Face-saving narrative to include
7. **Anti-Patterns** → Specific things NOT to do based on the diagnosis

**Cross-stack**: The universal input document for `/persuasion-copy`, Luke Iha workflows, Nicolas Cole ghostwriting, any content engine. This is the McRaney intelligence layer translated into a format any production workflow can consume.

**Primary patterns**: 1, 2, 4, 5, 13, 18, 21, 24, 25 | HK 12, 13
