## Execution Sequence

### 1. Vehicle Selection

Pick the first sellable vehicle by matching urgency, proof burden, and delivery bandwidth:

- Choose the prompt pack if speed and low fulfillment are the priority.
- Choose the audit service if buyer trust and cash collection matter most.
- Choose the async playbook if the user already has proof, audience, and repeatable examples.
- Choose the cohort only when there is enough demand or authority to support live delivery.

### 2. Workflow Packaging

Map each Perception workflow to a buyer-visible job:

- `/behavioral-copy-audit`: diagnose why current copy does not convert.
- `/blind-spot-social-engine`: create content that shifts how the market sees the problem.
- `/insight-perception-sprint`: generate authority angles and content vectors.
- `/positioning-perception-siege`: make the offer harder to compare.
- `/perception-dopamine-engine`: build the sales asset.
- `/perception-dominance-campaign`: integrate the full campaign.

### 3. Product Asset Build

Produce the first asset set:

- One-liner and promise for the product.
- Table of modules or prompt packs.
- Buyer transformation map.
- Sample output from one workflow.
- Checkout-ready offer description.
- First Parallax/newsletter issue or LinkedIn post driving to the product.

### 4. Launch Path

Build a 72-hour launch path:

- Day 1: package the first vehicle and create one proof sample.
- Day 2: publish the perception-shift issue/post and collect interest.
- Day 3: send the offer, collect buyers, and deliver the first audit or prompt pack.

For longer windows, expand into a 14-day validation sprint, a 30-day funnel, or a 90-day cohort build.

## Output

Return a product deployment brief with:

- Recommended first vehicle
- Product ladder
- First offer page copy
- Core workflow map
- 72-hour launch plan
- Proof sample to show buyers
- Validation metric and stop/continue rule

## Quality Gate

- The first product can be sold without building a complex platform.
- The buyer can understand the transformation in one sentence.
- Each deliverable points back to an existing workflow command.
- The launch path includes one proof asset and one distribution action.
- The plan avoids creating more internal machinery before testing demand.
