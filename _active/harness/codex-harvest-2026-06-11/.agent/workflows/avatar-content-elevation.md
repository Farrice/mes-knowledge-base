# /avatar-content-elevation — Avatar-Led Content Elevation Pipeline

Build a launch-ready content package that starts with buyer truth, then rewrites profile/content/platform assets so they feel specific, useful, emotionally alive, and commercially grounded.

Use this when a plan, brand, offer, profile, or content system is "good but not landing" and needs the same kind of third-pass upgrade produced for Coach Cooz: deeper ICP/avatar, sharper belief architecture, better reader value, stronger LinkedIn/Instagram/YouTube/blog assets, and repeatable voice capture.

## Usage

```text
/avatar-content-elevation [client/brand/project + source files or folder]
/avatar-content-elevation "Coach Cooz V6 files + Codex pass"
```

## Output Contract

Create an artifact folder:

```text
brain/[client-slug]-avatar-content-v[version]/
```

The folder must contain:

1. `README.md`
2. `AVATAR-ICP-BELIEF-PROFILE.md`
3. `CONTENT-STRATEGY-V3.md` or next available version
4. `LINKEDIN-POSTS-V3.md` or platform-primary equivalent
5. `INSTAGRAM-YOUTUBE-BLOG-CASCADE-V3.md` or relevant platform cascade
6. `VOICE-MEMO-INTAKE-PROMPTS.md`

If the user asks for a narrower scope, preserve the same sequence but reduce the number of assets.

## Core Principle

Do not polish the content first.

Find the buyer first.

The final package should make the intended buyer feel:

1. "This sees me accurately."
2. "This names something I could not quite name."
3. "This gives me a practical next move."
4. "This person is specific enough to trust."

## Workflow Stack

Run the stack in this order. Use the named workflows/skills when available; otherwise apply the protocol locally.

### 1. Audience Reaction Logic

Load and apply:

- `/content-audience-profile`
- Kieran Flanagan audience intelligence

Purpose:

- Identify what the audience is trying to evaluate.
- Separate theoretical ICP from content-reactive ICP.
- Define what the reader must get from each post besides proof of the client.

Output into the working notes:

- audience processing profile
- content reactivity assumptions
- reader value types
- purchase decision triggers

### 2. Avatar And ICP Excavation

Load and apply:

- Jun Yuh Avatar Psychographic Mapper
- Heath Brothers Deep ICP Excavation
- Dai Media Consumer Posture

Purpose:

- Build one primary buyer, not a vague segment.
- Add 1-3 secondary lanes only as entry paths, not separate ICPs.
- Map private conversation, trigger events, failed attempts, objections, and trust bridges.

Quality gate:

- The avatar must read like one human, not a demographic worksheet.
- The language bank must contain phrases a buyer would actually say or think.

### 3. Belief Architecture

Load and apply:

- `/belief-first-audience-intelligence`
- David McRaney belief change
- Dai Media posture translation

Purpose:

- Identify what the buyer believes now.
- Identify what that belief protects.
- Define the shift content must create.
- Determine where proof, empathy, authority, and social permission are needed.

Output:

- blocking belief map
- belief shifts
- objections beneath objections
- content that moves each belief

### 4. Strategic Content Architecture

Load and apply:

- Kallaway Strategic Market Architecture
- Kallaway Belief-Shift Content
- Diandra semantic lanes and save-worthy logic
- Lara/LinkedIn profile and hook discipline when LinkedIn is primary

Purpose:

- Define the content thesis.
- Choose semantic lanes.
- Assign each platform one job.
- Define reader value types and CTA rotation.
- Turn the buyer profile into a 30-day content test.

Quality gate:

- Every lane must have a reader payoff.
- No lane should exist only to talk about the client/brand.

### 5. Voice And Proof Translation

Load and apply:

- `/cooz-flywheel` or relevant voice-first flywheel if the project has one
- `/voice-first-content`
- proof/testimonial source docs
- any local voice profile, canon, ban list, or style guide

Purpose:

- Preserve authentic voice.
- Convert proof into proof-with-transfer.
- Prevent strategist language from replacing buyer language.

Output:

- voice rules
- ban list
- proof status notes
- permission and measurement cautions

### 6. Platform Cascade

Load and apply:

- Diandra LinkedIn if LinkedIn is primary
- Brock Johnson share-first Instagram logic if Instagram is included
- YouTube/blog search-intent logic when long-form support is included
- platform-adapt principles for all cross-platform work

Purpose:

- Rewrite for each platform, not copy-paste across platforms.
- Ensure Instagram has save/share reasons.
- Ensure YouTube answers objections with depth.
- Ensure blog assets target search/referral trust.

### 7. Final Tension And Anti-Slop Audit

Load and apply:

- `/comfort-trap-content`
- `/authenticity-audit`
- `/anti-slop-audit` or `/slop-check`

Purpose:

- Remove safe-but-forgettable copy.
- Remove AI cadence.
- Remove unsupported claims.
- Ensure emotional tension does not become manipulation.

Final question for every asset:

> What does the reader get from this besides knowing the client is good?

If the answer is weak, revise.

## Quality Gates

### Reader Value Gate

Every asset gives one of:

- checklist
- distinction
- diagnosis
- question
- minimum action
- belief shift
- proof transfer

### Buyer Truth Gate

Reject if:

- the buyer is described as a broad demographic only
- the private conversation sounds like marketer language
- the offer is clearer to the strategist than to the buyer
- the content assumes the buyer is most-aware too early

### Voice Gate

Reject if:

- the copy could belong to any coach/consultant
- the sentence rhythm is too polished or uniform
- the piece speaks at the buyer instead of across to them
- jargon replaces the buyer's words

### Proof Gate

Tag every major claim:

- verified fact
- observed pattern
- client quote
- hypothesis to test
- needs permission
- needs measurement verification

Unsupported claims must be softened or removed.

### Platform Gate

Reject if:

- Instagram is just LinkedIn screenshots
- YouTube has no search or objection purpose
- blog has no search intent
- LinkedIn has no profile/DM conversion role
- every platform uses the same CTA
