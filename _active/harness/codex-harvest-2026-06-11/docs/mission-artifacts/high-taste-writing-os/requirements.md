# Requirements: High-Taste Writing OS

Created: 2026-05-10
Mission: high-taste-writing-os

## Problem Frame
Design and implement a durable writing-quality operating layer so writing, copywriting, and content agents stop producing structurally sound but low-taste generic drafts; orchestrate existing taste, writing, copy, retention, and calibration assets into a scalpel-like workflow with validation and routing.

## Requirements
- R1. Add a command-invokable High-Taste Writing OS workflow that orchestrates taste, flow, reader pull, sentence craft, retention, conversion, and calibration without expert soup.
- R2. Wire the OS into Writing Agent, Copywriting Agent, Publishable Copy Gate, Autopilot, and Orchestrate for generic/flat/low-taste/poor-flowing writing.
- R3. Preserve the skill-system contract: explicit components, step order, inputs, outputs, handoffs, validation, result surface, context policy, and reuse hook.
- R4. Add verification so route discoverability and integration do not depend on memory.
- R5. Produce a pilot rewrite proving the new OS changes lines and flow, not just labels experts.

## Actors
- A1. Farrice as publisher and reviewer.
- A2. Writing Agent and Copywriting Agent.
- A3. Autopilot and Orchestrate as front doors.
- A4. Publishable Copy Gate as final public/revenue copy gate.

## Key Flows
- F1. User rejects writing as generic/flat -> route surfaces `/high-taste-writing-os` -> workflow creates reader contract, baseline, material ledger, architecture map, composed draft, scalpel passes, and Taste Evidence Ledger.
- F2. Copywriting Agent gets revenue copy that is structurally sound but unreadable -> High-Taste Writing OS runs before Publishable Copy Gate.
- F3. Future system check runs -> verifier confirms bridge files, integration terms, and natural language routing.

## Acceptance Examples
- AE1. Given "copy is structurally sound but not compelling," when workflow routing runs, then `/high-taste-writing-os` appears.
- AE2. Given a writing/copy agent handoff, when the work is flat or low-taste, then the agent routes to High-Taste Writing OS before finalizing.
- AE3. Given the AI Misfire pilot, when reviewed, then it includes reader contract, diagnosis, final draft, and Taste Evidence Ledger.

## Scope Boundaries
- In scope: workflow, command bridge, agent routing integration, verifier, mission artifacts, pilot rewrite, reusable solution capture.
- Out of scope: external publishing, marketplace application, payment setup, broad rewriting of every existing artifact, and real Codex subagent delegation.

## Open Questions
- Blocking: none.
- Deferred: broader regression fixtures for every writing style and live-market calibration after deployment.
