# Client Audit Delivery

## Purpose And Operating Definition

This primitive governs delivery of a fast, proof-first client audit. The work is not "write a report." The work is creating a credible diagnostic that shows the client where AI, agents, automation, or semantic documents can produce business leverage.

## When To Use

- Selling or fulfilling an AI Business Asset Audit.
- Creating a first paid diagnostic for a prospect.
- Turning public or supplied client materials into a practical implementation roadmap.

## When Not To Use

- When the user asks for broad strategy with no client or business target.
- When required private data is unavailable and the output would need to pretend it was inspected.
- When legal, financial, medical, or regulated advice would require a licensed professional.

## Inputs

| Input | Required | Source Of Truth | Notes |
|---|---|---|---|
| Client identity | Yes | User or public web | Verify current public facts when needed |
| Public assets or supplied files | Yes | Website, docs, exports, user files | Label what was actually reviewed |
| Business goal | Yes | User/client intake | Revenue, efficiency, risk, or speed |
| Constraints | Yes | User/client intake | Budget, timeline, tools, access |

## Outputs

| Output | Format | Destination | Owner |
|---|---|---|---|
| Audit findings | Markdown or doc | Client deliverable | Operator |
| Priority roadmap | Table | Client deliverable | Operator |
| First implementation step | Checklist | Client deliverable | Operator |
| Upsell path | Proposal notes | Internal or client-facing | Operator |

## Objects And Meaning

| Object | What It Means | Why It Matters |
|---|---|---|
| Finding | Evidence-backed diagnosis | Builds trust |
| Recommendation | Action tied to business outcome | Avoids generic AI advice |
| Priority | Ranking by value, speed, and difficulty | Creates momentum |
| Upsell | Next paid implementation | Turns audit into revenue path |

## Authority And Permissions

| Action | Agent May Do | Requires Approval | Never Do |
|---|---|---|---|
| Analyze public assets | Yes | No | Do not invent private data |
| Analyze supplied exports | Yes | No, if provided by user | Do not access private systems without connector/export |
| Draft client deliverable | Yes | No | Do not promise guaranteed revenue |
| Contact client | No | Explicit approval | Never send outreach automatically |

## Execution Protocol

1. Define the business objective and audit promise.
2. Inventory reviewed evidence.
3. Identify friction, leverage, risk, and semantic-readiness gaps.
4. Score each opportunity by speed, value, and difficulty.
5. Produce a 48-hour action plan.
6. Package a clear upsell tied to implementation.

## Decision Rules

| Condition | Rule | Reason |
|---|---|---|
| Evidence is public only | Label as public-asset audit | Avoid false authority |
| Private dashboard needed | Ask for export | Agents need actual data |
| Recommendation is high consequence | Add review or specialist caveat | Prevent overreach |

## Examples

### Good Example

"Based on the website, offer page, and three supplied call transcripts, the highest leverage first asset is a semantic sales-call handoff document because follow-up quality depends on unstated founder judgment."

### Counterexample

"You should use AI automations to scale faster" with no evidence, owner, or first step.

## Quality Tests

| Test | Pass Criteria | Failure Response |
|---|---|---|
| Evidence test | Every finding cites reviewed material | Remove or mark assumption |
| Actionability test | Client can act within 48 hours | Break into first step |
| Specificity test | Recommendation names workflow, owner, and outcome | Rewrite vague advice |
| Upsell test | Next paid step follows naturally | Reframe around implementation |

## Failure Modes

| Failure Mode | Early Signal | Prevention | Recovery |
|---|---|---|---|
| Generic AI advice | Could apply to any client | Anchor every point in evidence | Re-audit assets |
| Overclaiming | Mentions data not supplied | Maintain evidence inventory | Correct scope |
| No revenue path | Audit ends with ideas | Include implementation offer | Add upsell |

## Maintenance Protocol

- Owner: Client delivery operator.
- Review cadence: before each client delivery.
- Update triggers: new client data, new offer, new workflow, changed business goal.
