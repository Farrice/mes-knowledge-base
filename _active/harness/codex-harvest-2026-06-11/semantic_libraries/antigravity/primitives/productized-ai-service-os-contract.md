# Productized AI Service OS Contract

## Purpose

Use this primitive when a source, skill, or service idea should become a productized AI-assisted service: a clear off-the-shelf offer, a fast intake-to-value loop, a contained production queue, a quality gate, and a reusable client handoff.

This is not a generic agency playbook. It exists to prevent three failure modes:

- selling custom consulting when the buyer wants a clear package
- building AI workflows without a delivery container
- mistaking speed for quality and shipping undifferentiated output

## Operating Method

The method extracted from the source is:

1. Pick a repeatable digital service with recurring need.
2. Package it so buyers can understand, purchase, and submit work without a custom sales process.
3. Lower time to value by making the first useful artifact arrive quickly.
4. Run one request or one constrained workstream at a time.
5. Use AI to compress requirements, production, and iteration, while preserving human judgment.
6. Build a moat through distribution, brand, design taste, quality, and reliable delivery.
7. Use pause/cancel flexibility to reduce buyer risk and make the service easier to buy.

## Required Contract Fields

Every Productized AI Service OS run must define:

| Field | Requirement |
|---|---|
| Buyer | The specific person or business with recurring pain. |
| Promise | One concrete outcome the buyer can understand before a call. |
| First value artifact | The first thing delivered quickly enough to prove momentum. |
| Intake | The minimum inputs needed to start without a call. |
| Queue rule | One-at-a-time, sprint, or retainer workstream logic. |
| AI role | What AI may draft, structure, generate, inspect, or automate. |
| Human judgment role | What must be reviewed by the operator before delivery. |
| Quality gate | The acceptance bar before client handoff. |
| Pause/cancel rule | How buyer risk is reduced without breaking delivery economics. |
| Proof plan | The smallest test that proves people want the offer. |
| Delivery surface | How the buyer receives work and asks for revisions. |
| Reuse hook | What becomes reusable for the next client or internal use. |

## Fit Score

Score each item 0, 1, or 2. A durable command-grade build needs at least 12/18.

| Dimension | Question |
|---|---|
| Recurring need | Does the buyer need this repeatedly? |
| Fast first value | Can a useful artifact be delivered within 24-72 hours or a tight sprint window? |
| Standardized intake | Can the work begin from a form, files, examples, or async brief? |
| Scope containment | Can requests be queued or bounded without constant negotiation? |
| AI leverage | Does AI materially reduce requirements, production, or QA time? |
| Human moat | Does human taste, judgment, strategy, or implementation still matter? |
| Distribution wedge | Is there a clear way to get initial attention or proof? |
| Pricing room | Can the buyer justify a premium compared with hiring, DIY, or software? |
| Risk control | Are legal, security, brand, and performance claims manageable? |

## Failure Modes

| Failure Mode | Early Signal | Recovery |
|---|---|---|
| Custom consulting relapse | Every buyer needs a new proposal | Tighten ICP, intake, scope, and first artifact. |
| AI wrapper commodity | The offer is just "we use AI" | Add taste, distribution, implementation, QA, or domain expertise. |
| Unlimited chaos | Unlimited requests create burnout | Add one-request-at-a-time, request classes, and pause rules. |
| Weak proof | Offer sounds clever but no buyer behavior supports it | Run a small proof sprint before building more assets. |
| Unsupported earnings claims | Source revenue numbers become promises | Reframe as source evidence, not guaranteed outcomes. |

## Validation

A run passes when:

- source evidence is cited with timestamps or local paths
- the buyer, promise, intake, queue, AI role, quality gate, and proof plan are explicit
- existing offer/client-delivery routes are reused instead of duplicated
- the output includes an internal use path and a client-facing path
- router search surfaces `/productized-ai-service-os`
- artifact guards pass for written deliverables
