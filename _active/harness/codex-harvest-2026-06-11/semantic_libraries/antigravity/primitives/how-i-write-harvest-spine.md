# How I Write Harvest Spine

## Purpose

Use this primitive for `How I Write`-style interviews and adjacent expert source harvests where the goal is to turn nuanced writing expertise into deployable Antigravity capability without flattening the expert into a rigid template.

The spine is reusable; the expert extraction remains bespoke.

## Core Rule

Reuse the gates, not the insights.

The harvest should preserve the source's actual method, vocabulary, failure modes, and behavior change. The spine only prevents common failures: shallow summaries, duplicate skills, missing source evidence, no integration path, and no proof that the extraction changes writing behavior.

## Gate Order

| Gate | Required Question | Required Output |
|---|---|---|
| Source acquisition | What evidence do we actually have? | Source package, transcript/ledger, uncertainty limits. |
| Expert-specific method | What does this expert do that adjacent systems do not? | Mechanics ledger with evidence anchors. |
| Existing-system fit | Which current skills already own nearby terrain? | Companion, expansion, new skill, reference, workflow, OS layer, or no build. |
| Deployment shape | How should future agents use this? | Skill, workflow, reference, front-door update, proof lab, or command bridge. |
| Integration | Where does the layer plug into current writing/comedy/copy routes? | Explicit stacking and next-gate rules. |
| Behavior proof | What realistic input changed because of the source? | Before/after proof, cold-start run, or applied scenario. |
| Reuse decision | Is this pattern repeated enough to promote? | Keep expert-specific, keep elastic spine, or consider full channel OS after multiple proofs. |

## Build Shape Defaults

- If the source adds a distinct operating method but overlaps existing routes, prefer a companion skill or companion expansion.
- If the source primarily sharpens an existing workflow, prefer a reference and workflow update.
- If the source teaches an end-to-end repeatable capability, create a skill system.
- If the source only adds examples, keep it as a reference.
- If the source is thin, do not build.

## Required Proof

Writing, comedy, copywriting, storytelling, or communication harvests must include a before/after transformation with:

- original weak input
- weakness diagnosed
- source mechanics used
- rewritten output
- behavior delta
- proof gap or risk
- next gate

## Anti-Template Guard

Reject a harvest if the spine starts pre-deciding the expert's insight. The spine asks:

- what did this expert actually do?
- what did the existing system lack?
- what changed in output quality?

It must not force every expert into the same sections, same number of patterns, same prompt count, or same command shape.

## Promotion Rule

Do not promote a full `How I Write` channel OS after one source. Promote only after at least two or three successful harvests show the same orchestration pattern creates reliable leverage without reducing nuance.
