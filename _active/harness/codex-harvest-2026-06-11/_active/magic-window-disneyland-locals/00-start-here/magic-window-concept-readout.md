# Magic Window Disneyland Locals Concept Readout

## Verdict

The opportunity is real but not empty. Existing tools prove demand for wait times and crowd forecasting, but most are planner-first, data-first, or official-utility-first. The sharper wedge is a local passholder decision layer: should I go tonight, tomorrow, or skip and protect the magic?

## Product Shape

Magic Window is an unofficial local crowd forecast companion for Anaheim park nights. It does not replace the official app. It gives locals a fast, opinionated go-or-skip signal based on predicted crowd friction, not only average wait times.

## Existing Market

| Player | What it already does | Opening left for Magic Window |
|---|---|---|
| Official Disneyland app | Park map, wait times, dining, tickets, PhotoPass, Lightning Lane | Too broad and operational to be a local decision product |
| TouringPlans / Lines | Serious crowd calendars, trip plans, paid subscription | Strong, but planner-first and not positioned around locals preserving casual visits |
| IsItPacked | Simple crowd calendar and busy-day mental model | Lightweight, not deeply personalized |
| Thrill Data | Rich historical wait-time and crowd data | Data-heavy, not consumer-simple |
| Magic Guide / MouseWait / Queue-Times style apps | Live waits, maps, user or API data, park info | Live utility, not a polished forecast judgment layer |

## Monetization Test

Start with a small paid signal before building native iOS:

1. Publish a daily "Go or Skip Tonight" forecast for 14 days.
2. Track saves, replies, shares, and forecast accuracy receipts.
3. Offer a paid text/email alert list at $4 to $7 per month.
4. Add an annual passholder tier only after the signal has visible trust.

## Build Boundary

This is an unofficial product concept and must avoid official logos, characters, and brand assets. Nominative references to Disneyland are useful in strategy and research, but the consumer app should stay visually independent unless licensed.
