# Elastic How I Write Harvest Spine

## Purpose

This is not a rigid template. It is an elastic spine for future `How I Write` and similar expert interviews. It preserves the depth of each expert while making sure every harvest clears the same source, build-shape, integration, and behavior-proof bars.

## Rule

The reusable part is the gate sequence, not the expert's output shape.

Every expert should be allowed to produce a different kind of artifact if the source demands it: companion skill, reference, workflow, OS layer, proof lab, command bridge, productized asset, or no build.

## Gate Sequence

| Gate | Question | Output |
|---|---|---|
| Source acquisition | What evidence do we actually have? | Transcript, ledger, uncertainty report, visual limits. |
| Expert-specific genius | What does this expert do that adjacent systems do not? | Mechanics ledger with timestamps. |
| Existing-system overlap | Which current skills already own part of this domain? | Companion vs new skill decision. |
| Build shape | What should the source become? | Skill, workflow, reference, OS layer, proof lab, or no build. |
| Integration | Where should future agents find and use it? | Skill index, workflow references, route search, stack notes. |
| Behavior proof | What real input did it change? | Before/after or cold-start proof. |
| Reuse decision | Is this pattern repeated enough to become a broader OS? | Keep source-specific, create elastic spine, or promote channel OS. |

## Promotion Rule

Do not promote a full channel OS after one expert. Promote only after at least two or three harvests show that the same orchestration pattern keeps recurring and that the spine reduces work without reducing nuance.

## Required Output For Future Runs

Every future source-to-writing harvest should produce:

- source map
- mechanics ledger
- operating model
- use-now playbook
- behavior proof
- route/integration note
- uncertainty limits
- next gate

## Anti-Template Guard

Reject any future harvest if the template starts deciding the insights before the source is read. The spine should ask better questions, not pre-fill the answer.
