# Behavior Proof Ledger

## Proof Question

Does the new template package change the output from a generic service-business marketing plan into a usable one-person operating system and client-facing handoff?

## Baseline Output Risk

A generic marketing plan might recommend:

- post more consistently,
- improve the website,
- start email marketing,
- ask for referrals,
- create case studies,
- run paid ads later.

That is directionally useful but not operational. It leaves the operator to decide what to do first, what AI should handle, what to send clients, and how to prove the system worked.

## Required Behavior Delta

Using `02-research/cold-start-fixture.md`, this package must produce:

| Output | Pass Standard |
|---|---|
| Fit verdict | Names why this is or is not a good service-business use case. |
| Referral fix | Gives exact ask timing, ask surface, incentive or thank-you, and owner. |
| Message board | Converts proof, objections, and buyer questions into deployable messages. |
| AI copy-machine brief | Defines context, voice, proof, objections, review gate, and allowed outputs. |
| Weekly calendar | Compresses the default 40-hour week to the available hours with explicit tradeoffs. |
| Client-facing handoff | Explains the operating system in plain language without internal jargon. |
| Proof sprint | Defines a 48-72 hour diagnostic output and before/after proof artifact. |

## Fixture Acceptance

For the fixture, a passing first 7-day sprint should ship:

1. referral outreach packet for past clients,
2. proof-backed landing page or PDF improvement,
3. first follow-up/email sequence or sales collateral asset.

Paid ads, broad creator sourcing, and high-volume organic content should be deferred until referral, proof, and follow-up systems can catch demand.
