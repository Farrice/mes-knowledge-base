## Stage 2 Triage — Recommended Stage 3 Lever

Per the plan's triage table, multiple conditions are red. Resolving the priority:

| Red | Why it could be #1 | Why it isn't |
|---|---|---|
| Grounding silent | Affects every future session; fix compounds | — |
| Grade inflation | Enables drift detection | Doesn't change output quality immediately |
| 69% dead skills | Fixes architectural bloat | Doesn't fix the calibration loop; cosmetic |

**RECOMMENDATION: Stage 3 = Fix the Tier 1.5 Grounding Pipeline.**

Reasoning:
1. **Highest leverage per fix** — every subsequent content/brand/voice/strategy/copy session benefits. The other reds compound the gains.
2. **Smallest blast radius** — likely one fix in `chain_runner.py` (recall_logger invocation) and/or the domain classifier in `recall-grounding-protocol.md`. Not a system rewrite.
3. **Enables the other audits** — once grounding is firing, eval_harness can compare grounded vs ungrounded Expert Standard scores, which finally makes calibration data interpretable.
4. **Matches the felt symptom** — the "skills not producing results I hoped for" feeling maps directly to grounding-stripped production.

**Stage 3 scope (next session, NOT THIS ONE)**:
- Diagnose why `recall_grounding.jsonl` stopped logging Apr 25
- Trace `chain_runner.py finalize()` → does it call `recall_logger.log()`?
- Check domain classifier: does it match beyond "content"?
- Add a smoke test: a single chain run produces a grounding event
- Re-run the 14-day report after fix to confirm fire rate climbs

**Anti-scope for Stage 3**: Don't also fix grade inflation, don't archive dead skills, don't decompose Cooz workflows. One lever.
