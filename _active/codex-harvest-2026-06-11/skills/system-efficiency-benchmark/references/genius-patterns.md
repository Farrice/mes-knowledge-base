# System Efficiency Benchmark - Genius Patterns

## Core Pattern

Measure before packaging. A plugin is not automatically faster or clearer than a better router, tighter metadata, cleaner workflow descriptions, or better feedback logging.

## Benchmark Pattern

Use a small representative prompt set that covers the operating system:

- messy raw context
- revenue sprint
- extraction source
- creative brief
- client audit
- system health
- plugin readiness
- command bloat
- self-evolution
- knowledge retrieval

Each case should record the expected route, actual command-menu top route, actual workflow-router top route, expected-rank position, latency, and whether the user would still need to reconstruct the system manually.

## Packaging Pattern

Only package when the bundle improves repeatability. If cleanup-only gets the same routing result, package later.

## Anti-Bloat Pattern

Cold workflows are not deletion candidates until the system has enough usage evidence. Leave them on disk, surface the hot routes, and add feedback evidence before archiving.
