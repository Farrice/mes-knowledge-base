# Buyer Trigger Audit

## Input

- Product, offer, page, ad, or design concept.
- Target buyer or niche.
- Intended use context: apparel, POD, landing page, offer, client creative, content, or other product.
- Optional: current copy, visual prompt, mockup, product page, or launch note.

## Steps

1. Load `references/source-ledger.md` and `references/genius-patterns.md`.
2. Name the source timestamp anchors used.
3. If the request includes `--research`, current buyer insights, trends, social listening, purchase intent research, competitor evidence, or market claims, run `workflows/research-backed-trigger-run.md` first.
4. Use evidence IDs or source URLs for current buyer language, trends, marketplace signals, competitor facts, or community claims.
5. Separate observed input from assumptions.
6. Separate `Source Mechanics`, `Live Evidence Used`, and `Domain Extrapolation`.
7. Fill the Trigger Fit Table.
8. Identify the weakest trigger that most blocks purchase intent.
9. Rewrite only the parts needed to improve that trigger first.
10. Add a behavior proof note showing what changed.

## Quality Gate

Reject the audit if it only says the idea is good/bad. It must name the trigger failure and produce a concrete revision.

Reject the audit if it makes current-world claims without source URLs. If research status is `DEGRADED`, label the audit as research-informed. If research status is `FAILED`, output the evidence gap instead of fabricating buyer insight.
