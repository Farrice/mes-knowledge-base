# Code Intake and Self-Assessment

## Pre-Flight Gate

Load `../genius.md` and `../references/bank-code-field-guide.md`. Treat the output as a working code hypothesis unless the user provides direct ranked values.

## Input Required

- Person being assessed
- Ranked B/A/N/K values if available
- Decision style, work style, money behavior, buying behavior, communication likes/dislikes
- Context: business, relationship, sales, team, or content

## Execution

1. Score each code from direct ranking, stated values, behavior, and decision evidence.
2. Identify primary, secondary, tertiary, and blind-spot code.
3. Explain the practical meaning of the code order for communication, buying, selling, and work.
4. Generate five exercises that build fluency in the weakest or most commercially important code.
5. Create a short operating card the person can reuse before calls, content, or decisions.

## Output Requirements

- **B.A.N.K. Code Hypothesis**: ordered code, score, confidence.
- **Evidence Table**: observed clue, code signal, strength.
- **Communication Instructions**: how to speak to this person.
- **Selling Instructions**: how this person should sell to other codes.
- **Exercises**: five concrete practice actions.
- **Reusable Operating Card**: one-page reference.

## Quality Gate

Reject outputs that label without evidence, treat the code as fixed identity, or produce advice with no business use.
