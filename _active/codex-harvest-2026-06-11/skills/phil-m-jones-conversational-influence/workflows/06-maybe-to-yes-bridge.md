# Maybe-to-Yes Bridge

## Pre-Flight Gate

Use this when the person is interested but stuck in maybe, delay, or vague next steps.

## Skill Acquisition

Load:
- `genius.md` - Assumptive Timing Frame, Close Friction, Curiosity Recovery
- `references/phrase-library.md` - sequence families 6, 16, 18, 19, 23

## Inputs

- The maybe statement
- What decision is needed
- What information they already have
- Deadline or timing truth

## Execution

1. **Clarify the maybe**: name what is unresolved.
2. **Remove one uncertainty**: answer or isolate the biggest missing piece.
3. **Use an assumptive next-step frame**: describe what happens next if they proceed.
4. **Test the condition**: ask whether solving the remaining issue moves them forward.
5. **Create decision closure**: agree the next action and time.

## Content Type Adaptations

| Channel | Adaptation |
|---|---|
| Sales call | Use "what happens next" language and book the step. |
| Proposal email | Include a decision path with date and action. |
| DM | Ask a single clarifying question. |
| Webinar/chat | Use a low-friction reply prompt. |
| Internal leadership | Convert delay into owner, date, and decision. |

## Output Requirements

Produce:
- Maybe diagnosis
- Bridge script
- Conditional question
- Decision closure line
- Follow-up message if they still delay

## Quality Gate

The bridge must not bully. It should make indecision easier to resolve.
