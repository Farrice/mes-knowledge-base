# Founder Systems War Room

## Pre-Flight Gate

Use when the founder has multiple ideas, experiments, client opportunities, or product paths competing for attention.

Load:
- `skills/ash-maurya-founder-systems/genius.md`
- `skills/operator-autopilot/SKILL.md` when available

## Execution

1. **Collect The Inputs**
   - Active ideas.
   - Current evidence.
   - Open assumptions.
   - Build requests.
   - Revenue opportunities.
   - Constraints.

2. **Classify Each Item**
   - Raw idea.
   - Problem validation.
   - Solution design.
   - Offer delivery.
   - Demand validation.
   - Build/scale.

3. **Rank By Evidence And Leverage**
   - Strongest customer pull.
   - Fastest reachable prospect path.
   - Highest economic upside.
   - Lowest build cost before proof.
   - Best stacking partner.

4. **Choose One Weekly Bet**
   - Define the assumption.
   - Define the test.
   - Define the threshold.
   - Define what stops.

5. **Route The Work**
   - Ash for validation.
   - Dan Martell for scaling constraints.
   - Daniel Priestley for assets and demand.
   - Andrew Wilkinson for rapid prototype after proof.
   - Operator Autopilot for orchestration.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Personal founder system | Keep one test and one build decision per week |
| Client portfolio | Rank opportunities by evidence and closeability |
| Product studio | Create a validation kanban |
| Content-to-offer | Route audience signals into problem tests |

## Output Requirements

- War room board
- Ranked opportunity list
- One weekly experiment
- Stop-doing list
- Expert/workflow routing

## Quality Gate

Pass only if the founder leaves with fewer active bets. Fail if every idea remains equally important.
