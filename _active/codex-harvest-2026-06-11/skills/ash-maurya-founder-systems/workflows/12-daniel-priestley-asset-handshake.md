# Daniel Priestley Asset Handshake

## Pre-Flight Gate

Use when validation has revealed a real problem, segment, promise, or paid pathway that can become an asset. Do not create assets from unvalidated assumptions.

Load:
- `skills/ash-maurya-founder-systems/genius.md`
- `skills/daniel-priestley-oversubscribed/SKILL.md`
- `skills/daniel-priestley-oversubscribed/genius.md`

## Execution

1. **Extract The Validated Kernel**
   - Customer segment.
   - Pain language.
   - Switching trigger.
   - Proof of demand.
   - Offer promise.
   - Price anchor.

2. **Choose Asset Type**
   - Diagnostic assessment.
   - Scorecard.
   - IP method.
   - Workshop.
   - Lead magnet.
   - Sales asset.
   - Delivery playbook.

3. **Map Demand Tension**
   - What frustration is already visible?
   - What old way should be challenged?
   - What high-stakes outcome creates urgency?
   - What proof can be shown?

4. **Create Asset Roadmap**
   - First asset to ship.
   - How it collects more evidence.
   - How it supports sales.
   - How it feeds the next validation loop.

5. **Route To Priestley Workflows**
   - KPI brand if the founder needs authority.
   - High-stakes offer if pricing/demand is the issue.
   - Demand content if education is needed.
   - Oversubscribed launch if campaign-ready.

## Content Type Adaptations

| Context | Adaptation |
|---|---|
| Consulting | Build diagnostic and authority proof |
| Productized service | Build assessment and sales deck |
| Course/product | Build demand content before curriculum |
| Founder brand | Build IP narrative from validated pain |

## Output Requirements

- Validated kernel
- Asset recommendation
- Demand tension map
- First asset spec
- Priestley workflow route

## Quality Gate

Pass only if the asset is grounded in validated customer evidence. Fail if it becomes a generic lead magnet.
