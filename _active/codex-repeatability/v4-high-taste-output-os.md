## Preservation Lock

- **Keep**: preflight before output, one functional owner, explicit file-load proof, source-backed claim ledger, human scene, stakes, productized offer path, and an orchestration receipt.
- **Change**: the domain, audience, owner skill, evidence sources, format, and offer mechanism for the next task.
- **Do not disturb**: no invented authority, no fake client proof, no expert soup, no list-only structure, no generic CTA, no unsupported live-visibility claims.
- **Risk**: turning V4 into a rigid template and losing the lived thinking that made it feel human.
- **Gate**: do not ship unless the output has a clear source spine, voice proof, factual labels, and clean prose/grounding checks.

## The Eight Moves To Repeat

1. **Run preflight before touching the deliverable.**
   The preflight must name the owner workflow, owner files, support lanes, rejected routes, and required proof gates. If the route is wrong, fix the Codex route before drafting.

2. **Load the owner deeply, not decoratively.**
   For creative or client-facing work, load `SKILL.md`, `genius.md`, and one relevant workflow. Do not use an expert name unless the mechanics show up in the output.

3. **Create a Preservation Lock from the best prior example.**
   Name what must survive before making anything new: voice, proof, tension, offer, route behavior, or formatting standard.

4. **Build the evidence spine before the prose.**
   Pull current sources when claims may have changed. Create a claim ledger with `VERIFIED`, `LIKELY`, or `UNCONFIRMED` before the draft pretends to know things.

5. **Find the human pressure point.**
   V4 was not "AI search is changing wellness." It was "a tired buyer asks which magnesium to trust at 10:43 PM and the brand may not control the answer." Scene first, abstraction second.

6. **Translate weakness into inspectable proof.**
   "I do not have case studies yet" became "the audit before the pitch." The gap became the offer mechanism instead of an apology.

7. **Let support lanes change the work, not decorate it.**
   Lara shaped buyer/amplifier logic. Fresh Voice reduced formula and added human rhythm. Nicolas shaped zero-proof acquisition into a public diagnostic. The gates killed AI tells and unsupported claims.

8. **Finish with hard gates and a receipt.**
   Clean prose is not enough. The closeout must show what loaded, what changed, what passed, what failed, and what remains risky.

## Reusable Workflow

Use this for any important content, strategy, offer, research, client, or system artifact where "good enough" is not acceptable.

### 1. Intent Lock

Capture:

- raw ask
- audience or user
- desired artifact
- taste anchor or golden sample
- business objective
- deadline or publishing boundary

Score the intent from 1-5. If it is 3 or below, ask one sharp question or state assumptions.

### 2. Codex Preflight

Run:

```bash
.venv/bin/python .codex/tools/codex_orchestration_preflight.py --intent "[raw ask]" --mode deliverable --format md
```

Use `--mode system` for Codex/workflow repair and `--mode research` for research-first work.

Preflight must produce:

- owner workflow
- route proof
- owner files
- support candidates
- rejected routes
- memory retrieval
- hook state
- Context Load Manifest

If the route feels wrong, repair the Codex-only resolver or log the misroute before producing the main artifact.

### 3. Owner Load

For expert-domain output, read:

- owner `SKILL.md`
- owner `genius.md`
- one relevant owner workflow
- current project context
- one golden sample or benchmark, when available

Support lanes are bounded. Each support lane gets one job, not full co-ownership.

### 4. Source Spine

Before drafting:

- gather current sources if facts may have changed
- separate observed facts from inferences
- write a claim ledger
- label claims as `VERIFIED`, `LIKELY`, or `UNCONFIRMED`
- name what was not checked

No real-world claim gets smuggled into the prose without a home in the ledger.

### 5. Human Wound And Stakes

Before drafting, write one sentence for each:

- the scene
- the wound
- the buyer anxiety
- the category stakes
- the belief shift
- the offer or proof asset

If these are missing, the draft will become consultant-clean.

### 6. Draft

Draft from the thesis and source spine, not from a template.

Use the loaded expert mechanics silently. The reader should feel the structure without seeing the scaffolding.

Required qualities:

- one controlling thesis
- one concrete scene or lived pressure point
- buyer and amplifier relevance
- proof near claims
- conversational movement
- paragraphs that vary in length
- an offer path that feels like the natural next step

Avoid:

- repeated single-line cadence
- generic "value post" sequencing
- "not X, but Y" patterns
- clean consultant summaries
- CTA theater
- named experts in the copy

### 7. Adversarial Pass

Run a critique before finalizing:

- Which lines sound consultant-clean?
- Is the wound too abstract?
- Are the stakes too polite?
- Did proof become decoration?
- Does the format feel like AI learned LinkedIn?
- Is the CTA asking for trust too early?

Apply fixes before running gates.

### 8. Verification Gates

For public/revenue writing, run:

```bash
.venv/bin/python execution/content_finish_gate.py check --file [artifact path] --label [label]
.venv/bin/python execution/prose_classifier.py check [artifact path]
.venv/bin/python execution/grounding_guard.py [artifact path] --task-type Content --strict
```

Then finalize with the artifact itself, not only a summary:

```bash
.venv/bin/python execution/chain_runner.py finalize "[what was produced]" \
  --expert [owner] --skill [skill] --workflow [workflow] \
  --type [Content|Strategy|Research|Client Work|System|Creative|Analysis] \
  --intent [1-5] --expert-score [1-10] --adversarial [1-10] --sub-agents 0 \
  --content-file [artifact path] \
  --notes "[what worked] | platform: codex | Verification: [PASS/PARTIAL/FAIL]"
```

If chain finalize disagrees with clean gates, report the disagreement instead of hiding it.

### 9. Orchestration Receipt

Every substantial artifact closes with:

- intent score
- owner workflow
- route proof
- memory retrieved
- files loaded
- extracted patterns
- support lanes
- rejected routes
- verifier results
- finalize status
- open risks

Without the receipt, the artifact is draft-quality.
